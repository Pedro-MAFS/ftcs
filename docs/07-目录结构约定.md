# 07 - 目录结构约定

本文档定义仓库目录布局。所有模块、Skills、MCP 服务必须遵守此约定，确保跨环境与跨阶段一致。

## 1. 仓库根目录

**`workspace/` 是唯一标准工作流目录**。Skills、MCP、配置、业务数据只在此维护；仓库根只放应用壳与文档。

```
foreign-trade-customer-search/
├── README.md
├── .gitignore
├── .env.example                 # 说明用；真实 Key → workspace/.env
├── docs/
├── desktop/                     # Electron 应用壳
├── .cursor/                     # 本机 Cursor 临时目录（不进 Git）
├── .opencode/                   # 本机 OpenCode 缓存（不进 Git，工具自动生成）
└── workspace/                   # ★ 标准工作流（唯一维护处）
    ├── .env
    ├── config/
    │   ├── scoring-rules.yaml
    │   └── opencode/opencode.json
    ├── skills/                  # Skill 权威源（OpenCode 直接读取）
    ├── mcp-servers/             # MCP 源码与 dist
    ├── data/
    └── logs/
```

## 2. docs/

docs/

## 3. workspace/config/

运行时配置（不在仓库根）：

```
workspace/config/
├── scoring-rules.yaml           # 线索评分权重（兼工作区标记文件）
└── opencode/
    └── opencode.json            # MCP：mcp-servers/.../dist（相对 workspace）
```



## 4. workspace/data/

路径在 Skills/MCP 返回值中仍写作 `data/...`（相对 **workspace 根**）：

```
workspace/data/
├── products/{product_id}/profile.json
├── products/{product_id}/inputs/
├── keywords/{product_id}/expansion.json
├── leads/{product_id}/raw/{Rn}.jsonl
├── leads/{product_id}/scored.json
├── leads/{product_id}/discarded.json
├── emails/{lead_id}/draft.json
├── emails/{lead_id}/draft.md
├── exploration/{product_id}/runs/{run_id}.json
└── cache/search/
```

### 特殊目录

| 路径 | 说明 |
|------|------|
| `workspace/data/products/_example/` | 示例数据，纳入 Git |
| `workspace/data/products/{real_id}/` | 真实业务数据，不纳入 Git |
| `workspace/data/cache/` | 缓存，不纳入 Git |
| `workspace/.env` | API Key，不纳入 Git |

## 5. workspace/skills/（权威源）

```
workspace/skills/
├── extract-product-profile/
├── expand-keywords/
├── discover-leads/
├── score-and-dedupe/
├── draft-outreach-email/
└── ...
```

**维护规则**：只编辑 `workspace/skills/`。  
OpenCode / 桌面 App 直接读 `workspace/skills/`。  
根目录 `.cursor/`、`.opencode/` 为 IDE/工具本机缓存，不进 Git。

## 6. workspace/mcp-servers/（权威源）

```
workspace/mcp-servers/
├── lead-store/
├── search-api/
└── ...
```

每个 MCP 独立 `package.json` / 构建。仓库根 **不再** 保留 `mcp-servers/`。

## 7. logs/

运行日志在 `workspace/logs/`，不纳入 Git。

## 11. 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 产品 ID | `prod_{YYYYMMDD}_{seq}` | `prod_20260709_001` |
| 线索 ID | `lead_{YYYYMMDD}_{seq}` | `lead_20260709_0001` |
| 探索运行 ID | `run_{YYYYMMDD}_{seq}` | `run_20260709_001` |
| Skill 目录 | kebab-case | `extract-product-profile` |
| MCP 服务 | kebab-case | `lead-store` |
| 配置文件 | kebab-case.yaml | `scoring-rules.yaml` |

## 11. 初始化说明

工作流骨架已落在 `workspace/`。新环境只需：

1. 配置 `workspace/.env`
2. 构建 `workspace/mcp-servers/*/dist`
3. 开发桌面 App：`cd desktop && npm run dev`

无需 `scripts/` / `templates/` 目录。
