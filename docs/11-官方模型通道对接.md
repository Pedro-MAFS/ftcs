> **网关权威需求**：[token-gateway/docs/01-需求.md](../token-gateway/docs/01-需求.md)  
> **桌面用户故事**：[12-官方模型通道用户故事.md](./12-官方模型通道用户故事.md)

## 1. 目的与边界

本文档只描述 **外贸获客桌面端（`desktop/`）如何对接 Token 网关**。

| 在本文档 | 不在本文档 |
|----------|------------|
| 官方 / 自定义通道 | 网关内部计费、账本、代理实现 |
| Key `name=ftcs-desktop` 的开通与使用 | 改库充值、价目、限流细节 |
| 设置页余额 / 用量展示 | 网关表结构与运维 SQL |
| 与现有 UC 登录的衔接 | 多上游、管理端 |

网关定位回顾：`token-gateway` 是本应用的 **Resource Server**；桌面端 `ftcs-desktop` 是唯一面向用户的 **OAuth Client**；用户只登录一次。

## 3. 对接架构

```
用户中心 AS                    桌面端 ftcs-desktop              Token 网关 RS
user.ai-utills.com             desktop/                        token-gateway/
        │                            │                                │
        │◄── 已有 OAuth 登录 ────────│                                │
        │── access_token ───────────►│                                │
        │                            │── rotate name=ftcs-desktop ───►│
        │                            │◄── sk-（明文一次）─────────────│
        │                            │                                │
        │                            │ OpenCode baseURL + sk- ───────►│
        │                            │        /v1/chat/completions    │
```

依赖：

- 现有登录：`desktop/electron/auth/`（Client `ftcs-desktop`）
- 网关接口：见网关需求 §6（`/v1/keys/rotate`、`/v1/usage/me`、`/v1/chat/completions` 等）

## 4. 功能需求（FR-DESKTOP）

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-DESKTOP-01 | 设置中支持「官方通道 / 自定义通道」切换 | P0 |
| FR-DESKTOP-02 | 官方通道：UC 已登录 → 以 `name=ftcs-desktop` 调用 `POST /v1/keys/rotate`（无则创建/有则重置）→ 写入网关 `baseURL` + 该 Key 的 `sk-`；模型下拉调用 `GET /v1/models` | P0 |
| FR-DESKTOP-03 | 自定义通道行为与现状一致（用户自备 DeepSeek 等上游 Key） | P0 |
| FR-DESKTOP-04 | 设置页展示余额（厘→元）、今日输入/输出 Token 用量（调 `GET /v1/usage/me`） | P0 |
| FR-DESKTOP-05 | 余额不足时给出可理解提示；充值引导为联系运营/人工入账（无在线支付） | P1 |

### 4.1 约定

| 项 | 值 |
|----|-----|
| Key `name` | 固定 `ftcs-desktop`（与 OAuth `client_id` 对齐） |
| 网关根域名 | 默认 `https://token.ai-utills.com` |
| 网关 baseURL | 环境变量 `FTCS_TOKEN_GATEWAY_BASE_URL`，默认 `https://token.ai-utills.com/v1`（须指向网关 `/v1`） |
| 模型列表 | `GET {baseURL}/models`（US-G0-17；需网关 sk）；桌面官方通道下拉以此为准 |
| 开通鉴权 | UC `access_token`（调 `keys/rotate`） |
| Chat 鉴权 | 网关返回的 `sk-` |
| 余额单位 | API 为厘；UI 展示元：`yuan = balance_li / 1000` |

### 4.2 官方通道流程

1. 用户已完成 UC 登录；否则引导登录。  
2. 调用 `POST {gateway}/v1/keys/rotate`，Body：`{"name":"ftcs-desktop"}`。  
3. 响应含 `api_key` 明文：安全存储（仅本机）并配置 OpenCode provider（**每次调用都会发新明文**；本地旧 sk 作废）。  
4. 用该 `sk-` 调用 `GET {gateway}/v1/models`，刷新官方通道模型 / 轻量模型下拉（替换本地写死目录）。  
5. 若仅需确认通道可用且本地已有 sk：可先尝试 Chat；失败（401）再调 `rotate` 更新本地。  
6. Chat / Agent 一律打网关，不再使用用户自备上游 Key。

### 4.3 自定义通道

- 不调用网关 `keys/rotate` / usage。  
- 继续使用用户填写的上游 Key（与现网一致）。  
- 与官方通道配置隔离，切换时不互相覆盖。

### 4.4 丢 Key / 换机

- 与开通同一接口：再调 `POST /v1/keys/rotate` + `name=ftcs-desktop`，保存新明文即可。  
- **不提供**「只查元信息、不回明文」的 provision。

## 5. 验收用例（桌面）

| 用例 | 步骤 | 期望 |
|------|------|------|
| AT-08 桌面主路径 | UC 登录 → `keys/rotate` → 拉取 `models` → 仅官方通道跑通画像→探索→邮件 | 业务成功；下拉模型来自网关；网关侧有对应请求日志（`key_name=ftcs-desktop`） |
| AT-09 自定义通道 | 切换自定义并填自有 Key | 不走网关计费，行为与现网一致 |
| AT-D-01 未登录开通 | 未登录时切官方通道 | 引导登录，不静默失败 |
| AT-D-02 余额展示 | 官方通道下打开设置 | 显示余额（元）与今日用量 |
| AT-D-03 余额不足 | 余额为 0 后发起探索 | 可读提示 + 人工充值说明 |
