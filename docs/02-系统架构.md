# 02 - 系统架构

## 1. 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                    AI 智能体层（编排与决策）                    │
│   Cursor / Codex / Claude Code / OpenCode + Agent Skills    │
└──────────────────────────┬──────────────────────────────────┘
                           │ 调用
┌──────────────────────────▼──────────────────────────────────┐
│                    MCP 工具层（统一接口）                       │
│  lead-store │ chrome-devtools │ search-api │ email-sender │ ...  │
└──────────────────────────┬──────────────────────────────────┘
                           │ 读写 / 执行
┌──────────────────────────▼──────────────────────────────────┐
│                    数据与执行层（确定性逻辑）                    │
│  文件存储 / SQLite / PostgreSQL │ 队列 │ 定时任务 │ SMTP     │
└─────────────────────────────────────────────────────────────┘
```

## 2. 分层职责

### 2.1 AI 智能体层

**职责**：
- 理解用户意图与产品资料
- 提取与补全产品画像
- 规划关键词与探索策略
- 解读网页判断是否为目标客户
- 撰写个性化意向邮件
- 向用户呈现结果并等待审核决策

**不负责**：
- 大规模并发爬取
- 精确去重计算
- 邮件基础设施与送达率优化

### 2.2 MCP 工具层

将外部能力封装为智能体可调用的标准工具。详见 [06-MCP工具规范.md](06-MCP工具规范.md)。

| 工具 | 优先级 | Phase | 说明 |
|------|--------|-------|------|
| `lead-store` | P0 | 1 | 线索与画像的 CRUD |
| `search-api` | P0 | 1 | 搜索引擎查询 |
| `chrome-devtools-mcp` | P0 | 1 | 网站浏览与页面抓取（外部 MCP，Cursor 内置） |
| 智能体文件读写 | P0 | 1 | 普通文件输入（txt/md/json/csv 等） |
| `web-crawler` | P2 | 2 | 批量/定时 headless 爬取（Phase 2 自研） |
| `email-sender` | P2 | 2 | 审核后发送 |
| `scheduler` | P2 | 2 | 注册定时探索 |

### 2.3 数据与执行层

| 组件 | Phase 1 | Phase 2+ |
|------|---------|----------|
| 存储 | JSON 文件 + SQLite | PostgreSQL |
| 队列 | 无（手动触发） | Redis + BullMQ / Celery |
| 定时 | 无 | cron / GitHub Actions |
| 邮件 | 导出 Markdown | SMTP / SendGrid |

## 3. 核心数据流

### 3.1 产品信息输入流

按输入类型分流处理：

```
用户输入
    ├─ 网站 URL
    │     → chrome-devtools-mcp（navigate_page + take_snapshot / evaluate_script）
    │     → 抓取首页及 /products、/about 等关键页
    │
    ├─ 普通文件（txt / md / json / csv 等）
    │     → 智能体原生文件读写工具直接读取
    │     → 复制至 data/products/{id}/inputs/ 归档
    │
    └─ 特殊文件（PDF / Excel / 图片等）
          → Phase 1 暂不支持，提示用户转换或等待后续扩展

    → 智能体 extract-product-profile Skill
    → 产品画像 JSON 写入 data/products/
    → 就绪度检查（缺字段则追问用户）
```

**Phase 1 普通文件范围**：智能体可直接读取的文本类文件。PDF、扫描件、复杂 Excel 等列入后续扩展。

### 3.2 获客探索流

```
产品画像
    → expand-keywords Skill → data/keywords/
    → discover-leads Skill（多轮）
        → search-api 获取搜索结果
        → chrome-devtools-mcp 打开目标页并提取内容
        → 智能体判断是否为目标客户
        → lead-store 写入原始线索
    → score-and-dedupe Skill
    → 评分线索写入 data/leads/{id}/scored.json
```

### 3.3 邮件触达流

```
评分线索（高优先级）
    → draft-outreach-email Skill
    → 邮件草稿写入 data/emails/
    → 用户审核（通过 / 修改 / 拒绝）
    → email-sender 发送（Phase 2）
    → 更新线索状态
```

## 4. 探索策略引擎

探索分四轮，每轮有不同的数据源与关键词类型：

| 轮次 | 名称 | 数据源 | 关键词类型 |
|------|------|--------|-----------|
| R1 | 广撒网 | Google、行业目录、B2B 平台 | 产品名、行业词 |
| R2 | 深挖掘 | 贸易数据、海关、展会名单 | HS 编码、进口商 |
| R3 | 精匹配 | 竞品客户、LinkedIn、采购公告 | 竞品、买家角色 |
| R4 | 持续监控 | 定时复搜 | 高产出词 + 新词自学习 |

每轮输出写入 `data/leads/{product_id}/raw/{round_id}.jsonl`，经评分合并为 `scored.json`。

## 5. 线索评分模型

默认权重（可在 `config/scoring-rules.yaml` 调整）：

| 维度 | 权重 | 信号示例 |
|------|------|---------|
| 产品匹配度 | 30% | 网站售卖同类产品或上下游 |
| 采购意图 | 25% | 进口记录、招聘采购岗 |
| 规模适配 | 15% | 公司规模与 MOQ 匹配 |
| 地理匹配 | 15% | 位于目标市场 |
| 可触达性 | 10% | 有邮箱 / 联系表单 |
| 竞争难度 | 5% | 是否被竞品深度绑定 |

分数区间：
- **80–100**：高意向，优先生成邮件
- **60–79**：中意向，可批量跟进
- **40–59**：低意向，观察
- **< 40**：丢弃或归档

## 6. 跨 IDE 兼容方案

```
.cursor/skills/          # Cursor Skills（主环境）
docs/05-智能体技能规范.md  # 通用 Skill 说明（其他 IDE 可读）
mcp-servers/             # MCP 服务实现（标准协议）
data/                    # 数据目录（所有环境共享）
config/                  # 配置（所有环境共享）
```

其他智能体环境通过阅读 Skill 规范文档 + 连接同一 MCP Server + 读写同一 `data/` 目录即可运行。

## 7. 技术选型建议

| 类别 | 推荐 | 备选 |
|------|------|------|
| MCP 服务语言 | TypeScript | Python |
| 爬虫 | Playwright + Cheerio | Puppeteer |
| 搜索 API | Tavily / SerpAPI | Bing API |
| 存储 Phase 1 | SQLite + JSON | 纯 JSON |
| 存储 Phase 2+ | PostgreSQL | — |
| 前端审核台 Phase 2+ | Next.js | 纯 Markdown 审核 |

## 8. 非功能需求

| 项 | 要求 |
|----|------|
| 可观测性 | 每次探索记录日志到 `logs/exploration/` |
| 幂等性 | 同 URL 线索不重复写入 |
| 成本控制 | 搜索 API 调用计入配额，支持每日上限 |
| 安全 | 密钥仅通过 `.env`，不入库 |
