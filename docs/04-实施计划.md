## Phase G：Token 网关（商业化通道）

> 需求规格见 [token-gateway/docs/01-需求.md](../token-gateway/docs/01-需求.md)；桌面端对接见 [11-官方模型通道对接.md](11-官方模型通道对接.md)。  
> **架构**：`token-gateway` = 本应用 Resource Server；`ftcs-desktop` = 唯一 OAuth Client；`user.ai-utills.com` = AS。  
> **Key 模型**：**一用户多 Key**，以 `name` 区分（桌面端用 `ftcs-desktop`）；余额账户级共享。  
> **本期不做**：管理端（Web / 管理 API）；运维充值/禁用/调价 **直接改库**（须同步写流水）。

**目标**：建成可计费的 DeepSeek 中转 RS，桌面端官方通道可开通账户、按输入/输出两档（厘）扣费并跑通主路径。

## 执行节奏建议

### 每周例会检查项

1. 当前 Phase 哪些任务已完成？
2. 有哪些阻塞（API 预算、数据质量、技术难点）？
3. 下周计划完成哪 2–3 个任务？

### 任务优先级原则

1. **先闭环后完美** — Phase 1 不追求自动化，先证明价值
2. **先 R1 后 R2/R3** — 广撒网足够验证，深挖掘需要付费 API
3. **先文件后数据库** — JSON 足够 MVP，有性能瓶颈再迁移
4. **先 Skill 后 UI** — 智能体对话 + Markdown 审核足够 Phase 1

## 风险与应对


| 风险            | 影响      | 应对                                                |
| ------------- | ------- | ------------------------------------------------- |
| 搜索 API 成本高    | 探索规模受限  | 设每日配额；缓存搜索结果                                      |
| 线索噪音大         | 用户信任下降  | 加强评分；默认只展示 ≥ 60 分                                 |
| 邮件进垃圾箱        | 触达失败    | Phase 2 专做域名预热与送达率                                |
| 爬虫被封 / 浏览器不可用 | 网站抓取失败  | Phase 1 用 chrome-devtools；Phase 2 加 headless + 降频 |
| 多 IDE 兼容问题    | 团队工具不统一 | 严守 MCP + 文件约定                                     |
| Token 网关命中率不稳 | 差价毛利变薄  | 保守定价；固定前缀；SQL 盯命中率；无管理端阶段靠改库限流/禁用 |
