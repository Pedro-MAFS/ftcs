## 2. 用户故事

### US-G1-01　官方 / 自定义通道切换

**作为** 终端用户，**我想** 在设置里选择官方通道或自定义通道，**以便** 按需使用网关或自备 Key。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | —（UI 可先行；联调依赖 G0） |
| 验收要点 | 两种模式可切换并持久化；文案清晰 |
| 映射 | FR-DESKTOP-01 |
| 详细设计 | [design/US-G1-01-官方自定义通道切换设计.md](./design/US-G1-01-官方自定义通道切换设计.md)（**仅官方+自定义**；编码已落地；开通 rotate 归 G1-02） |

> **设计要点**：删除 DeepSeek/Anthropic/OpenAI/Google 预置；设置与首次引导均为二选一；新装默认官方；旧配置迁移为 custom；**未登录选官方 → 引导登录（去登录）**。开通 rotate 归 G1-02。

---

### US-G1-02　官方通道开通并写入网关凭证

**作为** 已 UC 登录的用户，**我想** 以 `name=ftcs-desktop` 调网关 `keys/rotate` 取得 sk 并配置 OpenCode `baseURL` + `sk-`，**以便** 无需自备 DeepSeek Key 跑业务（丢 Key 时同一接口可重置）。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-G0-06，US-G0-10，US-G0-17，US-G1-01 |
| 验收要点 | 未登录引导登录；成功后官方通道可用；模型下拉来自网关；AT-08 |
| 映射 | FR-DESKTOP-02；S1 |
| 详细设计 | [design/US-G1-02-官方通道开通接入设计.md](./design/US-G1-02-官方通道开通接入设计.md)（编码已落地） |

> **相对 G1-01 本期须明确落地的改动**（G1-01 仅本地占位）：
>
> 1. **网关 baseURL 可配置**  
>    - 环境变量：`FTCS_TOKEN_GATEWAY_BASE_URL`（须指向网关 **`/v1`**，与 OpenAI 兼容 base 一致）  
>    - **默认值**：`https://token.ai-utills.com/v1`  
>    - 代码只去尾 `/` 后拼 `/keys/rotate`、`/models` 等，**不再**拼接 `/v1`；替换 G1-01 临时默认本机 `8088`；在 `.env.example` 中写明  
>
> 2. **官方通道模型列表改为接口拉取**  
>    - 开通并具备网关 `sk-` 后，调用 `GET /v1/models`（依赖 **US-G0-17**，仅 sk）填充设置/引导中的默认模型与轻量模型下拉  
>    - **废弃** G1-01 本地写死的 `OFFICIAL_MODEL_CATALOG` 作为唯一数据源（可作离线兜底，但主路径必须是接口）  
>    - 拉取失败时给出可读错误，不静默回落自备上游 Key
