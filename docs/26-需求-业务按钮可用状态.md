# 26 - 需求:业务界面 · 按钮可用状态（明显缺口）

> **文档类型**:本期需求 + 用户故事(**US-BS**,Button States)  
> **状态**:**v0.5.7 开发中**  
> **基线**:桌面端 **v0.5.7**（业务主路径按钮多数已有 `disabled` + `title` / 页内原因）  
> **对齐**:GitHub Issue [#9](https://github.com/Pedro-MAFS/ftcs/issues/9);计划项 `ui-button-states`  
> **关联**:[17-需求-业务效率工具.md](17-需求-业务效率工具.md)、[18-需求-任务编排一键跑通.md](18-需求-任务编排一键跑通.md)

---

## 1. 一句话目标

沿业务主路径，只修**明显有问题**的按钮可用状态：前置条件未满足或进行中时提前置灰，并用现有方式给出简短原因；不重做视觉，不扫荡式改「已正常」的按钮。

---

## 2. 背景与动机

| 现象 | 痛点 |
|------|------|
| 部分门槛只在点击后 Preflight / toast | 用户误点后才发现不能跑 |
| 进行中已禁用，但 `title` 仍是动作说明 | 悬停看不出「为何不能点」 |
| 多数关键按钮已有禁用+原因 | 全量重做浪费且易回归 |

马丰顺 2026-10-03：**按业务路径梳理，只把有明显问题的按钮纳入本需求；大部分按钮应视为正常。**

---

## 3. 已确认产品规则

| # | 规则 |
|---|------|
| **BS1** | **问题导向范围**：只修下文 In Scope 清单；Out 中的按钮本期不改行为。 |
| **BS2** | **原因展示**：沿用现成 **HTML `title`**；探索「开始」类继续可用页内 `explore-action-msg`。不新做仅靠 toast 的原因体系（方案「执行」点后 toast 属既有路径，见 BS7）。 |
| **BS3** | **进行中互斥**：保持现网「相关操作互斥」（如 `generating` / 补全中锁评分、起草）。本期对相关按钮**只补禁用原因文案**，不收窄为「只锁同一按钮」。 |
| **BS4** | **环境类 Preflight 不收**：OpenCode / 搜索 Key / Chrome 等全路径点后 Preflight **不纳入**本期单按钮改造。 |
| **BS5** | **版本**：纳入 **v0.5.7**；需求 PR 基线 `dev-0.5.7`。 |
| **BS6** | **不做视觉大改**：不重做设计系统；不改按钮样式语言。 |
| **BS7** | **方案「执行」不提前、不点后做业务数据门槛**（2026-10-03 手测修订）：不因后续步骤业务数据提前置灰；**点击时只做基础配置校验**，失败 toast。**基础配置**仅：未选产品、已有任务在跑。**业务数据不进**点击判断（含：画像未就绪、R1/R2/R3 前置、没有未评分线索、没有待起草、没有待补全）。**环境类**（OpenCode、搜索 Key、Chrome）仍点后检查，本期不动（与 BS4 一致）。按钮 `disabled` 不并入业务数据门槛。 |

---

## 4. 范围与非范围

### 4.1 本期做（In Scope，按路径）

1. **开始 R3**：未配置 Places Key 时**提前禁用**；原因写入现有 `startR3DisabledReason`（title 与 `explore-action-msg` 同源）。  
2. **探索页「评分去重」**：禁用时补充 `title`（如已有任务 / 评分中）。  
3. **线索页「评分去重」「批量起草」「行内写邮件 / 重写邮件」**：因进行中/已有任务而禁用时，`title` 应说明「已有任务在运行」（或等价短句），**不得**继续只显示动作说明。批量/行内「补全」进行中 title 可顺手对齐，不单开故事。

### 4.2 本期不做（Out of Scope）

| 项 | 说明 |
|----|------|
| **方案「执行」业务数据门槛（提前禁用或点后 assert）** | **BS7**：点击只校基础配置（未选产品 / 已有任务）；业务数据与环境类不按本条改 |
| 生成画像 / 保存画像 / 新建探索任务 | 现网禁用+原因已够用 |
| 开始 R1 / R2、停止 | 同上 |
| 批量/行内补全主门槛 | Hunter、未评分、无域名等已有 title |
| 开发信页：批量起草、重写、保存、驳回、通过 | 空态与进行中禁用已可接受 |
| 定时新建 / 启用 | 限额与调度跳过逻辑非本期按钮误导 |
| OpenCode / 搜索 Key / Chrome 点后 Preflight | BS4 |
| 全面重做视觉 / 设计系统 | BS6 |
| Agent 对话区「发送」、筛选、导出、方案 CRUD 等 chrome | 非本路径关键缺口 |

### US-BS-01　探索路径：R3 Places 与评分去重原因

**作为** 外贸业务员，**我想** 在探索页一眼看出「开始 R3」和「评分去重」为何不能点，**以便** 少误点、少试错。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | — |
| 状态 | **详设修订中 / 开发中** |

**验收要点**

- 未配置 Places Key 时，「开始 R3」禁用；`title` 与页内 `explore-action-msg`（若展示）给出简短原因（写入/复用 `startR3DisabledReason`）。  
- 已配置且其他现网条件满足时，「开始 R3」可点（不收窄 R1/R2 既有规则）。  
- 探索页「评分去重」在因进行中/已有任务等原因禁用时，有非空 `title` 说明原因。  
- 不改变 OpenCode/搜索 Key/Chrome 等环境类点后 Preflight 策略（BS4）。

---

### US-BS-02　线索页：进行中禁用 title

**作为** 外贸业务员，**我想** 在线索页相关按钮因任务进行中被禁用时悬停能看到原因，**以便** 明白为何不能点。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | —（建议在 BS-01 之后提测，便于联调文案风格） |
| 状态 | **详设修订中 / 开发中** |

**验收要点**

- 线索页「评分去重」「批量起草」「行内写邮件/重写邮件」在因已有任务/进行中禁用时，`title` 为进行中类原因（统一「已有任务在运行」或详设等价短句），不再仅显示动作说明。  
- **方案「执行」**：不按业务数据提前禁用；点击时**只校基础配置**（未选产品、已有任务在跑），失败 toast；**不**把画像/轮次前置/未评分线索/待起草/待补全等业务数据放进点击判断（BS7）。环境类仍点后检查。本期不把业务数据门槛并进按钮 `disabled`。  
- 保持相关操作互斥中与线索操作相关的部分（BS3）；不改设计系统（BS6）。  
- 开发信审核页按钮、定时按钮本期不改（Out）。

## 6. 验收清单（需求级）

- [ ] 开始 R3：无 Places Key 时禁用且有原因（title / 页内文案）。  
- [ ] 探索页评分去重：禁用时有 title。  
- [ ] 线索页评分去重 / 批量起草 / 行内写邮件：进行中禁用时 title 为进行中原因。  
- [ ] 方案「执行」：未因业务数据提前禁用；点击只校基础配置（未选产品 / 已有任务）+ toast；业务数据与环境类不进本次点击判断（BS7）。  
- [ ] 未扩大到 Out 清单中的「已正常」按钮。  
- [ ] 未引入新视觉体系；环境类点后 Preflight 策略未被迫改为全面前置。
