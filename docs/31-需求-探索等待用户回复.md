# 31 - 需求：探索时任务等待用户回复

> **文档类型**：本期需求 + 用户故事（**US-AQ**，Await Question）  
> **状态**：**PR #75 修订中 · 马丰顺 2026-10-18 已锁定 O1～O10**（待合入 `dev-0.5.8`）  
> **基线**：桌面端 **v0.5.7+**（`dev-0.5.8`，探索 Agent 运行与时间线已落地）  
> **对齐**：GitHub Issue [#69](https://github.com/Pedro-MAFS/ftcs/issues/69)；Milestone **v0.5.8**  
> **关联**：[25-需求-Agent流式输出.md](25-需求-Agent流式输出.md)、[22-需求-任务完成Windows通知.md](22-需求-任务完成Windows通知.md)  
> **OpenCode 事件参考**：`docs/reference/opencode-events/`（`@opencode-ai/sdk`）；桌面现网订阅见 `desktop/electron/opencode/agent-runner.ts`

---

## 1. 一句话目标

探索（及其它 Agent 长任务）运行中，若 OpenCode 向用户提问并等待回复，客户端要**认得出来**：在界面显示问题与选项、让用户点选提交后任务继续；用户不想答时能**结束任务**，不再无限转圈卡住。同时在 `workspace/AGENTS.md` 引导 Agent **少问、可不问就不问**，但**不禁止**必要提问。

---

## 2. 背景与动机

### 2.1 用户反馈

用户反馈探索时任务卡住。排查发现：OpenCode 在运行中调用交互工具 `question`，向用户提问后一直等待回复；客户端既没识别、也没有提交入口，任务**既不能继续也不能结束**。

### 2.2 复现样例（Issue #69）

探索 R2 阶段，Agent 调用 `question`，问题大意：「R2 共 200 个合格社媒词，已完成 42 个、写入 5 条线索，海外渠道命中率低，剩余 158 词，你希望如何继续？」，**单选**，三个选项：

1. 继续跑完全部 200 条  
2. 只跑完 70 条高优先词后收尾  
3. 立即收尾并评分  

每个选项带一句说明；另有一个简短标题（如「R2 剩余范围」）。

### 2.3 痛点

| 现象 | 痛点 |
|------|------|
| 界面一直转圈，无任何提示 | 用户不知道任务在等自己，误以为卡死 |
| 没有回答入口 | 任务无法继续，白白占用探索额度与时间 |
| 没有结束出口（或用户不知道能结束） | 只能强关应用 |
| 与「任务完成通知」等机制并存 | 任务未完成也不报错，用户切走后更难发现 |

## 3. 已确认产品规则

> 取自 Issue #69「目标」与验收草案，及马丰顺口头需求（2026-10-15 / **2026-10-18**，O1～O10 已全部锁定，见 §7）。

| # | 规则 |
|---|------|
| **AQ1** | **识别等待态**：任务运行中，OpenCode 进入「等待用户回复」时，客户端必须能识别，并让界面进入明确的等待状态。 |
| **AQ2** | **全 Agent 统一展示**：评分、开发信起草、画像生成、探索等**所有**会跑 Agent 的页面，统一识别并展示提问内容与选项（**O1**）；支持单选与多选（`multiple`）；`custom === true` 时提供自定义文字输入（见 AQ2a）。 |
| **AQ2a** | **自定义输入（SDK 已具备）**：OpenCode `QuestionInfo` / `QuestionV2Info` 含可选字段 `custom?: boolean`。`custom === true` 时界面须提供选项外的文字输入；`custom` 为 false / 缺省时仅展示选项。 |
| **AQ3** | **提交后继续**：用户选择并提交后，答案回传（`question.reply` / `question.v2` 对应 API），任务继续运行。 |
| **AQ4** | **等待态文案**：等待期间界面显示 **「任务在等你回复」**（白话、用户视角），**不得**继续显示为普通运行中的转圈；**不得**出现 OpenCode / `question` 等内部词（**O5**）。 |
| **AQ5** | **可结束**：处于等待中的任务，用户可取消 / 结束；不得只能强关应用。结束等待中的提问可用 `question.reject`（或等价）+ 现网 `session.abort`，具体组合归详设。结束时**已写入的线索保持不变**，不做额外清理或强制评分收尾（**O7**）。 |
| **AQ6** | **久不回复选默认**：无法识别的交互须有明确提示及可结束出口；用户（或无人值守场景）**长时间不答**时，按 **AQ6a** 自动选默认项继续，不得无限卡住（**O4**、**O9**）。具体「长时间」阈值归详设拟定（须可测）。 |
| **AQ6a** | **默认项选取规则（SDK 无 default 字段）**：OpenCode `QuestionOption` 仅有 `label` / `description`，**无**显式 `default` 标志。自动续跑时：① 若该题 `options.length ≥ 1` 且 **非** `multiple`，提交 `answers` 为 `[[options[0].label]]`（多题则每题各取首项）；② 若 `multiple === true`，或无可选 `options`（仅自定义输入、自动选取不可能），则 **`question.reject`（或等价）结束本次等待**，写一条本地日志说明原因，**不得**让会话继续挂起。 |
| **AQ7** | **交互工具必须全覆盖识别与渲染**：须梳理 OpenCode 提供的、会阻塞等待用户的交互类型（见 §5 US-AQ-00 清单），形成可交付清单；**客户端必须识别清单内每一类**。问答类须渲染可操作控件；权限类按 **AQ10** 自动处理，清单中须标明「已识别、自动 always」。 |
| **AQ8** | **版本**：已纳入 Milestone **v0.5.8**；基线 `dev-0.5.8`，不合 `main`，发版前不关 #69。 |
| **AQ9** | **减少交互、不禁止提问**：在 OpenCode 会话实际加载的 **`workspace/AGENTS.md`**（仓库根 `AGENTS.md` 是开发约定，不替代本文件）中增加提示：尽量减少向用户提问、能自行决策就不问；**不得**写成完全禁止提问。实现时若改 `workspace/AGENTS.md`，须按根 `AGENTS.md` 约定同步升高 `WORKSPACE_TEMPLATE_VERSION`。 |
| **AQ10** | **权限继续自动 always**：`permission` / `permission.v2` 保持现网行为——收到 asked 后自动 `reply: 'always'`，**不**改为界面人机确认（**O10**）；仍须在清单中识别并写明。 |
| **AQ11** | **切页 / 重启不保留待答**：现网 `agentTimeline` 仅为进程内内存、无磁盘持久化，应用重启后时间线即丢。本期**不要求**切页或重启后恢复待答问题 / 续答（**O2**）；同进程内若布局级面板仍持有运行态，可顺带展示，但不做额外持久化。 |
| **AQ12** | **后台通知**：窗口不在前台时，须弹出系统 / 后台通知，文案 **「任务在等你回复」**（与 [22](22-需求-任务完成Windows通知.md) 机制衔接，具体通道归详设）（**O8**）。 |
| **AQ13** | **定时 / 编排无人值守**：遇到提问先**等待**；若长时间不答，按 **AQ6a** 选默认（与前台久不回复同一规则）（**O9**）。 |

## 4. 范围与非范围

### 4.1 本期做（In Scope）

1. 识别任务进入「等待用户回复」，覆盖 US-AQ-00 清单中全部类型（`question` / `question.v2` 必须渲染；`permission` / `permission.v2` 识别并自动 always）。  
2. **所有** Agent 任务页面统一展示问题与选项（单选 / 多选 / `custom` 文字），点选后提交，任务继续。  
3. 等待期间显示「任务在等你回复」，且可取消 / 结束任务；结束时已写入线索不动。  
4. 久未回复按 AQ6a 自动选默认（或无法默认时 reject + 日志）；无法识别的交互有明确提示与结束出口。  
5. 窗口不在前台时弹「任务在等你回复」通知。  
6. 交互工具清单及处理方式文档（AQ7 / US-AQ-00）。  
7. 在 `workspace/AGENTS.md` 增加「少问、可不问就不问、必要时仍可问」提示（AQ9）。

### 4.2 本期不做（Out of Scope）

| 项 | 说明 |
|----|------|
| 待答问题跨重启 / 跨切页持久化恢复 | **O2 / AQ11**：不做 |
| 权限弹窗人机确认 | **O10 / AQ10**：继续自动 always |
| 新增与提问无关的任务控制（暂停 / 恢复等） | 非本需求 |
| 合入 `main` / 打 tag / 发版 | AQ8 |
| 站内信 Inbox（`desktop/src/composables/useInbox.ts`） | 那是网关站内信，**不是** OpenCode `question`；勿混用 |
| 结束等待任务时清理或回滚已写入线索 | **O7**：已写入的保留不动 |

### 4.3 适用页面

**全部**会跑 Agent 的页面统一处理（探索、评分、开发信起草、画像生成等），同一套识别与渲染机制（**O1**）。

### US-AQ-00　OpenCode 交互工具清单

**作为** 项目组，**我想** 有一份 OpenCode 会等待用户回复的交互清单，**以便** 客户端按清单逐类识别并渲染操作控件，不漏类。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | — |
| 状态 | **待详设**（下列为需求侧基于仓库代码 + `@opencode-ai/sdk` + `docs/reference/opencode-events/` 的**调研基线**，详设须核对版本后定稿） |

#### 调研基线：会阻塞等待用户的交互

| 类型 | 事件（Legacy / 同名 V2） | SDK 入参要点 | 答复 / 出参 | 客户端 API（SDK） | 现网 `agent-runner.ts` | 本期处理（需求） |
|------|--------------------------|--------------|-------------|-------------------|------------------------|------------------|
| **问答 `question`** | `question.asked` → `question.replied` / `question.rejected` | `id`, `sessionID`, `questions[]`（每项：`question`, `header`, `options[{label,description}]`, `multiple?`, `custom?`）, `tool?` | `answers: Array<string[]>`（每题一串所选 label / 自定义文案）；拒绝仅 `requestID` | `client.question.list` / `.reply({ requestID, answers })` / `.reject({ requestID })` | **未处理**（正是 #69 卡死根因） | **必须识别 + 渲染可操作 UI + 提交/拒绝**；久不回复按 AQ6a |

| **权限 `permission`** | `permission.asked` → `permission.replied` | `id`, `sessionID`, `permission`, `patterns[]`, `metadata`, `always[]`, `tool?` | `reply: once / always / reject` | `client.permission.reply({ requestID, reply })`（旧 `respond` 已弃用） | 收到 asked 后 **自动 `reply: 'always'`** | **必须列入清单并识别**；**继续自动 always**（AQ10），不渲染确认弹窗 |
| **权限 `permission.v2`** | `permission.v2.asked` → `.replied` | `id`, `sessionID`, `action`, `resources[]`, `save?`, `metadata?`, `source?` | `PermissionV2Reply`: `once / always / reject` | 同上 permission 客户端 | 同上自动 `always` | **同上；与 v1 同等列入，继续自动 always** |

#### 非「等待用户作答」、本期不按 AQ 交互 UI 处理（仅备案）

| 类型 | 说明 |
|------|------|
| `session.status`（`idle` / `busy` / `retry`） | 运行态，不是提问；可用于辅助判断，**不能替代** `question.*.asked` |
| `tui.*`（`prompt.append` / `command.execute` / `toast.show` / `session.select`） | 面向 TUI 的控制事件；桌面 Electron 客户端不按用户问答渲染 |
| `pty.*` | 交互终端会话生命周期；非业务选择题 |
| 站内信 Inbox | 网关产品消息，与 OpenCode 协议无关 |

#### 验收要点

- 详设文档正式收录上表（可增删经核实后的类型），每项有入参、出参、处理方式（AQ7）。  
- 每类标明：界面处理 / 自动处理（须写清条件）/ 不支持（后者须走 AQ6 兜底）。  
- **禁止**只覆盖 `question` 而漏掉 `question.v2` 或权限类条目。  
- 权限类须写明「自动 always」，与 AQ10 一致。

**本故事不做**：客户端 UI 实现（归 AQ-01～03）；AGENTS.md 文案（归 AQ-04）。

**作为** 外贸业务员，**我想** 任务在等我回答时界面明确告诉我并显示问题，**以便** 我知道该做什么，而不是以为卡死。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-AQ-00 |
| 状态 | **待详设** |

**验收要点**

- 触发 `question` / `question.v2` 时，**所有** Agent 任务页出现问题标题（`header`）、问题正文（`question`）与全部选项（`label` + `description`）（AQ1、AQ2）。

### US-AQ-02　点选提交并继续任务

**作为** 外贸业务员，**我想** 点选答案后任务接着跑，**以便** 不用重开任务。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-AQ-01 |
| 状态 | **待详设** |

**验收要点**

- 选择答案并提交后，经 `question.reply`（或 v2 等价）回传，任务继续运行，界面回到正常运行态（AQ3）。  
- 复现样例中选「立即收尾并评分」后，任务按该选择继续推进（以 Agent 后续行为为准，客户端不替其解读选项含义）。  
- 提交失败有明确提示，问题仍保留，可重试或结束任务（AQ5）。  
- 已回答的提问不能重复提交。

**本故事不做**：减少提问的 AGENTS 改造（归 AQ-04）。

### US-AQ-03　等待中可结束；无法识别 / 久未回复的兜底

**作为** 外贸业务员，**我想** 随时能结束处于等待中的任务，**以便** 不会被无限卡住。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-AQ-01 |
| 状态 | **待详设** |

**验收要点**

- 等待中的任务可取消 / 结束，结束后界面回到非运行态；**已写入线索保留不动**（AQ5、O7）。  
- 遇到无法识别的交互，界面给出明确提示（说明任务在等待、客户端暂不能代答，文案仍用「任务在等你回复」口径）及结束出口，而非无限转圈（AQ6）。  
- 用户长时间不答：按 **AQ6a** 自动选 `options[0].label` 继续；`multiple` 或无可选项时 `reject` + 写日志，不挂起（AQ6、AQ6a）。  
- 定时 / 编排无人值守：先等待，久不回复同样走 AQ6a（AQ13）。  
- 「长时间」阈值由详设给出可测数值。

**本故事不做**：权限人机确认（AQ10）；待答持久化（AQ11）。
