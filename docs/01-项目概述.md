# 01 - 项目概述

## 1. 背景与愿景

外贸企业获客成本高、线索分散、跟进效率低。本系统利用 AI 智能体的理解、推理与写作能力，结合结构化数据与自动化工具，构建一条可重复、可扩展的获客流水线。

**愿景**：用户只需提供产品信息，系统持续发现、整理、触达潜在客户，用户专注于审核与成交。

## 2. 运行环境

系统运行于现代 AI 智能体环境，而非传统单一 Web 应用：

| 环境 | 角色 |
|------|------|
| Cursor | 主要开发与交互环境，Skills + MCP |
| Codex / Claude Code / OpenCode | 兼容执行环境，共享同一套 Skills 与 MCP |
| 后端服务（可选） | 定时任务、大规模爬取、邮件发送 |

智能体是**编排者与决策者**；爬虫、数据库、邮件网关是**执行者**。

## 3. 功能范围

### 3.1 核心功能（In Scope）

| 功能 | 描述 |
|------|------|
| 产品信息输入 | 支持公司网站（chrome-devtools-mcp）、普通文件（智能体原生读写）；特殊格式后续扩展 |
| 产品画像提取 | 将非结构化资料转为统一结构化画像 |
| 关键词扩展 | 按产品、场景、买家、地理、竞品五维扩展 |
| 自动获客探索 | 多数据源搜索，支持定时与持续运行 |
| 线索整理输出 | 评分、去重、分级，输出可行动客户列表 |
| 意向邮件生成 | 基于画像与线索证据生成个性化草稿 |
| 审核与发送 | 用户审核后一键发送（Phase 2+） |

### 3.2 暂不纳入（Out of Scope，后续版本）

- 全自动无人值守群发
- 完整 CRM 替代品
- 合同、报价、订单管理
- 多租户 SaaS 计费系统

## 4. 目标用户

- 外贸业务员 / 外贸经理
- 中小制造企业出海团队
- 使用 AI 工具提升获客效率的一线人员

## 5. 设计原则

### 5.1 产品画像优先

一切获客动作必须从**结构化产品画像**出发，避免直接用原始网页或文件内容搜索。

### 5.2 分层探索，质量优于数量

探索分轮次进行：广撒网 → 深挖掘 → 精匹配 → 持续监控。线索必须经过评分与去重。

### 5.3 证据可追溯

每条线索必须记录：来源 URL、匹配理由、发现时间，便于用户判断与跟进。

### 5.4 合规与安全

- 遵守目标市场数据保护法规（GDPR 等）
- 邮件需支持退订与发送频率限制
- 不存储明文邮箱密码；API Key 使用环境变量

### 5.5 可移植性

使用**文件约定 + MCP 协议 + Agent Skills**，避免逻辑绑定单一 IDE。

### 5.6 产品信息输入策略

按输入类型分流，Phase 1 不自研通用爬虫与文件解析器：

| 输入类型 | 处理方式 | Phase |
|---------|---------|-------|
| 公司网站 URL | `chrome-devtools-mcp` 浏览抓取 | 1 |
| 普通文件（txt/md/json/csv 等） | 各智能体原生文件读写工具 | 1 |
| 特殊文件（PDF/Excel/图片等） | 后续按需扩展专用解析 | 2+ |

详见 [02-系统架构.md](02-系统架构.md) 第 3.1 节。

## 6. 成功标准

### Phase 1（MVP）

- [ ] 输入一个公司网站或产品文件，生成产品画像
- [ ] 自动扩展至少 30 个多维关键词
- [ ] 完成一轮探索，产出 ≥ 20 条带评分的线索
- [ ] 为 Top 5 线索各生成一封可审核的意向邮件草稿

### Phase 2（自动化）

- [ ] 支持定时探索任务
- [ ] 审核后一键发送邮件
- [ ] 线索去重准确率 ≥ 95%（同域名不重复）

### Phase 3（智能化）

- [ ] 探索策略根据历史线索质量自优化
- [ ] 支持回复跟踪与跟进建议

## 7. 术语表

| 术语 | 定义 |
|------|------|
| 产品画像（Product Profile） | 从多种输入提取的统一结构化产品与公司信息 |
| 线索（Lead） | 潜在客户公司记录，含匹配度与来源证据 |
| 探索任务（Exploration Task） | 一次或一系列按关键词执行的获客搜索 |
| Skill | 智能体可调用的标准化工作流说明 |
| MCP | Model Context Protocol，智能体访问外部工具的统一接口 |
