# 独立站需求拆分与交付顺序

> **状态**：拆分已验收，待技术验证与逐项详设
> **父需求**：[41 - 智能体创建与发布独立站](41-需求-智能体创建与发布独立站.md)
> **关联 Issue**：[#145](https://github.com/Pedro-MAFS/ftcs/issues/145)
> **记录日期**：2026-11-09

## 1. 拆分目标

把独立站从“生成网站到线上可访问”的大需求拆成可以逐步开发、演示和验收的工作项。先验证关键技术条件，再完成本地建站与预览，然后接入用户自己的 GitHub、Cloudflare 和域名，最后核对更新及异常恢复。

本文中的顺序是依赖建议，不代表已确定的版本安排。故事拆分已通过核对，后续逐项进行详设和开发。技术验证的结果可能调整故事边界，但应保留父需求中的产品目标。

以下暂用 **US-SITE** 标识独立站用户故事，用 **TV-SITE** 标识技术验证。正式创建 Issue 前再确认编号与仓库现有编号无冲突。

## 2. 用户可见的阶段成果

| 阶段 | 用户能看到或完成什么 | 主要工作项 |
| --- | --- | --- |
| 技术验证 | 在测试环境验证权限、本地预览和客户账号发布链路，明确可自动化的范围 | TV-SITE-01～03 |
| A. 本地建站 | 在一个工作区创建全局站点，通过智能体编写和修改项目，使用产品资料，并在本机预览 | US-SITE-01～04 |

阶段 A 可以独立演示本地建站，但完整首期目标仍包含阶段 B 和 C。阶段 B、C 如何分批发布待产品和研发决定。

## 3. 技术验证工作项

### TV-SITE-01　站点开发权限与本地项目运行

**要回答的问题**

- 当前默认拒绝编辑和命令执行，如何为建站场景提供可实际执行的站点文件操作、依赖安装、预览与构建，同时控制作用范围？
- 如何限制智能体直接操作站点目录以外的路径，并对安装、构建等命令执行提供用户确认？运行后的项目脚本与依赖使用用户账户权限，不作为首期操作系统级隔离保证。
- 如何识别开发服务实际监听的地址、检查静态构建产物、停止预览进程，并适配目标用户的 Windows 环境？

**验证结果**

记录可运行的验证项目、具体权限方案、能力边界和失败情况。验证应包含正常运行、尝试越界、端口占用和异常退出。方案通过核对后再进入对应详设。

### TV-SITE-02　客户 GitHub 与 Cloudflare 的首次发布链路

**要回答的问题**

- 用户自己的 GitHub 个人或组织账号如何授权？哪些仓库可以选择或创建？
- 用户自己的 Cloudflare 账号如何授权 GitHub 仓库，如何创建或选择项目，并设置构建命令、产物目录和生产分支？
- 哪些步骤可由 FTCS 完成，哪些步骤必须由用户在 GitHub 或 Cloudflare 页面操作？
- 如何关联代码提交与实际部署，区分推送成功、构建中、部署失败和线上成功？

**验证结果**

使用测试账号从授权、仓库到线上访问走通至少一条链路，记录权限、所需用户操作、接口能力、失败与恢复方式。Cloudflare 具体产品和 Git 集成方式按验证结果确定。

### TV-SITE-03　客户自有域名绑定

**要回答的问题**

- 客户使用自己的 Cloudflare 账号时，根域名和子域名分别如何绑定？
- 域名由不同 DNS 服务商管理时，用户需要完成哪些操作？系统能查询和展示哪些状态？
- 已有记录冲突、域名验证未通过和证书尚未就绪时如何告知用户？

**验证结果**

用测试域名记录完整操作、所需权限、可获取状态及失败处理。正式支持范围以核对后的结果为准。

## 5. 用户故事与验收草案

### US-SITE-01　创建和恢复全局站点

**用户故事**：作为外贸用户，我希望在一个工作区内有一个全局站点，便于持续维护企业网站。

**验收草案**

- 用户可以找到独立站入口，创建站点项目或继续使用当前工作区已有项目。
- 切换当前产品不创建、切换或删除站点；一个站点不归属于某个产品画像。
- 重启应用后能恢复站点项目的位置和基本状态，继续进入站点功能。
- 项目目录不存在或无法读取时，页面显示原因和可执行的后续操作。

**待详设**：站点入口、项目目录及配置结构、已有站点丢失时的恢复交互。

### US-SITE-02　通过智能体创建和修改站点

**用户故事**：作为用户，我希望用自然语言描述网站，让智能体按我的要求编写和修改项目。

**验收草案**

- 用户可以要求单页或包含多个页面与产品详情页的网站，框架和页面结构随需求确定。
- 智能体能够创建和修改当前站点项目，生成的项目包含 npm run dev、npm run build 及可识别的静态产物目录。
- 智能体可以继续修改已有项目；用户能看到执行状态和失败原因。
- 文件操作、命令执行和依赖安装按核对通过的权限边界执行，工作区其他数据与凭据受到保护。

**待详设**：智能体接入方式、任务生命周期、文件和命令权限、运行环境及授权交互。

### US-SITE-03　使用产品画像和资料库

**用户故事**：作为用户，我希望让智能体参考已有画像、说明书和图片建站，减少重复输入。

**验收草案**

- 用户可以选择零个、一个或多个产品画像，也可以选择资料库文件和图片，或直接提供内容。
- 智能体按用户需求使用已选资料生成网站，信息缺失时能继续向用户确认或展示待补充内容。
- 用户能够检查网站将公开的内容和图片；发布文件只包含网站需要公开的内容和资源。
- 资料库或产品画像发生变化时，不自动覆盖用户已经编辑的网站内容；是否提示变化由详设确定。

**待详设**：资料选择交互、内容来源记录、素材复制和后续同步策略。

### US-SITE-04　本地预览和构建

**用户故事**：作为用户，我希望在发布前预览网站并检查构建是否成功。

**验收草案**

- 用户可启动、打开和停止本地预览，FTCS 使用站点的 npm run dev 并展示实际访问地址。
- 用户能在应用内浏览器查看网站；修改后的更新按项目开发服务的能力显示。
- 系统能执行 npm run build，识别约定的静态产物目录并展示构建结果。
- 依赖缺失、脚本缺失、端口占用、构建失败或预览进程退出时，界面说明原因并提供重试路径。
- 停止预览和关闭应用时，按详设清理本次产生的进程。

**待详设**：安装依赖的时机、端口识别、日志展示、超时和进程管理。

### US-SITE-05　连接自己的 GitHub

**用户故事**：作为用户，我希望使用自己的 GitHub 账号管理网站源码。

**验收草案**

- 用户能完成 GitHub 授权，查看当前连接状态并重新授权。
- 用户可以按验证后的能力选择个人或有权限的组织仓库，或创建新仓库。
- 用户能够确认目标仓库、分支和可见性；系统保存站点关联。
- 授权拒绝、失效、仓库无权限或网络失败时有明确反馈，不暴露凭据。

**待详设**：GitHub App / 授权方式、权限范围、组织账号与仓库创建步骤。

### US-SITE-06　将站点推送到 GitHub

**用户故事**：作为用户，我希望把确认过的网站项目保存到自己的 GitHub 仓库。

**验收草案**

- 推送前展示目标仓库、分支及待发布内容，用户发起后执行推送。
- 成功后展示对应的提交或版本信息；失败时保留本地项目并说明原因。
- 远端已有变更、无权限、网络失败或重复请求时，按详设处理，避免静默覆盖。
- 凭据及用户未选择公开的原始资料不会进入提交内容。

**待详设**：已有仓库写入范围、提交生成、冲突解决、文件检查和重试策略。

### US-SITE-07　连接自己的 Cloudflare

**用户故事**：作为用户，我希望将自己的 Cloudflare 项目连接到网站仓库。

**验收草案**

- 用户能连接或授权自己的 Cloudflare 账号，并完成 GitHub 仓库访问所需授权。
- 用户能选择或创建项目，确认仓库、生产分支、构建命令和静态产物目录。
- 应用展示连接状态；遇到必须在外部页面完成的步骤时，给出指引并能继续流程。
- 授权失效、项目或仓库不可访问时，用户能查看原因并重新连接。

**待详设**：实际 Cloudflare 产品、账号权限、Git 授权和项目创建接口，以 TV-SITE-02 为依据。

### US-SITE-08　发布并查看部署结果

**用户故事**：作为用户，我希望看到网站是否真正上线及访问地址。

**验收草案**

- 用户可以发起网站发布，界面区分本地构建、GitHub 推送和 Cloudflare 部署状态。
- 系统跟踪与本次发布对应的版本。只有 Cloudflare 确认部署成功后，才显示该版本发布成功和访问地址。
- 构建、推送或部署失败时，用户能区分失败步骤、查看原因并在修复后重试。
- 发布中断、重复点击或某步骤成功后后续失败时，按详设恢复，不误报成功。

**待详设**：版本关联、状态查询、失败信息、重试和中止策略。

### US-SITE-09　绑定自有域名

**用户故事**：作为用户，我希望通过自己的域名访问已经发布的网站。

**验收草案**

- 用户可以输入自有域名并发起绑定，看到与其账号和域名情况相符的后续步骤。
- 需要用户配置 DNS 或验证所有权时，界面展示所需操作和当前状态。
- 用户可以刷新并查看待配置、验证中、已生效或失败等状态；只有实际生效后才显示绑定完成。
- 遇到域名冲突或验证失败时，提供原因和可执行的后续操作。

**待详设**：根域名和子域名支持范围、DNS 托管商差异、证书状态、解除和更换域名。

### US-SITE-10　修改后再次发布

**用户故事**：作为用户，我希望持续修改自己的独立站，并在确认后更新线上版本。

**验收草案**

- 用户能继续使用智能体修改已有站点并预览，再主动发起发布。
- 页面能区分本地已修改、正在发布和已发布状态，并指向相应版本。
- 关联仓库和 Cloudflare 项目可复用，发布目标与待发布内容对用户可见。
- 再次发布成功后，线上状态对应本次确认的版本；失败时保留本地修改及已有线上访问信息。

**待详设**：变更检测、历史版本展示、远端修改冲突及版本恢复。

### US-SITE-11　重启、断线和异常恢复

**用户故事**：作为用户，我希望遇到中断后还能找到网站和下一步操作。

**验收草案**

- 应用重启后，站点项目及已保存的仓库、部署项目和域名关联能够恢复展示。
- 服务授权失效、网络中断、远端仓库变化或站点目录缺失时，界面展示对应问题和处理入口。
- 推送成功但部署未完成、部署状态未知或查询失败时，界面保留真实状态并允许重新查询。
- 重试操作不会静默覆盖远端修改，也不会把未知结果显示为成功。

**待详设**：状态持久化、凭据保护、同步机制和恢复操作。每个前置故事也须覆盖本身的失败场景。

## 6. 建议推进顺序

1. 以已验收的拆分为基础，逐项确定站点范围、用户流程和阶段验收细节。
2. 完成 TV-SITE-01 与 TV-SITE-02。TV-SITE-03 可与之并行，域名正式详设前需要结果。
3. 详设并实现 US-SITE-01～04，先演示从自然语言生成网站到本地预览和构建。
4. 依据账号验证结果详设并实现 US-SITE-05～08，演示客户自有账号发布及部署结果。
5. 完成 US-SITE-09～11，验证自有域名、再次发布和异常恢复，形成完整首期验收。

技术验证通过不等于产品故事已交付。具体每一阶段是否独立发布、何时纳入版本和是否再拆分，以后续核对为准。
