# 19 - 需求：简化运行环境安装

> **文档类型**：本期需求 + 用户故事（**US-R**）  
> **状态**：已评审待详设（支持计划 P0 · 简化运行环境安装）  
> **基线**：桌面端 **v0.5.2+**（现网 Node winget/MSI、OpenCode npm `--prefix`、OfficeCLI Gitee 直链已落地）  
> **关联**：[09-Node.js一键安装方案.md](09-Node.js一键安装方案.md)、[10-OpenCode一键安装方案.md](10-OpenCode一键安装方案.md)、[design/US-I-09-OfficeCLI可选安装.md](design/US-I-09-OfficeCLI可选安装.md)、[04-实施计划.md](04-实施计划.md)

---

## 1. 一句话目标

把 **Node.js** 与 **OpenCode CLI** 的默认安装方式，从「系统级 winget/MSI + npm install」改为 **下载官方预置包 → 解压/落盘到 `userData` 私有目录 → 写 prefs → 当场探测变绿**，降低 UAC、系统 PATH、npm 代理/卡死导致的首次启动失败率。

---

## 2. 背景与动机

### 2.1 用户痛点（现网反馈）

| 依赖 | 现网方式 | 典型问题 |
|------|----------|----------|
| **Node.js** | winget 指定版本 → 失败则官方 MSI + npmmirror | UAC 拒绝；装完 **系统 PATH 未写入**；须 **完全退出重启** 后才可能变绿 |
| **OpenCode** | 合格 Node 下 `npm install opencode-ai@1.18.4 --prefix userData/opencode-runtime` | **长时间卡住**；开网络代理仍失败；Windows wrapper/postinstall 已知问题；强依赖先装好 Node+npm |
| **OfficeCLI** | Gitee/GitHub 直链 exe + SHA256（已落地） | 体验较好，**无 npm、无 UAC、装完当场绿** → 作为 Node/OpenCode 新方案的参照 |

### 2.2 与现网文档的关系

- [docs/09](09-Node.js一键安装方案.md)、[docs/10](10-OpenCode一键安装方案.md) 描述 **已实现** 的 winget/MSI 与 npm 方案；**本需求不删除其历史决策记录**，但产品上 **仅保留私有运行时这一种一键安装路径**，**不设** winget/MSI/npm 并列入口，也 **不设**「私有失败则回退旧方案」的预案。
- OfficeCLI（[US-I-09](design/US-I-09-OfficeCLI可选安装.md)）的 **下载 + 校验 + prefs + 当场 probe** 模式，直接复刻到 Node zip 与 OpenCode exe。

### 2.3 目标用户场景

```text
首次打开 FTCS → 引导「环境」步
  ① 一键准备 Node   → userData/node-runtime/     （无 UAC、不写系统 PATH）
  ② 一键准备 OpenCode → userData/opencode-runtime/opencode.exe （无 npm）
  ③ 重新检测 → 当场变绿（尽量 needsRestart: false）
  ④ Chrome 仍探测 + 外链 / 手动说明（本需求不扩 Chrome 一键装范围）
```

## 3. 已确认产品规则

| # | 规则 |
|---|------|
| **R1** | **默认安装**改为 **应用私有运行时**（`userData` 下固定目录），**仅 FTCS 子进程使用**；不依赖用户系统 PATH 是否写入成功。 |
| **R2** | **Node**：官方 **Windows x64 zip**（含 `node.exe`）解压到 `<userData>/node-runtime/`；prefs 增加 **`nodePath`**（指向 `node.exe` 绝对路径）。 |
| **R3** | **OpenCode**：**单文件 `opencode.exe` 或小型 zip** 落盘到 `<userData>/opencode-runtime/`；继续写已有 **`opencodePath`**；**安装阶段不执行 npm**。 |
| **R4** | **下载源**：与 OfficeCLI 一致 — **Gitee 团队镜像优先**，失败再 **官方 / GitHub / npmmirror** 回退；**钉死版本 + SHA256** 校验不过则失败。 |
| **R5** | **版本钉死**：Node **24.18.0**（与现网安装目标一致）；OpenCode **`opencode-ai@1.18.4`** 对应 Windows x64 二进制（与桌面 `@opencode-ai/sdk` ^1.18.x 同主版本；发版可 bump）。 |
| **R6** | **探测合格线不变**：Node **major ≥ 22** 即 `ok`；OpenCode 以 **可执行文件存在且 `--version` 可读** 为准（规则对齐现网 `env-probe`）。 |
| **R7** | **解析链（私有唯一）**：环境变量（`FTCS_NODE_PATH` / `FTCS_OPENCODE_PATH`）→ **prefs**（`nodePath` / `opencodePath`）→ **userData 默认私有路径**。**禁止**再扫描系统 PATH、注册表、npm `node_modules` 树作为 Node/OpenCode 就绪依据。 |
| **R8** | **成功感知**：目标 **needsRestart: false**，安装 IPC 返回后 UI **立刻 `runProbe()`**；若某步无法避免重启，须在 IPC 结果中显式 `needsRestart: true` 并说明原因。 |
| **R9** | **唯一安装路径**：引导 / 设置中 Node、OpenCode **仅有**「一键准备（私有下载）」；**移除或停用** winget、MSI、`npm install` 等旧安装编排，**不提供**「安装到系统」「改走 npm」等并列或回退入口。 |
| **R10** | **私有绑定**：用户 **一旦完成** 私有 Node / OpenCode 一键安装（prefs 已写入 `nodePath` / `opencodePath`，或 `userData` 下对应私有目录已落盘），即 **永久绑定私有模式** — 此后探测、spawn、重装 **只认私有链**；文件缺失或损坏时报 `missing` / `error` 并引导 **重新私有安装**，**不**回退系统安装或 npm 前缀。 |
| **R11** | **失败不回退旧方案**：私有下载、校验、解压、落盘任一步失败 → 提示 **重试**、查日志、**手动下载同版本私有资产**（Gitee/GitHub 直链）；**禁止**自动或文案引导用户改走 winget/MSI/npm/全局安装。 |
| **R12** | **运行期**：`ensurePreferredNodeOnPath()` / `ensureOpenCodeOnPath()` **仅**注入私有解析结果，再 spawn MCP、`opencode serve`、`npx` 等子进程；**不**因私有 Node 不可用而改用系统 PATH 上的 Node。 |
| **R13** | **OpenCode 与 Node 依赖**：OpenCode **安装**不执行 npm；**运行期 MCP / npx** 仍依赖 **同套私有 Node**；二者并列准备，不假定系统已装 Node。 |
| **R14** | **平台**：首发 **Windows x64**；其它平台 probe `missing` + 说明，一键按钮禁用（与 OfficeCLI 一致）。 |
| **R15** | **互斥**：任一 runtime（Node / OpenCode / OfficeCLI）安装进行中，禁用其它一键按钮（沿用现网习惯）。 |

## 4. 目录与 prefs 约定

| 运行时 | 落盘目录 | prefs 字段 | 环境变量兜底 |
|--------|----------|------------|--------------|
| Node | `<userData>/node-runtime/`（zip 解压后含 `node.exe`） | `nodePath` | `FTCS_NODE_PATH` |
| OpenCode | `<userData>/opencode-runtime/opencode.exe` | `opencodePath`（已有） | `FTCS_OPENCODE_PATH` |
| OfficeCLI | `<userData>/officecli-runtime/officecli.exe` | `officecliPath`（已有） | `FTCS_OFFICECLI_PATH` |

> **说明**：`userData` 为 Electron `app.getPath('userData')`，与 `officecli-runtime` 同级，便于运维与用户排查。

### 4.1 私有绑定判定（实现须一致）

满足 **任一** 即视为该运行时已进入 **私有绑定**，解析与重装 **不得回退旧方案**：

| 运行时 | 绑定条件 |
|--------|----------|
| Node | `prefs.nodePath` 已写入；或 `<userData>/node-runtime/` 下存在由本应用写入的 `node.exe` |
| OpenCode | `prefs.opencodePath` 已写入；或 `<userData>/opencode-runtime/opencode.exe` 由本应用落盘 |

绑定后若文件不可用：probe **`missing` / `error`**，UI 仅提供 **「重新安装（私有）」**，不探测、不使用系统 PATH / npm 遗留路径。

## 6. 用户故事详述

### US-R-00　Spike：资产来源与 SHA256

**作为** 开发，**我需要** 确认 Node 24.18.0 与 OpenCode 1.18.4 的 Windows x64 **可下载资产 URL、文件大小、SHA256、是否纯静态二进制**，**以便** Gitee 镜像与代码常量一次钉对。

| 项 | 内容 |
|----|------|
| 优先级 | Must（阻塞 R-01 / R-02） |
| 依赖 | 无 |
| 状态 | 待实施 |

**验收要点**

- **Node**：确认 `node-v24.18.0-win-x64.zip` 官方 URL；npmmirror 等价 URL；解压后 `node.exe` 路径；SHA256。
- **OpenCode**：从 **GitHub Release CLI 包** 或 **`@opencode-ai/opencode-windows-x64@1.18.4` npm tarball** 提取 `opencode.exe`；**勿**误用 Desktop 安装包；确认 **运行 `opencode serve` 是否仍依赖外部 Node**（若 CLI 自包含，则与 R-11 一致：仅 MCP 要 Node）。
- 产出 **`docs/research/运行时私有安装-spike.md`**：推荐主源 URL、Gitee 镜像命名建议、SHA256、体积、许可说明。
- 发版运维清单：升版本时同步 Gitee Release 资产 + 改代码常量。

---

### US-R-01　私有 Node 运行时（zip 下载解压）

**作为** 外贸业务员，**我想** 在引导里一键下载 Node 到应用目录，**以便** 不必 UAC、不必自己配系统 PATH，也能跑 MCP 和 npx。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-R-00 |
| 状态 | **编码已落地** → [design/US-R-01-私有Node运行时.md](design/US-R-01-私有Node运行时.md) |

**验收要点**

- 新增 `install-node-portable-service.ts`（或等价命名）：Gitee → 回退官方/npmmirror；下载 zip → SHA256 → 解压到 `<userData>/node-runtime/` → `writeUserPrefs({ nodePath })`。
- 扩展 `user-prefs.ts`：`nodePath?: string`。
- 扩展 `resolve-node.ts` / `ensurePreferredNodeOnPath()`：**仅**走私有解析链（**R7**）；**删除或停用**注册表、PATH 扫描回退。
- `probeNode()`：未绑定且无私有目录 → `missing`；已绑定或装完 → 只校验私有 `node.exe` 且 `major ≥ 22` → `ok`，否则 `error` / `missing`。
- IPC：`onboarding:install-node` **仅**走 portable；返回 `needsRestart: false`（目标）；失败码、日志路径、手动 URL 对齐 OfficeCLI 形态；失败 **不回退** winget/MSI（**R11**）。
- 设置 / 引导：**唯一按钮**「一键准备 Node」；**移除** winget/MSI 安装入口与相关 IPC 调用。
- 单测：mock 下载/解压、prefs 写入、resolve 顺序。

**本故事不做**：修改 OpenCode 安装逻辑（R-02）；Chrome。

---

### US-R-02　OpenCode 二进制直装（替代 npm）

**作为** 外贸业务员，**我想** 一键下载 OpenCode 可执行文件，**以便** 不被 npm install 卡死，也无需先解决 npm 代理问题。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-R-00（与 R-01 无硬顺序，可并行） |
| 状态 | **编码已落地** → [design/US-R-02-OpenCode二进制直装.md](design/US-R-02-OpenCode二进制直装.md) |

**验收要点**

- 新增 `install-opencode-binary-service.ts` + 下载/校验模块（可抽 `opencode-download.ts`，对齐 `officecli-download.ts`）。
- 落盘：`<userData>/opencode-runtime/opencode.exe`；`writeUserPrefs({ opencodePath })`。
- **移除或停用** 现网 `install-opencode-service.ts` 中 **npm install** 全路径；**删除** `need-node` 安装门禁（OpenCode 安装本身不依赖 npm）。
- 更新 `opencode-paths.ts`：默认路径 **扁平 exe**；**不再解析** `node_modules/opencode-ai/...`；绑定后 **不回退** npm 前缀（**R7、R10**）。
- `needsRestart: false`；装完立刻 probe 变绿。
- 版本钉死 **1.18.4**；与 SDK 联调 `opencode serve` smoke。
- 失败文案：Gitee/GitHub **私有资产**直链 + `getDocsInstallUrl()`；**禁止**引导 npm / 全局安装（**R11**）。

**本故事不做**：升级 OpenCode 大版本（随发版 bump）；Desktop GUI 安装包。

**作为** 外贸业务员，**我想** 在首次引导里按清晰顺序准备 Node 和 OpenCode，**以便** 少踩坑、少重启。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-R-01、US-R-02 |
| 状态 | 待详设 |

**本故事不做**：Chrome 一键装；「一条龙自动装三个 runtime」强制编排（可文案建议顺序：Node → OpenCode）。

## 7. 非功能需求

| 项 | 要求 |
|----|------|
| **安全** | 仅 HTTPS；SHA256 不过禁止落盘；日志不打印完整 token |
| **可观测** | 每次安装写 `logs/node-install-*.log` / `logs/opencode-install-*.log`（与现网命名习惯一致） |
| **兼容（仅升级过渡）** | 本需求 **上线前** 已用旧方案就绪、且 **prefs 尚未绑定私有** 的用户，可在 **首次升级后** 仍被旧逻辑探测为 ok（一次性过渡，详设可选迁移策略）；**一旦完成私有安装或写入 prefs**，即按 **R10** 永久私有绑定，**不回退** |
| **可测** | resolve 顺序、SHA 失败、解压失败、prefs 读写单测；主进程集成测试 mock 下载 |
| **运维** | 发版 checklist：bump 版本 → 上传 Gitee Release → 更新常量 SHA256 → 手工引导验收 |
| **体积** | Node zip + OpenCode exe 不进主安装包；首次一键时才下载 |

## 8. 风险与开放问题

| # | 项 | 倾向 |
|---|-----|------|
| O1 | 直链下载仍受企业代理/防火墙影响 | Gitee 主源 + 失败文案含手动下载说明；后续可加 `HTTPS_PROXY` |
| O2 | OpenCode CLI 是否完全自包含、不依赖外部 Node | **R-00 Spike 必须确认**；若依赖 Node，仅影响「能否去掉 Node 前置」，不影响「去掉 npm 装 OpenCode」 |
| O3 | 旧用户 `opencode-runtime/node_modules` 占盘 | 私有重装后只认 flat exe；npm 遗留目录 **不参与解析**；可选后续清理工具，非 MVP |
| O4 | 用户机器上另有系统 Node 20/22 | **绑定私有后** FTCS **只用** 私有 Node；**不**因系统 PATH 上有其它版本而切换 |
| O5 | 钉死版本与安全更新 | 随 FTCS 发版 bump；不在应用内自动追 latest |
| O6 | 许可与再分发 | Node MIT；OpenCode MIT；Gitee 镜像注明上游来源 |

## 9. 验收场景（端到端）

| 场景 | 期望 |
|------|------|
| 全新 Windows x64，无 Node/OpenCode | 引导内依次一键 Node、一键 OpenCode → **当场** Node/OpenCode 行变绿；可继续引导 |
| 无 Node/OpenCode，用户不点一键 | Node/OpenCode 行 **`missing`**；**不**因系统 PATH 有 Node 而自动变绿 |
| 私有 Node 装完，用户系统另有 Node 20 | FTCS **只用** 私有 24.x；**不**回退系统 Node |
| Gitee 不可用 | 自动回退 **官方/GitHub 私有资产**；仍 SHA 校验；**不**改走 winget/MSI/npm |
| SHA 不匹配 | 安装失败，不落盘，日志可查；UI 仅 **重试 / 手动下私有包** |
| 私有绑定后用户手动删除 `node.exe` | probe **`missing`**；仅 **重新私有安装**；**不**探测系统 PATH |
| 私有绑定后 OpenCode exe 损坏 | probe **`error`**；仅 **重新私有安装**；**不**解析 npm `node_modules` |
