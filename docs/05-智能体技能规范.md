# 05 - 智能体技能规范（Agent Skills）

Skills 是智能体执行标准化工作流的说明书。**权威目录**：`workspace/skills/`（OpenCode / 桌面 App 直接读取）。

## 1. Skill 通用结构

每个 Skill 目录包含：

```
workspace/skills/{skill-name}/
├── SKILL.md          # 主说明（必需）
├── prompts/          # 可选：子步骤 prompt 模板
└── examples/         # 可选：输入输出示例
```

### SKILL.md 模板

```markdown
---
name: skill-name
description: 一句话描述何时使用此 Skill
phase: 1
inputs:
  - name: input_name
    type: string
    required: true
outputs:
  - path: data/...
    schema: ProductProfile
---

# Skill 名称

## 何时使用
...

## 前置条件
...

## 执行步骤
1. ...
2. ...

## 输出要求
...

## 错误处理
...
```

## 3. Skill 详细规范

### 3.1 extract-product-profile

**触发语**：用户提供公司网站或产品文件，需要建立产品画像。

**输入**：
- `product_id`（可选，无则自动生成）
- `website_url`（可选）
- `file_paths`（可选，一个或多个）

**输入分流**（按类型选择不同工具，见 [02-系统架构.md](02-系统架构.md) 3.1 节）：

| 输入 | 工具 | 说明 |
|------|------|------|
| 网站 URL | `chrome-devtools-mcp` | `navigate_page` / `new_page` + `take_snapshot` 或 `evaluate_script` |
| 普通文件 | 智能体原生文件读写 | txt、md、json、csv 等可直接读取的文本类文件 |
| 特殊文件 | — | Phase 1 不支持；提示用户转换格式或等待后续扩展 |

**执行步骤**：

1. **若提供 `website_url`**（chrome-devtools-mcp）：
   - `navigate_page` 或 `new_page` 打开网站首页
   - `take_snapshot` 提取公司名、简介、导航结构
   - `evaluate_script` 收集站内链接
   - 由智能体按需自由探索相关页面（不设数量上限），优先补齐产品、认证、联系方式等画像字段；信息足够或边际收益递减时停止
   - 合并所有已访问页面的产品列表、认证、联系方式
2. **若提供 `file_paths`**（普通文件）：
   - 使用智能体原生 Read 工具读取文件内容
   - 将原始文件复制至 `data/products/{product_id}/inputs/` 归档
   - 若文件为 PDF/Excel/图片等特殊格式 → **停止**，提示：
     > 「该文件格式需专用解析器，当前版本暂不支持。请提供 txt/md/json/csv，或提供公司网站 URL。」
3. 若同时提供网站与文件，合并两路提取结果
4. 按 [03-数据模型.md](03-数据模型.md) 生成 `profile.json`
5. 计算 `readiness.score`
6. 若 `score < 60` 或缺少关键字段，向用户追问：
   - 目标市场（regions）
   - 目标买家类型（distributor/OEM/retailer）
   - 主要差异化卖点
7. 写入 `data/products/{product_id}/profile.json`

**输出**：`profile.json`，`status` 为 `ready` 或 `draft`

---

### 3.2 expand-keywords

**触发语**：产品画像已就绪，需要生成探索关键词。

**前置条件**：`profile.status == "ready"`

**输入**：`product_id`

**执行步骤**：

1. 读取 `data/products/{product_id}/profile.json`（`product_get`）
2. **由大模型**根据画像与获客目标生成五维关键词与可执行 `search_queries`（30～50 条，覆盖 ≥4 维；R1 占多数）
3. 调用 `lead-store.keywords_save` 校验并落盘（**已移除**规则工具 `keywords_expand`）
4. 输出至 `data/keywords/{product_id}/expansion.json`

**输出**：`expansion.json`

---

### 3.3 discover-leads

**触发语**：需要执行一轮或多轮获客探索。

**输入**：
- `product_id`
- `rounds`（默认 `["R1"]`）
- `max_queries`（默认 10，防止超预算）

**执行步骤**：

1. 读取 `expansion.json`，筛选指定 `rounds` 的 queries
2. 创建探索运行记录 `run_{id}.json`，`status: running`
3. 对每个 query（不超过 `max_queries`）：
   a. 调用 `search-api.search_web` 执行搜索
   b. 取 Top 5 结果，使用 `chrome-devtools-mcp` 打开页面：
      - `new_page(url)` 或 `navigate_page`
      - `take_snapshot` 或 `evaluate_script` 提取页面内容
   c. 智能体判断：是否为目标客户？
      - 是 → 生成线索记录（含 `match_reason`、`source.url`）
      - 否 → 跳过
   d. 调用 `lead-store` 追加至 `raw/{round_id}.jsonl`
4. 更新运行记录：`status: completed`，填写统计

**判断目标客户标准**（智能体依据）：
- 公司类型属于 `buyer_personas.company_types`
- 国家属于 `target_markets.regions`（若有）
- 业务与 `products` 相关（经销、使用、生产配套）
- 排除：纯资讯站、招聘站、政府机构、直接竞品

**输出**：`data/leads/{product_id}/raw/*.jsonl`、`data/exploration/.../runs/*.json`

---

### 3.4 score-and-dedupe

**触发语**：原始线索需要评分、去重、分级。

**输入**：`product_id`

**执行步骤**：

1. 读取所有 `raw/*.jsonl`，合并
2. 去重：按 `dedupe_key`（域名规范化）保留最高分原始记录
3. 对每条线索计算 `score_breakdown`（六维）与加权 `score`
4. 分配 `tier`：high / medium / low
5. 若已有 `scored.json`，保留已有线索的 `status` 不被覆盖
6. 调用 `lead-store.leads_score_and_dedupe` 自动完成上述步骤，写入 `scored.json`（保留）与 `discarded.json`（同域名淘汰）

**输出**：`scored.json`、`discarded.json`

---

### 3.5 draft-outreach-email

**触发语**：为高意向线索生成开发信草稿。

**输入**：
- `product_id`
- `lead_ids`（可选，默认 `tier == "high"` 且 `status == "new"`）

**执行步骤**：

1. 读取 `profile.json` 与目标线索
2. 为每条线索：
   a. 分析 `match_reason`、`source.url`、公司信息
   b. 生成 2 个 variant：`short`（≤ 120 词）、`professional`（≤ 200 词）
   c. 语言按客户 `country` 选择（默认 `en`）
   d. 记录 `personalization_evidence`
3. 调用 `lead-store.email_draft_generate` 自动生成；智能体审阅后可 `email_draft_save` 润色
4. 写入 `data/emails/{lead_id}/draft.json` 与 `draft.md`
5. 更新线索 `status` → `email_drafted`

**邮件约束**：
- 必须有明确 CTA（如预约通话、索要报价）
- 禁止虚假承诺、过度夸张
- 首封邮件不附大附件

**输出**：`draft.json`、`draft.md`（可选）

---

### 3.6 review-and-send-email（Phase 2）

**触发语**：用户审核邮件并确认发送。

**输入**：`lead_id`、`variant_type`、`approved: boolean`

**执行步骤**：

1. 读取 `draft.json`
2. 若 `approved == false`：更新 `review`，线索 `status` → `rejected`
3. 若 `approved == true`：
   - 记录 `selected_variant`
   - 调用 `email-sender` 发送
   - 线索 `status` → `contacted`
4. 回写 `draft.json` 与 `scored.json`

## 4. Skill 调用顺序（标准流水线）

```
extract-product-profile
        ↓
expand-keywords
        ↓
discover-leads (可多次，不同 round)
        ↓
score-and-dedupe
        ↓
draft-outreach-email
        ↓
[人工审核]
        ↓
review-and-send-email (Phase 2)
```

## 5. 在 Cursor 中启用

Phase 1 实施时，将 `skills/` 中各 Skill 同步至 `.cursor/skills/`，智能体即可通过描述自动匹配。

用户典型对话：

> 「这是我们的产品网站 https://example.com，请提取产品画像。」  
> → 触发 `extract-product-profile`

> 「基于当前产品，扩展关键词并开始 R1 探索。」  
> → 触发 `expand-keywords` → `discover-leads`
