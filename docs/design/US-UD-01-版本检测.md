# US-UD-01 详细设计：版本检测（启动 / 手动 / 定时）

> **用户故事**：作为 Windows 上的外贸业务员，我想在启动、手动点「检查更新」、以及大约每天一次时发现新版本，以便不用自己记着去官网看。
> **范围**：三条检测入口；成功检查后记下时间；有更新则立刻交给 US-UD-02 后台下载；已是最新只在手动检查时说明；检查失败不当成已是最新。
> **依赖**：[27-需求-后台检测与下载更新.md](../27-需求-后台检测与下载更新.md) UD1、UD5、UD6、UD8；现网 `desktop/electron/update/update-check.ts`、`desktop/src/composables/useUpdateCheck.ts`、`desktop/src/views/SettingsView.vue`。
> **不在本期**：后台下载与安装引导的实现细节（US-UD-02）；electron-updater；便携版；macOS；强制最低版本；改发版、打 tag、改官网下载页。
> **文档位置**：`docs/design/`
> **状态**：**已确认待开发**

## 0. 相对现网

| 现网 | **本期（UD-01）** |
|------|-------------------|
| 启动约 2.5 秒后检查一次 `latest.json` | 保留。每个进程启动仍检查一次，不因为刚查过就跳过 |
| 设置里手动「检查更新」 | 保留，且与启动、定时走同一套结果 |
| 没有运行中的 24 小时再查 | 距上次**成功**检查满 24 小时再查一次 |
| 有更新只出横幅，主按钮「前往下载页」 | 有更新不弹「是否下载」，立刻进入 US-UD-02 |
| 「忽略此版本」和 7 天「稍后提醒」会压住横幅 | **去掉**。这两条不得再挡住检测，也不得挡住随后的下载 |
| 检查失败文案是「检查更新失败：…」，且 `hasUpdate` 为 false | 保持失败文案；界面不得写成「已是最新」 |

---

## 1. 目标与非目标

### 1.1 目标

1. 启动自动检查一次（沿用现网约 2.5 秒延迟，避免和引导、OpenCode 抢焦点）。
2. 设置页「检查更新」仍在，`forceNotify: true`。
3. 进程一直开着时，距上次成功检查 24 小时再查一次。成功指清单拉取且版本比较完成（`ok: true`），不管有没有新版本。失败不刷新这个时间。
4. `isNewerVersion` 仍用现网 `semver.ts`：高于当前版本才算有更新。
5. 有更新则调用 US-UD-02 的开始下载，不先问。
6. 手动检查且已是最新：设置页提示「已是最新版本（当前版本号）」，不出现横幅。
7. 启动或定时检查且已是最新：不提示、不挡主流程。
8. 检查失败：短错误说明，并给出重试和「去官网下载」。不得显示成已是最新。

### 1.2 非目标

| 不做 | 说明 |
|------|------|
| 引入 electron-updater 或改更新源域名 | 仍读 `getUpdateManifestUrl()`，即 `{官网根}/updates/latest.json` |
| 强制最低版本 | 清单里的 `minVersion` 可以继续解析，但**不得**因此静默安装，也不得藏起「稍后」 |
| macOS 及其他平台 | `process.platform !== 'win32'` 不开始下载，检测结果仍可按现网打开下载页 |
| 改官网下载页、发版流程、打 tag | UD6 / 需求 4.2 |

---

## 2. 已确认选型

| 项 | 决定 |
|----|------|
| **Q1 更新源** | 继续官网 `latest.json`。不引入 electron-updater。 |
| **Q2 检测节奏** | 启动必查一次；手动保留；运行中距上次成功检查 24 小时。24 小时 = `24 * 60 * 60 * 1000` 毫秒。应用关掉期间不补定时，下次启动的那一次检查即补上。 |
| **Q3 忽略与 7 天稍后** | 界面去掉「忽略此版本」和现网「稍后提醒」。`dismissedVersion`、`snoozeUntil` 不再参与要不要下载。安装上的「稍后」归 US-UD-02，不是这 7 天逻辑。 |
| **Q4 失败** | 失败文案保留「检查更新失败：…」。另给重试（再跑一次检查）和「去官网下载」（打开现网 `downloadPage`，缺省 `getDownloadPageUrl()`）。 |

## 3. 实现要点

### 3.1 记住上次成功检查

`user-prefs.ts` 的 `update` 增加 `lastCheckedAt?: string`（ISO 时间）。

只在 `checkForAppUpdate` 返回 `ok: true` 时写入。失败不写。

现有 `dismissedVersion`、`snoozeUntil` 保留字段，避免旧文件读坏，但本故事的判断不再读它们。

### 3.2 三条入口

1. **启动**：`useUpdateCheck` 的 `bootstrapUpdateCheck` 仍只跑一次，`setTimeout` 2500ms 后 `checkForUpdate({ forceNotify: false })`。
2. **手动**：`SettingsView.vue` 的 `onCheckUpdate` 仍 `forceNotify: true`。有更新时，设置页文案改为「发现新版本 x.x.x，正在后台下载」，不再写「可点击前往下载页获取安装包」。
3. **定时**：主进程在一次成功检查之后，用一次性定时器安排下一次，延迟为 `max(0, lastCheckedAt + 24h - now)`。到点再调 `checkForAppUpdate({ forceNotify: false })`。不要用短轮询。进程退出则定时器自然消失。

同一时刻只允许一次检查在飞。手动如果撞上正在检查，等这一次结束，用它的结果，不并行打两次清单。

### 3.3 有更新就交下载

`hasUpdate === true` 且平台是 `win32` 时，检查函数返回前调用 US-UD-02 的开始下载（同一版本已在下或已下好则由 UD-02 自己忽略）。

不弹「是否下载」。不先打开官网。

非 Windows：不调用开始下载。设置页和横幅保持现网「前往下载页」。

### 3.4 已是最新与失败

| 结果 | 启动 / 定时 | 手动 |
|------|-------------|------|
| `ok && !hasUpdate` | 不显示横幅 | 设置页「已是最新版本（版本号）」 |
| `ok && hasUpdate` | 进入下载，横幅按 UD-02 | 同上，设置页写正在后台下载 |
| `!ok` | 横幅一行错误 +「重试」+「去官网下载」，不挡主界面 | 设置页同一句错误，并给出这两个动作 |

`hasUpdate` 在失败时保持 false，但文案禁止用「已是最新」。

### 3.5 去掉的界面

`UpdateBanner.vue` 删除「忽略此版本」按钮，删除现网「稍后提醒」（7 天）按钮。`preload` 的 `dismissUpdate` 不再被界面调用。通道可以留着，避免这次为删 IPC 扩大改动；新逻辑不得再调用。

## 7. 风险

| 风险 | 缓解 |
|------|------|
| 启动每次都查，清单请求变多 | 只在启动、手动、满 24 小时，且同时只飞一次 |
| 旧的忽略记录还在 prefs 里 | 明确不读 `dismissedVersion` / `snoozeUntil` 来决定下载 |
