# US-G1-03 设置页余额与用量展示设计

> **用户故事**：[../12-官方模型通道用户故事.md](../12-官方模型通道用户故事.md) · US-G1-03  
> **状态**：编码已落地 · 交互稿 `04c`；今日 Token 占位（等网关 `today`）  
> **范围**：官方通道**已开通**时，设置页展示账户余额（厘→元）；调用 `GET /v1/usage/me`（sk）；今日 Token 与网关 G0-16 对齐（见 §0）  
> **需求映射**：[../11-官方模型通道对接.md](../11-官方模型通道对接.md) FR-DESKTOP-04；AT-D-02  
> **依赖**：US-G0-16（usage/me）、US-G1-02（本地 sk / `officialProvisioned`）  
> **不做**：402 / 充值引导（G1-04）；自定义通道调网关；在线支付；网关补 `today` 聚合  
> **文档位置**：`docs/design/`

---

## 0. 相对需求的收窄

| 来源 | 期望 |
|------|------|
| FR-DESKTOP-04 / 用户故事原文 | 余额（元）**+ 今日输入/输出 Token** |
| 网关 **US-G0-16（已落地）** | **`GET /v1/usage/me` 仅 `balance_li`**，响应**无 `today`** |
| G1-01 衔接表述 | 今日用量若网关未就绪 → **先只展示余额** |

**本期 Desktop 决定**：

| 项 | 决定 |
|----|------|
| **余额** | **Must**：调 `usage/me`，厘→元正确展示（AT-D-02 余额部分） |
| **今日 Token** | UI **预留一行**（输入 / 输出）；网关未返回时显示「—」+ 短提示「今日用量即将支持」；**不**本地扫日志伪造 |
| **后续** | 网关补 `today` 后，同一组件填真实数，不改信息架构 |

交互稿同时画出「有余额 + 今日占位」完整态，避免编码后再改布局。

## 1. 已确认选型

| 项 | 决定 |
|----|------|
| **Q1 展示位置** | **设置 → 模型通道 → 官方通道** 区块内（与「费用从账户余额扣除」同区）；**不**放账号与授权区 |
| **Q2 何时拉取** | `channelMode === 'official'` **且** `officialProvisioned`；进入设置 / 切到模型分类 / 开通成功后 / 用户点「刷新」 |
| **Q3 鉴权** | 本地 `FTCS_GATEWAY_API_KEY`（sk）；**不用** UC JWT |
| **Q4 换算** | `yuan = balance_li / 1000`；展示保留 **2～3 位小数**（建议最多 3 位，去尾零）；单位「元」 |
| **Q5 负余额 / 零** | 仍展示（可警告色）；不拦截设置页 |
| **Q6 自定义通道** | **不**调 `usage/me`；不展示余额卡片 |
| **Q7 未开通 / 未登录** | 不调接口；无余额卡片（保持 G1-01/02 登录/开通引导） |
| **Q8 刷新** | 手动「刷新余额」；打开设置时自动拉一次；**不做**短间隔轮询（避免无意义打网关） |
| **Q9 错误** | 401/403 → 提示凭证失效并引导「重置网关凭证」；网络错误可读文案；失败时保留上次成功缓存（若有） |
| **Q10 与搜索「今日用量」** | 搜索区 Tavily 日限额**保持原样**；文案勿与网关 Token 混淆（网关侧标签用「账户余额 / 今日 Token」） |

## 2. 目标与非目标

### 2.1 目标

1. 官方已开通用户能在设置里看到**当前余额（元）**。  
2. 数据来自 `GET {FTCS_TOKEN_GATEWAY_BASE_URL}/usage/me`。  
3. 交互稿与实现信息架构一致（已开通态含余额区）。

### 2.2 非目标

| 不做 | 归属 |
|------|------|
| Chat 402 横幅 / 充值说明 | G1-04 |
| 网关实现 `today` | token-gateway 后续 |
| 用量图表 / 历史账单 | 超出 MVP |
| 账号区重复展示余额 | 避免双入口 |

## 3. 信息架构与交互稿

### 3.1 设置 · 官方已开通（编码目标态）

```text
设置 → 模型通道
  ├─ 通道 chip：官方（选中）
  ├─ 说明文案
  ├─ 状态条：已开通 · sk 掩码 · [重置网关凭证]
  ├─ ★ 账户用量（本期新增）
  │     账户余额    ¥12.340          [刷新]
  │     今日 Token  输入 — · 输出 —   （占位）
  │     小字：今日用量待网关开放；余额来自 Token 网关
  ├─ 默认模型 / 轻量模型
  └─ 当前模式摘要
```

### 3.2 Pencil 画板

| Frame | 用途 |
|-------|------|
| `04 Workspace · 设置 · 官方通道` | 保留：**未登录**态（去登录） |
| `04b … 自定义通道` | 不变 |
| **`04c Workspace · 设置 · 官方已开通 · 余额`**（新增） | **已开通** + 余额卡片 + 今日 Token 占位 + 模型下拉可用 |

编码以 **04c** 为官方已开通视觉基准。

### 3.3 文案草案

| 场景 | 文案 |
|------|------|
| 余额标签 | 账户余额 |
| 余额值 | `¥{yuan}`（如 `¥0` / `¥12.34` / `-¥0.5`） |
| 今日占位 | 今日 Token · 输入 — · 输出 — |
| 脚注 | 余额来自 Token 网关；今日用量即将支持 |
| 加载中 | 正在获取余额… |
| 刷新失败 | 无法获取余额：{reason} |
| sk 失效 | 网关凭证无效，请重置网关凭证 |

## 4. API 消费（对齐 G0-16）

权威：[token-gateway/docs/design/US-G0-16-查询余额usage-me设计.md](../../token-gateway/docs/design/US-G0-16-查询余额usage-me设计.md)

```http
GET {base}/usage/me
Authorization: Bearer sk-…
```

成功字段（本期使用）：

| 字段 | Desktop 用途 |
|------|----------------|
| `balance_li` | 换算展示 |
| `li_per_yuan` | 优先用响应值（默认 1000） |
| `key.prefix` / `key.name` | 可选与开通态掩码交叉校验 |
| `today` | **若未来出现**：填入输入/输出；本期忽略缺失 |

错误：与 models/sk 一致（401/403/503/网络）。

## 5. Desktop 模块设计

### 5.1 `gateway-client.ts`

新增 `getUsageMe({ apiKey, baseUrl? })` → `{ balanceLi, liPerYuan, keyPrefix?, … } | GatewayClientError`。

### 5.2 `official-channel-service` 或 `usage-service`

| 函数 | 行为 |
|------|------|
| `refreshOfficialUsage()` | 读 sk → `getUsageMe` → 更新内存缓存 → 可合并进 SettingsSnapshot |
| 开通成功后 | 可顺带调一次（rotate 已有 `balance_li`，仍以 usage/me 为准刷新） |

### 5.3 Snapshot 扩展（建议）

```ts
export interface OfficialUsageSnapshot {
  balanceLi: number
  balanceYuan: number          // 已换算
  balanceDisplay: string       // 如 "12.34"
  liPerYuan: number
  keyPrefix?: string
  /** 今日：网关未提供时均为 null */
  todayPromptTokens: number | null
  todayCompletionTokens: number | null
  fetchedAt: number
  error?: string
  loading?: boolean
}

// SettingsSnapshot 增加：
officialUsage: OfficialUsageSnapshot | null
```

自定义 / 未开通 → `officialUsage: null`。

### 5.4 IPC

| Channel | 说明 |
|---------|------|
| `gateway:refresh-official-usage` | invoke；返回 usage + 可选更新后的 settings |

打开设置时：已有 `refreshOfficialModels`；可并列调用 `refreshOfficialUsage`，或合为一次「刷新官方通道状态」——**建议分两个 IPC**，职责清晰。

### 5.5 UI（`SettingsView`）

- 仅 `isOfficial && officialProvisioned` 渲染 `UsageCard`
- 绑定 `snapshot.officialUsage`
- 「刷新」按钮 → IPC
- 引导 Onboarding：**不强制**展示余额（可省略，避免干扰开通主路径）
