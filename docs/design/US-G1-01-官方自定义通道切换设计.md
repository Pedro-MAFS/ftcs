## 3. 信息架构

### 3.1 设置（`SettingsView`）

```text
设置 → 模型通道（原「模型与提供商」可改名）
  ├─ ○ 官方通道
  │     说明：经公司 Token 网关调用 DeepSeek，按账户余额计费；无需自备上游 Key
  │     若未登录：醒目状态「需要登录」+ 主按钮「去登录」（复用现有 OAuth）
  │     若已登录未开通：状态「未开通」+「开通官方通道」（逻辑 G1-02）
  │     若已开通：状态「已开通」+ 模型 flash/pro
  │
  └─ ○ 自定义
        API Key、Base URL、默认模型 ID、轻量模型 ID
        （不再出现 DeepSeek/Anthropic/OpenAI/Google 芯片）
```

分类标签建议：`模型通道`。

> **与「主流程免登」的关系**：线索/画像等仍可免登；**官方通道是账号能力**，与意见反馈类似——选官方或调用官方模型时必须登录，不得拖延到「引导结束再去设置」。

### 3.2 首次引导（`OnboardingOverlay` · phase `keys`）

| 现网 | 修订后 |
|------|--------|
| 下拉：五家 + 自定义兼容 | **二选一**：官方 / 自定义（与设置同款控件语义） |
| DeepSeek 提示链到 platform.deepseek.com | 官方：**未登录则引导登录**；已登录则提示开通（G1-02）；自定义：兼容接口说明 |
| 必填模型 API Key | **仅自定义**必填 Key；官方**不**填自备 Key |
| 未登录 + 官方 | 展示与「意见反馈需登录」同级的明确引导：**去登录**；可保存 `FTCS_CHANNEL_MODE=official`，但**不得**暗示「先跳过登录、引导结束后再设置里开通」 |

步骤标题可改为：「配置模型通道与搜索密钥」。

### 3.3 文案草案

| 场景 | 文案 |
|------|------|
| 官方 | 使用公司官方模型通道（Token 网关）。费用从账户余额扣除，无需自行购买 DeepSeek Key。 |
| 自定义 | 使用你自己的 OpenAI 兼容接口（含自备 DeepSeek / 其它兼容服务）。请求不经过公司网关计费。 |
| 官方 + 未登录 | **官方通道需要登录。** 请先登录用户中心，登录后即可开通。主按钮：**去登录** |
| 官方 + 已登录未开通 | 已登录。请开通官方通道以获取网关凭证。（开通按钮 → G1-02） |
| 官方未开通 preflight | 请先登录并开通官方通道（短码/文案指向登录或开通，而非「去设置里再说」）。 |

## 4. 数据模型与 `.env`

### 4.1 主键

| 键 | 说明 |
|----|------|
| `FTCS_CHANNEL_MODE` | `official` \| `custom`；**新装默认 `official`** |
| `FTCS_MODEL` / `FTCS_SMALL_MODEL` | 继续用；官方建议 `deepseek/deepseek-v4-pro` 与 `…-flash`（或网关 id 约定，编码时与 OpenCode provider 名对齐） |
| `FTCS_MODEL_BASE_URL` | **仅 custom** |
| `FTCS_CUSTOM_API_KEY` | **仅 custom**（可同步写 `OPENAI_API_KEY` 若现网 custom 已如此） |
| `FTCS_GATEWAY_API_KEY` | G1-02 写入；官方用 |
| `FTCS_TOKEN_GATEWAY_BASE_URL` | 网关 `/v1`；**G1-02 强制落地**；默认 `https://token.ai-utills.com/v1`（替换本机 8088 占位） |

### 4.2 废弃（UI/叠配不再使用）

| 键 / 概念 | 处理 |
|-----------|------|
| `FTCS_PROVIDER_ID=deepseek\|anthropic\|openai\|google` | 迁移后改为 `custom` 或删除；代码不再分支这四家 |
| 设置里写 `DEEPSEEK_API_KEY` / `ANTHROPIC_*` / … | **不再由设置写入**；迁移时可把 DeepSeek Key 拷到 `FTCS_CUSTOM_API_KEY` |
| `MODEL_CATALOG` 中 anthropic/openai/google/deepseek 大表 | 删除；官方用小表两模型；custom 仍手填 ID |

### 4.3 类型（建议）

```ts
export type ChannelMode = 'official' | 'custom'

export interface SettingsSnapshot {
  channelMode: ChannelMode
  officialProvisioned: boolean  // 是否已有 FTCS_GATEWAY_API_KEY
  // custom 字段：
  apiKeyMasked: string
  apiKeySet: boolean
  baseUrl: string
  model: string
  smallModel: string
  // …
}

export interface SettingsSaveInput {
  channelMode: ChannelMode
  apiKey: string      // custom 才有意义；official 可忽略
  baseUrl: string
  model: string
  smallModel: string
  // search…
}
```

`providerId: ModelProviderId` **删除或仅内部兼容一层**；对外 IPC 以 `channelMode` 为准。

## 5. 旧配置迁移

启动读设置时（`settings-service`）：

```text
mode = FTCS_CHANNEL_MODE
if mode 空:
  if FTCS_PROVIDER_ID in {deepseek, anthropic, openai, google, custom} 或已有自备 Key:
    mode = custom
    写回 FTCS_CHANNEL_MODE=custom
  else:
    mode = official   // 全新用户
    写回 FTCS_CHANNEL_MODE=official

if 旧 FTCS_PROVIDER_ID == deepseek 且 DEEPSEEK_API_KEY 有值且 FTCS_CUSTOM_API_KEY 空:
  拷贝到 FTCS_CUSTOM_API_KEY
  FTCS_MODEL_BASE_URL 默认 https://api.deepseek.com/v1（若空）
  FTCS_PROVIDER_ID 可写为 custom 或删除

if 旧为 anthropic/openai/google:
  → custom；Key 尽量从对应 env 拷到 FTCS_CUSTOM_API_KEY
  Base URL 需用户自填（无可靠默认则留空并提示）
```

原则：**不静默丢 Key**；预置厂商入口消失后，用户仍可在自定义里用回原 Key（DeepSeek 场景最顺）。

## 6. OpenCode / Preflight

```text
channelMode == custom
  → 现网 custom 分支：baseURL + FTCS_CUSTOM_API_KEY + 用户模型 ID

channelMode == official
  → 若无 FTCS_GATEWAY_API_KEY：不叠任何上游 Key；preflight 失败
  → 若有（G1-02）：baseURL=网关, apiKey=gateway sk, models=白名单
```

删除 `user-opencode-prefs.ts` 中 `providerId === 'deepseek'` 专用分支（官方改走网关分支；自备 DeepSeek 走 custom）。

Preflight：

| 模式 | 通过条件 |
|------|----------|
| custom | `apiKeySet && model && baseUrl`（baseUrl 是否强制：建议 **必填**，避免空打到错误主机） |
| official | `officialProvisioned`（本期多失败）+ model |
