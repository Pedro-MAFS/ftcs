# US-BG-01 至 03 · 后台运行与贸贸悬浮窗详细设计

0.6.6 · Windows 桌面端 · 待评审 · 2026-11-28。[需求与七项验收场景](../44-需求-后台运行与贸贸悬浮窗.md) · [Issue #175](https://github.com/Pedro-MAFS/ftcs/issues/175)

## 1. 窗口行为由谁决定

Electron 主进程处理用户关窗、进入后台、回到工作区和完全退出。进入后台时隐藏已有主窗口，保留渲染进程、当前标签和正在运行的服务。贸贸是一个按需创建的小窗口，只负责展示和接收鼠标操作。

| 现有入口 | 本次接入方式 |
| --- | --- |
| 主窗口的 `close`、启动时的 `startHidden` | Windows 手动关窗进入偏好判断；登录自启和 `--hidden` 直接进入后台。保留首屏延迟显示逻辑，回调执行时核对当前状态。 |
| 托盘「显示主窗口」、双击托盘、应用激活 | 恢复同一个主窗口。判断主窗口自身是否存在，避免把仍存在的辅助窗口当作主窗口。 |
| 任务通知和邮件通知 | 沿用现有 Windows 聚焦逻辑。主窗口的 `show` / `restore` 事件统一收起贸贸；邮件通知继续向主窗口发送原来的 `MAILBOX_OPEN` 目标。 |
| 托盘「退出」、应用内退出、更新安装器请求退出 | 均进入已有 `before-quit` 流程；增加贸贸菜单与关窗选择的「退出 FTCS」作为同一路径的入口。 |
| 主窗 `blur` / `minimize` | 保留任务等待回复的通知逻辑及普通最小化行为。按显示偏好在最小化或隐藏时展示贸贸。单纯失焦时保持原有显示状态。 |

当前入口可对照[主进程](../../desktop/electron/main.ts)、[托盘菜单](../../desktop/electron/tray/app-tray.ts)、[任务通知](../../desktop/electron/notify/task-done-notify.ts)和[新邮件通知](../../desktop/electron/notify/mail-notifications.ts)。新版交互以 Windows 为交付平台，其他平台沿用现有关窗路径。

## 2. 本机偏好与迁移（US-BG-03）

继续使用 `app.getPath('userData')/ftcs-prefs.json`，通过现有 `readUserPrefs` / `writeUserPrefs` 按字段读写。所有工作区共用一份设置。[偏好存储](../../desktop/electron/config/user-prefs.ts)

| 新字段 | 值与用途 |
| --- | --- |
| `closeAction` | `ask`、`background`、`quit`。明确保存的 `ask` 优先于旧值。 |
| `backgroundMascotEnabled` | 可缺省的布尔值。显式 `false` 表示已长期关闭显示。 |
| `mascotPosition` | 可选的 `{ x, y }`，以桌面逻辑像素（DIP）保存上次拖动结束的位置。允许副屏负坐标。 |

**第一次解析**按下表逐字段取值。读设置只计算结果；变更时写入最新文件，保留开机自启、其他工作区配置以及用户明确设置的另一项偏好。

| 原配置 | 有效关窗动作 | 贸贸显示规则 |
| --- | --- | --- |
| 新字段已设置 | 合法的新值优先 | 显式开关优先于所有默认值 |
| 旧 `closeToTrayEnabled === true` | `background` | 默认开启，包括旧版定时页一键开启的用户 |
| 旧值缺失或为 `false` | `ask` | 默认开启，含静默登录 |
| 字段损坏或值无法识别 | 将该字段视为缺失，逐字段按上面规则解析 | 无效坐标回到默认位置 |

旧版保存其他设置也可能写入 `false`。它没有足够信息区分“用户明确选过退出”和“只改过模型设置”。Windows 新版只读旧字段以兼容历史配置。实施时采用以下写入语义：

- 弹窗选择「后台运行」且未勾选记住，只执行这次动作，关窗偏好继续是 `ask`。勾选记住时只写入关窗动作。
- 关窗动作和贸贸开关分别保存。用户在设置页切换开关时写入显示偏好；在定时页一键开启后台只更新关窗动作和自启设置。
- Windows 上，普通保存从 `SettingsView.vue` 的 `saveSettings` 输入里移除 `closeToTrayEnabled` 和已单独即时保存的 `openAtLogin`。对应的 Windows 通用保存分支不再处理这两个启动字段，防止缓存的旧表单覆盖定时页或关窗弹框中的新选择。[设置页](../../desktop/src/views/SettingsView.vue) · [设置服务](../../desktop/electron/settings/settings-service.ts)

## 3. 关窗、恢复与退出（US-BG-01）

主进程保留一个会话内的窗口状态：`foreground`（含普通最小化）、`prompting`、`background`、`quitting`。进程启动时按本次启动方式初始化；只将用户偏好写盘。托盘从应用启动时即存在。

| 当前状态 / 事件 | 处理与下一状态 |
| --- | --- |
| 前台点 × 或 Alt+F4 | 同步拦截 `close`。根据有效偏好打开唯一弹框、进入后台或请求退出。 |
| 询问中再次关窗 | 使用现有弹框。取消、Esc 或弹框右上角 × 均返回前台，忽略复选框。 |
| 确认后台 | 应保存的偏好写入成功后，先置 `background` 再隐藏主窗；按显示偏好展示贸贸。托盘、邮箱、定时器和站点预览继续工作。 |
| 后台恢复主窗口 | 先置 `foreground`，撤销尚在加载的贸贸显示请求并收起悬浮窗，再还原主窗、显示并聚焦。通知跳转仍由原业务处理。 |
| 前台普通最小化、失焦，或内置浏览器获得焦点 | 仍属 `foreground`。最小化或隐藏后按开关显示贸贸，任务栏还原回到原页面并收起贸贸。失焦时保持原有显示状态。 |
| 任一状态收到明确退出 | 置 `quitting`，使未完成的弹框结果和悬浮窗加载回调失效，进入单次退出流程。 |
| 登录自启或 `--hidden` | 以 `background` 启动，按显示偏好决定是否显示贸贸。邮箱、OpenCode、定时调度沿用当前启动顺序。 |

### 工作区内的关窗对话框

用户从任务栏或主窗口发起关闭时，先显示工作区，再在当前页面中央打开模态对话框。弹框使用 FTCS 确认框的主题、遮罩和按钮样式，随应用切换明暗。默认聚焦「后台运行」，「记住我的选择」初始未勾选。「退出 FTCS」走现有退出流程。「取消」、Esc 和弹框右上角 × 都回到原页面。

主进程保存当前请求编号，页面通过 preload 在挂载时订阅并读取当前请求，重新加载后仍能显示待回答的弹框。主进程只接收主窗口主框架对当前编号的有效回答。

弹框挂起期间持有一次请求标识和 AbortController。若托盘先触发退出，取消弹框并作废其结果。需要记住选择但写盘失败时，保留主窗口并提示保存失败，用户可重新选择。正常显示主窗的延时回调也要核对状态，避免刚点完后台运行又被首屏兜底逻辑显示出来。

### 完全退出与草稿

从关窗选择退出时直接请求 `app.quit()`，去掉当前 `close` 回调里先保存草稿再 `win.close()` 的分支。所有主动退出最终由 `before-quit` 拦截，主窗口要保留到 `flushMailDrafts()` 完成。

1. 复用现有退出互斥，重复点击只共用一次保存和清理。若来自「记住并退出」，先保留待写偏好，草稿保存成功后写入。
2. 草稿或必需偏好写入失败时，撤销退出状态，收起贸贸、恢复原窗口，提示对应错误。用户可以继续编辑、保存和重试。业务服务此时仍在运行。
3. 成功后销毁贸贸和托盘，停止邮箱、调度、站点发布及预览、内置浏览器和 OpenCode，走现有进程退出收尾。系统更新等程序化退出同样跳过关窗询问。
4. Windows 注销、关机沿用系统会话结束处理，仅对应用内主动退出承诺上述可取消的草稿保存流程。

## 4. 悬浮窗与交互（US-BG-02）

**窗口和打包。** 主进程按需创建一个无父窗口的 `BrowserWindow`，首版建议 **72 × 72 DIP**，透明、无边框、不可调整大小、常规窗口之上、跳过任务栏。初始隐藏，内容就绪且当前状态仍为后台时调用 `showInactive()`。不强占正在使用的应用焦点。只有主窗的关闭事件会打开关窗弹框。

开发与安装包均加载同一份静态 HTML、CSS、脚本以及专用的沙箱 preload（CommonJS）。建议静态文件放在 `desktop/resources/mascot/`，开发时从该目录加载，图片定位到仓库已有素材；打包时用 electron-builder 的 `extraResources` 将静态文件和所用 PNG 映射到 `resources/mascot/`，页面使用统一的资源相对地址（开发态由加载器传入本地图片基址）。三帧解码后显示窗口，以实际显示为起点，半秒后双眨眼。此后每隔 4～8 秒随机单眨或双眨。悬停时显示张嘴帧并朝指针进入的一侧倾斜 4°，拖动时恢复正立微笑，隐藏时取消计时。系统开启「减少动态效果」时保留悬停表情切换。[现有素材](../../ftcs-mascot-icons/README.md) · [打包配置](../../desktop/package.json)

**点击与拖动。** 使用同一个图形按钮。左键按下时捕获指针，并通知主进程记录窗口起点和 `screen.getCursorScreenPoint()`。移动中以主进程读到的屏幕 DIP 计算位移。建议阈值为 5 DIP，超过后本次手势只拖动，按帧合并移动事件。移动与松手校正位置时都写入固定的 72 × 72 DIP 窗口边界，动画按钮按 72 × 72 CSS 像素绘制。松手时再次计算最终位移；点击走恢复，拖动按对应显示器的 `workArea` 将窗口放回可见范围并保存一次位置。取消捕获、弹菜单或隐藏窗口时结束手势，避免松手误开主窗口。右键只打开主进程创建的原生菜单，三个菜单项分别调用已有的恢复入口、暂时收起贸贸、请求退出。

**多屏和故障。** 首次靠当前主窗口所在显示器工作区右下角显示，建议距边缘 16 DIP。每次显示及屏幕拔插、分辨率或缩放变化后校正位置；原位置已在所有屏幕之外时回到主屏工作区。位置写入失败只影响下次恢复。「暂时隐藏贸贸」只在内存中记录，主窗口恢复可见时清除。同一次后台期间重复收到最小化、隐藏或设置同步事件时，贸贸保持隐藏。窗口创建、资源加载失败或悬浮窗渲染进程崩溃时销毁该实例，保留系统托盘和后台服务，下次进入后台可重新创建。使用 `webContents` 的载入结果及窗口实例标识防止过期回调显示旧窗口。[Electron 屏幕与坐标 API](https://www.electronjs.org/docs/latest/api/screen)

**窗口边界。** 通过已有 `allowCreatedWebContentsDuring` 创建悬浮窗，维持窗口创建检查。使用独立 preload、`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`，只加载本地页面并拒绝打开新窗口或跳转到其他页面。业务事件仍由原窗口接收，在遍历 `BrowserWindow.getAllWindows()` 的广播中排除贸贸。内置浏览器的标签发现和 CDP 列表继续过滤本地界面。[窗口创建检查](../../desktop/electron/browser-runtime/builtin-browser-window.ts) · [浏览器标签过滤](../../desktop/electron/browser-runtime/cdp-filter.ts)

## 5. 接口与文件落点

以下接口名为实现建议。设置类 IPC 仅接受主窗口主框架，手势 IPC 仅接受当前贸贸窗口主框架。主进程校验参数并返回最终生效的值。

| 调用方 | 契约 / 改动 |
| --- | --- |
| 设置页、定时页 | `getSettings()` 快照提供 `closeAction`、有效的 `backgroundMascotEnabled` 和 `openAtLogin`。设置页中的「主窗口最小化或隐藏时显示贸贸」与关窗进入后台、静默自启共用同一显示偏好。 |
| 设置页 | `setBackgroundPreferences({closeAction?, backgroundMascotEnabled?})` 只提交有改动的字段。返回成功或错误及当前有效偏好，写入失败时控件回退。由菜单或弹框改变偏好时，向主窗口发送 `background-preferences-changed`，已打开的设置页和定时页只更新相关字段。 |
| 定时页 | 仅当 `openAtLogin && closeAction === 'background'` 时满足常驻条件。「一键开启」复用现有开机自启入口及新的偏好接口，两项完成后重读状态；部分失败提示尚缺哪项，再点时只补缺项。仅保存计划继续使用原计划接口。 |
| 贸贸静态页 | 专用 preload 只暴露 `pointerDown / pointerMove / pointerUp / pointerCancel / openMenu`。主进程完成点击或拖动判定、取坐标和执行菜单动作。无需暴露整个 `window.ftcs`。 |

现有登录项写入异常只记日志。为使一键开启的反馈准确，Windows 上设置系统登录项后按相同的可执行文件和启动参数读取系统结果，再更新本地偏好；失败时返回实际状态和可读原因。启动时按偏好纠正登录项沿用已有入口。[登录项实现](../../desktop/electron/login/login-item.ts)

在 `electron/tray/` 内分别落地关窗偏好解析、后台状态协调、贸贸窗口与菜单；`main.ts` 负责注入主窗口、托盘和退出流程。设置改动同步更新主进程 IPC 类型、主窗口 preload、渲染端声明及设置视图，替换定时页的 `setCloseToTray` 调用。Windows 以外继续使用现有布尔语义及对应设置控件。[IPC 定义](../../desktop/electron/ipc/types.ts) · [主窗口 preload](../../desktop/electron/preload.ts) · [定时页](../../desktop/src/components/workflow/WorkflowSchedulePanel.vue)

## 6. 实施顺序与验证

| 交付顺序 | 可独立验证的结果 | 对应需求验收 |
| --- | --- | --- |
| 1 · 偏好迁移、关窗与退出 | 用空对象、旧 true / false、新旧值冲突、仅有显示偏好及损坏字段做表驱动测试。验证保存模型设置、重启及切换工作区后选择仍正确。模拟 Esc、连点 ×、弹框未返回时从托盘退出、草稿写失败后重试，统计真正的保存与清理调用次数。 | 1、2、3、7 |
| 2 · 贸贸与工作区恢复 | 在 Windows 按「关闭进后台 → 点击 / 拖动 / 右键 → 恢复」逐次核对标签和草稿。覆盖普通最小化、任务及邮件通知恢复、后台刚进入就立即还原、图片加载失败、连续进出后台。任务栏应只反映主窗口状态。 | 1、4、5、7 |
| 3 · 定时、自启与发布包 | 使用含旧偏好的工作区与新用户配置分别登录 Windows，核对静默启动、托盘可恢复、已选的贸贸显隐。后台等待一封测试邮件和一次定时触发，检查站点预览地址仍可访问。最后在安装包和便携版检查透明动画、右键菜单、双屏负坐标、混合缩放与拔屏后的可达性。 | 3、4、5、6 |

应用内弹框的键盘操作和任务栏关闭后的窗口恢复、Windows 登录自启焦点及跨屏拖动属于实机验收项。上述测试是开发完成后的验证计划。
