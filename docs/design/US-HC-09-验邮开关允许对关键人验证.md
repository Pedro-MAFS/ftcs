## 1. 对应需求

两条通道都保留这只开关。含义锁定为「允许对关键人验证邮箱」。

- 关闭：同一次补全只查找。技能硬禁止调用 `email_verifier`。
- 开启：允许对关键联系人验邮。验谁、验几封由智能体决定。技能提示必须提醒节省用量。不设每家硬顶，不写死 3 或 5。
- 未验的联系人仍写入。之后在抽屉单条验证，入口仍按 US-HC-03。

旧口径「开启则对查到的全部联系人自动验邮」「`verify_emails === true` 就对每个写入的联系人都调验邮」已被本故事超越。删除该技能规定，不再按它编码。

官方实际发起的验邮仍经网关代调并计入官方通道（交叉 US-HC-02）。自定义仍直连，消耗用户自己的 Hunter 额度（交叉 US-HC-04）。本篇不改这两条的传输和计费验收。

## 2. 模块与界面

勾选仍在 `desktop/src/views/SettingsView.vue` 的 Hunter 区块，官方分支与自定义分支各一处，绑定仍是 `form.hunterVerifyEmails`。两处现在的标签都是「补全联系人时验证邮箱」。

推荐原句（等马丰顺确认后再合入）：

- 勾选标签：**允许对关键人验证邮箱**
- 标签下短说明：**由智能体决定验谁、验几封，请注意节省用量。**

两处通道用同一句。删除「补全联系人时验证邮箱」。含义不得退回「开启则对查到的全部联系人自动验邮」。

`desktop/src/views/settings-hunter-panel.test.ts` 两处断言了旧句。实现时改成推荐原句。官方区块仍然只有免配说明和这只勾选，不把 Key、测试连接加回来（那是 US-HC-06）。

默认开或关不改：`parseHunterVerifyEmails` 缺省仍为开。保存仍写入 `.env` 的 `HUNTER_VERIFY_EMAILS`，与通道无关。

线索页官方费用 title「补全联系人并验证邮箱，费用从官方通道余额扣除」仍是 US-HC-02 已确认的费用句。本篇不改它。它只说明可能产生官方通道费用，不表示会对全部联系人自动验邮。要不要连这句一起改，等马丰顺在本 PR 回复。

抽屉「验证」不看这只开关。本篇不改 `LeadDetailDrawer.vue`，也不改 US-HC-03。

## 3. 数据与状态

| 项 | 约定 |
|----|------|
| 存储 | 仍是 `HUNTER_VERIFY_EMAILS`。桌面 `LEADS_ENRICH_CONTACTS` 与编排仍用 `getSettingsSnapshot().hunterVerifyEmails` 注入 `verify_emails`，忽略渲染进程另传的值 |
| 关闭 / 缺省未注入 | 技能硬禁止 `email_verifier`。对话里没人传入时，技能表仍按未开启处理；桌面按钮会注入设置值，设置缺省为开 |
| 开启 | 允许验关键人。没有「必须每人一封」的规定，也没有每家最多 3 或 5 封的常数 |
| 建议 | 「跳过 info@ / generic」只能写在技能提示里，作为节省建议。代码里不要滤掉这些邮箱，也不要因此拒绝验邮 |
| 写回 | 查找结果先全量写入，含未验的人。验过的人再 patch `email_status`。符合现网规则的才同步联系人：`hunter_valid` + personal + confidence ≥ 70 |
| 状态 | 不改枚举。`unknown` → `hunter_unknown` 终态，`webmail` → `hunter_invalid`。504 不写终态。与 US-HC-02 相同 |
| 缓存 | 验邮不加缓存 |

## 4. 调用链

查找与第一次写回仍按现网 Step 5（`sync_valid_to_contacts: false`）。然后：

- `verify_emails` 不为 true：到此为止，不调用 `email_verifier`。
- 为 true：智能体挑选关键联系人，对挑中的邮箱调用 `hunter-api.email_verifier({ email })`。同一封失败后不要再打。没有挑中的人保持已写入的状态。

官方挑中的每一封：一次 `POST {base}/hunter/email-verifier`，正文只有 `{ "email" }`，超时 90 秒，客户端不轮询。`base` 规则与 US-HC-01 相同。自定义挑中的每一封：仍走 `requestOnce("/email-verifier")` 与最多约 24 秒的 202 轮询。

要删除的现文（两处都有，从技能和桌面提示里删除）：

- 技能 Step 6「对 people 中每一条只调用一次」，以及输入表「是否对全部候选人验邮」、文首「对全部候选调用 Email Verifier」、流程图 `email_verifier×每人`。
- `buildEnrichLeadContactsPrompt` 里 `verify_emails=true` 的两句：「对当前 lead 的 people 每条只调用一次」「对 people 中每一条只调用一次」。
- 工具描述若要求对每个邮箱都调用，改成：仅当开关允许且这一封被选中时调用；失败后不要再打同一封。工具本身不要循环 `people[]`。

开关为 true 时，技能和桌面提示换成：

- 允许对关键联系人验邮。由你决定验谁、验几封。
- 注意节省用量。官方通道每封实际发起的验邮计入官方通道费用。不写单价，不写账本。
- 可以少验 `info@` 和 generic，这只是节省建议，不是必须。
- 未验的人留在 `people[]`。
- 成功且 `pending` 不是 true 时，状态映射与现在相同，然后再 patch，且 `sync_valid_to_contacts: true`。
- 工具报错不要改成 `hunter_unknown`，不要再打同一封。官方按工具中文转述。`pending: true` 仍只属于自定义轮询用尽。

`official-verifier-config.test.ts` 已经锁住、并且仍然有效的句子要继续满足：关闭时禁止调用、`unknown` 终态、`webmail` 映射、504 与 502 两句、不要再打同一封。改「对每人」时不要删掉这些句子。

实现若改了技能或 `hunter-api`，同一次升 `WORKSPACE_TEMPLATE_VERSION` 并打包 MCP。本详设不升。
