# US-MAIL-05 · 从审核页发出开发信并核对结果

0.6.4 · 已实现，用户已完成真实邮箱联测。

用户在「邮件审核」里选中 Alice，改好主题和正文，可以点「通过」留到以后，也可以点「通过并发送」。后者只需点击一次。服务器接受后，原按钮的位置显示「查看往来」，点开即可在邮箱里看到刚发出的这封信。Alice 在其他产品下的往来也在同一个会话里。

## 审核页上怎么发

沿用当前线索、收件人标签、主题和正文编辑器。在正文上方并列展示「发件邮箱」和「收件邮箱」，在当前收件人操作区并列放置「通过」和「通过并发送」。左侧草稿队列继续统计每条线索有多少份草稿通过审核。发送结果放在当前收件人旁，切换收件人时随草稿切换。[现有审核页](../../desktop/src/views/EmailView.vue)

| 当前情形 | 用户看到的内容与操作 |
| --- | --- |
| 待审核 | 「通过」只保存当前编辑并标为已通过。「通过并发送」先保存审核，再提交当前这封信。点击发送本身即确认页面显示的发件人、收件人、主题和正文。 |
| 已通过，尚未发送 | 显示「已通过」和「发送」。用户改了正文或主题，可以直接点「发送」确认并保存当前编辑，再投递。不能悄悄发出磁盘上的旧稿。 |
| 工作区未连接邮箱 | 保留编辑、保存和「通过」。「发送」入口提示「先连接工作区邮箱」，提供前往邮箱设置的入口。返回审核页保留所选收件人和编辑内容，连接成功后由用户点发送。 |
| 收件地址、主题或正文不符合发送条件 | 在对应字段旁说明原因，修正后可发送。「通过」沿用现有审核条件，例如暂缺收件地址也可以先审稿。 |

**实际收件人**。个人草稿显示一个完整的 To 地址。公司向草稿可能收集了 `info@`、`sales@` 等多个候选，建议改成单选，默认选草稿的有效主地址，其次为收件人池首个有效地址。用户可以改选，保存或通过后，下次打开沿用已选地址。原选择失效时提示重新选择。公司别名只进入候选列表。一次点击只向显示的一个地址投递，Cc、Bcc 为空。[收件人池](../../desktop/electron/emails/email-recipient-pool.ts)

**实际邮件**。按审核页显示的原文主题和正文发送一封新邮件。保留正文换行，中文对照、风格提示、个性化依据仅供审阅。邮箱页的首行主题规则、放大编辑器模板、当前引用和附件都不会被带入。已有工作区的旧版变体草稿沿用审核页现有的读取逻辑，用户看到哪一版就确认哪一版。

## 点完按钮后会看到什么

审核成功后一直显示「已通过」。旁边另列这次投递的结果，两者各回答一个问题。[工作区邮箱需求](../43-需求-工作区邮箱与即时通讯式会话.md)

| 发送状态 | 当前收件人下的反馈 | 下一步 |
| --- | --- | --- |
| 提交中 | 「已通过 · 发送中…」，固定本次收件人和原文 | 暂停本稿的发送、改写和驳回；用户可以切到别的收件人。 |
| SMTP 明确接受 | 「已通过 · 已发送」，显示发件邮箱和发送时间。「已发送」表示发件服务器已接受。 | 「查看往来」打开对应联系人，定位这封邮件。本稿的发送操作到此结束。 |
| 明确失败，如收件地址被服务器拒绝 | 「已通过 · 发送失败」，展示具体原因，保留地址和原文 | 「重新发送」。可以先改稿或改选有效地址，点击才发起下一次尝试。新地址不会因为失败就出现在联系人列表里。 |
| 无法判断服务器是否接受，如提交后回执丢失 | 「已通过 · 发送结果待确认」，保留本次投递快照 | 「检查已发送邮件」触发该账号已有的 IMAP 同步。匹配成功后变为「已发送」；暂时查不到就保留待确认，可去网页邮箱人工核对。若账号未绑定已发送文件夹，提示先在邮箱设置中选择。 |
| 审核保存失败，或审核已保存但发送还未开始 | 以落盘结果为准。前者提示保存失败；后者显示「已通过 · 尚未发送」并给出原因。 | 修复问题后继续。若只有线索汇总更新失败，先按草稿修复汇总，再允许发送。 |

待确认的这次投递只提供核对，刷新、重开和同步都不会再次提交 SMTP。用户确实要继续联系时，可在邮箱页主动写另一封。已发邮件保留当时的地址与原文；日后用户显式重新起草、审核形成的新稿，作为另一封处理。

## 审核与邮箱之间的数据约定

| 位置 | 持久化内容及用途 |
| --- | --- |
| 公司向 `data/emails/<lead_id>/draft.json`，个人向同目录下的 `<recipient_key>/draft.json` | 沿用 `status` 和 `review.reviewed_at`。新增可选的实际选中地址与审核版本 ID。首次发送前给当前审核版本分配 UUID，单纯刷新、翻译中文或重复保存相同外发内容都沿用。尚未发送或明确失败的稿件，修改实际地址、主题或正文并经用户确认后生成新版本。发起尝试时给该版本绑定 `account_id`、`request_id`，用于重开后取回结果。 |
| `data/mail/accounts/<account_id>/sends/<YYYY-MM>.jsonl` | 沿用发送尝试日志与状态。首条冻结发件人、唯一 To、主题、正文，并增加 `source = { kind: "outreach", product_id, lead_id, recipient_key, review_id }`。后续依旧按尝试追加结果。此日志是发送状态的依据。 |
| 同账号 `messages/<YYYY-MM>.jsonl` | 接受后复用尝试预分配的本地 `message_id` 写一条出站消息，保留 `source`。服务器改写邮件头或补回已发送副本时仍保留本地业务来源。普通往来和历史消息允许没有 `source`。 |

邮箱联系人继续按账号内的规范化邮箱地址归并。产品、线索和收件人草稿的 ID 只标识消息来源。邮箱消息详情可以显示「来自开发信审核」和对应产品、线索；原草稿仍存在时可回到该收件人，若已被重写则说明当前草稿已有更新。驳回、删除草稿或更名都不删除已发送邮件，原文以发送快照为准。[邮箱数据模型](工作区邮箱数据模型设计.md)

旧草稿缺少上述字段时照常审阅；首次保存所选地址或首次发送时按需补齐。已有 `approved` 草稿展示「已通过」，只有找到关联的发送记录才显示「已发送」。审核、保存、重写、翻译和旧变体兼容路径都要保留仍然有效的版本绑定；未决尝试不能通过重写或驳回同一草稿绕过。已通过数量及 `email_approved` 线索状态沿用现有汇总规则。[现有审核写入](../../desktop/electron/emails/emails-writer.ts)

## 一次点击怎样走到时间线

1. **核对并保存。** 审核详情返回草稿版本标记、候选地址和当前邮箱身份。点击时，审核页向主进程提交操作、产品与收件人定位、读取时的版本标记、当前编辑、明确选中的 To、邮箱上下文和请求 UUID。主进程按工作区校验草稿归属，复核账号连接代次、候选地址以及外发版本。另一个窗口重写了原稿或账号发生切换时，保留用户编辑并提示重新核对。只有「通过」继续使用现有审核入口，无需连接邮箱。
2. **固定待发版本。** 主进程对同一收件人草稿串行执行核对和本地写入。先持久化审核结果及请求绑定，再将快照以 `submitting` 追加到原账号的发送日志，成功后才调用 SMTP。相同请求只返回已有结果；同一审核版本即使从两个窗口用不同请求号点击，也只能有一次进行中、待确认或已接受的投递。明确失败后再次主动点击才分配新尝试。不要用主题、正文相似度或时间接近来合并邮件。
3. **共用发送服务。** 将现有撰写流程中的快照提交、SMTP 结果处理和本地回显提取为邮箱页、审核页共用的逻辑。审核入口直接提交自己的快照，不经过联系人输入框的保存和清稿。按实际 To 查找联系人，在接受后才建立新的可见会话。给 Alice 留在邮箱输入框的私有草稿、附件和引用，即使在审核页给 Alice 发信也原样保留。[现有发送与恢复逻辑](../../desktop/electron/mailbox/composer-store.ts)
4. **同步结果。** 主进程写入结果后通过现有 `mailbox:changed` 通知页面。审核页按当前收件人和审核版本重读状态，只更新匹配的投递，不覆盖其他正在编辑的草稿。邮箱页重读受影响的联系人和时间线。点击「查看往来」复用邮箱标签及已有的消息定位能力，传原账号、联系人和本地消息 ID，即使正在查看另一位联系人也能定位目标。

**重开应用**。若已保存审核绑定而发送日志还没有该请求，只能说明这次尚未开始 SMTP，显示「尚未发送」并等待用户点击。日志已记 `submitting` 但缺少终态时沿用邮箱恢复规则，归为待确认；已记 `accepted` 而本地消息尚未写完时，按原消息 ID 补齐。核对同账号已发送副本沿用 `X-FTCS-Send-ID` 或 `Message-ID` 命中任一个即可的规则。[发送恢复与副本核对](US-MAIL-03-写新邮件、引用回复和保留草稿.md)

**切换托管账号**。工作区由 A 改托管 B 后，旧审核绑定仍指向 A。页面提示「此发送记录属于原邮箱」，只有重新连接 A 才能核对或查看该次往来。B 可以发送尚未绑定的草稿。过期窗口里的操作不能改用 B 投递，B 的邮箱页也不会展示 A 的联系人和原文。

## 联测验收

| 场景 | 预期结果 |
| --- | --- |
| 断开邮箱，只点「通过」，再连接邮箱并重新打开审核页 | 草稿已通过、收件人选择已保留，期间发出 0 封；点「发送」才投递。 |
| 公司有两个通用邮箱，改选第二个、修改英文稿并展开中文对照，点「通过并发送」 | 仅第二个地址收到 1 封；主题和正文与页面刚确认的原文一致。 |
| 两个产品各向 Alice 成功发一封，Alice 的邮箱输入框已有另一个带附件草稿 | 两处「查看往来」进入同一联系人，各自定位正确消息；来源区分两个产品，原输入框草稿和附件仍在。 |
| 服务端明确拒收，改好地址后重试 | 显示「已通过 · 发送失败」，新地址没有空会话；手动重试成功后时间线出现一封。 |
| 提交后断线，重启并多次点击「检查已发送邮件」 | 核对不重发；找到可靠匹配后转为已发送，邮件头 ID 被改写时仍保留来源；缺少匹配则继续待确认。 |
| 双击、两个窗口同时发送，或本地只写完审核、只写完提交记录、只写完接受记录就退出 | 每次有效操作最多一次 SMTP 提交；恢复后分别呈现尚未发送、待确认、已发送，接受的消息只追加一次。 |
| 在审核页打开期间切换账号、重写草稿或切换到另一位收件人 | 旧页面不能用新账号或旧版本发信；异步结果落回原收件人。切回原账号可以核对原记录。 |
