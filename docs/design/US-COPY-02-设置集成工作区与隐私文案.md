### 1.3 运行状态（设置页 + 状态栏）

导航（设置侧栏与主侧栏）和状态栏弹出层标题，由「OpenCode 运行时」改为「运行状态」。对用户谈到这项服务时用「智能体服务」。

| 区域 / 位置 | 旧文案要点 | 最终文案（定稿） | 备注 |
|-------------|------------|------------------|------|
| 导航 / 弹出层标题 / 设置页标题 | OpenCode 运行时 | 运行状态 | `SettingsView`、`Sidebar`、`RuntimePopover` |
| 状态栏主文案 | OpenCode ready / idle / starting / running / error / stopped | 服务已就绪 / 服务空闲 / 服务启动中 / 服务运行中 / 服务异常 / 服务已停止 | `useAppStatus` 的 `runtimeLabel`。主芯片不再附加 `MCP n/m` |
| 健康徽章 | healthy / starting / error / stopped | 正常 / 启动中 / 异常 / 已停止 | |
| 空列表 | OpenCode 未就绪或 MCP 尚未连接 | 服务未就绪，请稍后或重启应用 | 设置页与弹出层同一句 |
| MCP 列表标题 | MCP 服务 | 收到「诊断信息」里，标题可用「服务连接」 | 主界面不出现 MCP |
| 停止确认 | 停止 OpenCode？当前有 Agent 任务正在运行… | 标题「停止智能体服务？」。正文「当前有任务正在运行，停止后任务会被中断。确定继续？」 | 停止行为不改 |
| 重连不可用 | 当前环境不支持 MCP 重连；OpenCode 未运行，无法重连 MCP | 暂不支持重新连接，请重启应用 | 渲染进程与主进程送到界面的句子都用这一句 |
| 地址与版本行 | baseUrl · 版本号 | 放进诊断信息 | 主界面不展示 |

弹出层里每项服务的中文说明（线索读写、Tavily 搜索、Places 地图、浏览器抓取）可以留在诊断信息中。主界面不列出内部服务名。

### 1.4 关于与隐私

| 区域 / 位置 | 旧文案要点 | 最终文案（定稿） | 备注 |
|-------------|------------|------------------|------|
| 关于页主视图 | 应用版本、架构 Electron + Vue3 + OpenCode SDK、用户偏好路径、OpenCode 模板路径 | 主视图只留「应用」和版本号，例如「FTCS Desktop {版本}」 | 架构、偏好路径、模板路径、更新清单 URL 放进诊断信息 |
| 页脚隐私句 | API Key 与模型偏好均写入本地 workspace/.env；opencode.json 由模板托管… | 见下方候选句 | **待开发核对实现** |
| 环境检测说明 | 用于检测 Node / OpenCode / Chrome…OfficeCLI…装完需重启 | 检查运行所需组件并引导完成设置 | 按钮「打开环境与配置引导」「打开业务引导」保留 |
| 隐私政策 | 无 | 产品已有隐私政策 URL 时，加「隐私政策」链接 | 没有 URL 就不编造，链接不出现 |

隐私候选句（**待开发核对实现**，对不上整句不写）：

> 你的 Key 和设置只保存在本机，不会上传。

核对至少这三件事：

1. 自定义通道的 Key、模型偏好是否只写在本机工作区，而没有单独的「上传设置」接口。
2. 官方通道登录、凭证开通会把登录信息交给官方账号服务。只要存在这类离开本机的数据，就不能写绝对的「不会上传」。
3. 更新检查、意见反馈、日志是否还会另传数据。

对不上时：删除候选句，改留空。可以改成中性句「设置保存在这台电脑上的工作区文件夹。」但这也要核对「设置」里没有会上传的内容；核对不过仍留空。两种情况下，有隐私政策链接就只放链接。

不要写「不保存在这台电脑上」。Places 官方 Key 的存放口径在 US-COPY-01 §1.4，不在本页重复。

## 2. 诊断信息（O4）

设置「运行状态」和「关于」各放一块默认折叠的「诊断信息」，带「复制」按钮。

区内可以保留技术名、路径、连接状态、原始错误，供排障。区外（导航、说明、按钮、确认框、Toast）不适用这个例外。

本故事不新增第二套运行时界面，只是把现有 MCP 列表、地址、架构和路径从主视图移进去。启停、重启、重连的调用不改。
