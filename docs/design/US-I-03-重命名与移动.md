## 1. 已确认选型

| 项 | 决定 |
|----|------|
| **Q1 改名 UI** | **行内输入**（VS Code 式），不是树顶 `mkdir-row`。F2 或右键「重命名」进入；回车确认、Esc 取消；失焦也确认 |
| **Q2 改名对象** | 文件夹、普通文件、网站书签均可。资料库根不可改名 |
| **Q3 书签改名** | 编辑展示名（frontmatter `title`）；文件改为 `{新名}.md`；URL 不变 |
| **Q4 非法字符** | 替换 `<>:"/\|?*` 与控制字符为 `_`；去掉首尾空白与尾部 `.` / 空格；拒绝 `.`、`..`、Windows 保留名（`CON` 等）。**不**把空格改成 `-` |
| **Q5 同名** | 目标处已有文件或文件夹 → 抛「已存在同名文件或文件夹」，不静默覆盖 |
| **Q6 拖动落点** | 与导入相同：夹 = 该夹；文件/书签行 = 其父夹；根 / 空白 = `''` |
| **Q7 非法移动** | 不能移出 `files/`；不能把夹移进自己或子孙；拖到原父夹 = 无操作成功 |
| **Q8 多选** | 只移动**被拖的那一行**，不跟勾选集合（I-06） |

## 2. 目标与非目标

### 2.1 目标

1. 焦点节点 F2 或右键可改名，中文与空格保留。  
2. 把文件、书签或文件夹拖到另一夹（或根）即移动。  
3. 改名 / 移动后，展开、勾选、焦点按旧路径前缀迁到新路径。  
4. 从资源管理器拖入仍走 I-04 导入，不被树内移动抢走。

### 2.2 非目标

| 不做 | 归属 |
|------|------|
| 一次拖动多个勾选项 | US-I-06 |
| 导入冲突仍加 `-2` / 合并目录 | 保持 I-04 |
| 树外剪切板「剪切/粘贴移动」 | 不做 |

### 3.2 行内改名

### 3.3 拖动

拖树行时 `dropEffect = move`，目标夹用现网 `is-drop-target` 高亮。外部 `Files` 拖入仍是复制导入。

## 4. 数据与 IPC

### 4.1 名称

共享 `sanitizeEntryName`（无 Electron）：

- `trim`，非法字符 → `_`，去掉尾部 `.` 与空格，最长 120。  
- 空、`.`、`..`、Windows 保留名 → 空字符串，调用方报「名称无效」或「请输入目录名」。  
- 新建目录、导入源名、书签默认文件名、重命名都走它（导入冲突仍用 `uniquePath`）。

### 4.2 `renameLibraryEntry(relativePath, newName)`

1. 根 `''` 拒绝。  
2. 规范化新名；书签保证 `.md` 后缀，并写回 `title`。  
3. 未变化则原样返回。  
4. 目标已存在则拒绝。  
5. `fs.renameSync`，返回新 `relativePath`（相对 `files/`）。

### 4.3 `moveLibraryEntry(relativePath, destDir)`

1. `destDir` 必须是沙箱内已有目录（或 `''`）。  
2. 新路径 = `destDir/basename`。  
3. 夹 → 自身或子孙 → 「不能移动到自身或子文件夹」。  
4. 已在该夹 → 成功无写入。  
5. 同名存在 → 拒绝。  
6. `fs.renameSync`。

### 4.4 返回

`LibraryMutationResult.createdPath` = 新相对路径。快照 `focusDir`：改名/移动后的文件夹用新夹路径，文件/书签用父夹。
