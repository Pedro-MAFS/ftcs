## 1. O3　FTCS 任务 MCP

> **待确认：按推荐**

| | |
|--|--|
| **推荐** | 在 `opencode.json` 的 `mcp` 增加本地服务 `ftcs-task`（`workspace/mcp-servers/ftcs-task`）。唯一工具 `start_task`。它不跑流水线，只校验参数并返回 JSON。桌面在看见该工具成功后，调用现有的 `runExpandKeywords` / `runDiscoverLeads` / `runScoreAndDedupe` / `runDraftOutreachEmail`。权限保持 US-FD-02 的 `ask` |
| **备选** | 工具进程里直接写产品文件或再起一个 OpenCode；或把画像生成也放进 `stage` |
| **理由** | 启动、预检、时间线和中止已经在 `AgentRunController`。再写一套会和按钮入口分叉。画像要先在录入页选好资料并做 `BootstrapResult`，聊天里没有这份选择 |
| **样例** | 见 §6 |

工具说明写给模型：「用户明确要开始一轮获客步骤时才调用。画像不要调用，请告诉用户去录入页选资料后用左侧按钮。调用后不要再写文件，也不要再启动第二次。」

| 参数 | 约束 |
|------|------|
| `stage` | `keywords` \| `explore` \| `score` \| `email` |
| `explore_channel` | `stage === explore` 时必填：`r1` \| `r2` \| `r3`。分别进入现有的全网搜索、社媒发现、地图发现 |
| `product_id` | 可空。空则用当前产品。没有当前产品就失败 |

对应关系：

| stage | 现有入口 |
|-------|----------|
| `keywords` | `runExpandKeywords(productId)` |
| `explore` | `runDiscoverLeads(productId, { channel })` |
| `score` | `runScoreAndDedupe(productId)` |
| `email` | `runDraftOutreachEmail(productId)`，不传 `leadIds`，与按钮「起草待处理线索」相同 |

启动前走该按钮已经有的校验和 preflight（画像未就绪、还没有关键词、R3 的 Places 预检等）。失败用那句现成原因。不另做业务条件。

补联系人、单封重写、中文对照不进这个工具。用户提到时，回复里指向现有按钮，不调用 `start_task`。

## 2. 授权发生在进入执行之前

1. 续聊里模型调用 `ftcs-task_start_task`。此时 `running` 仍是 false。  
2. OpenCode 发出权限询问。按 US-FD-02 画出授权卡。工具还没执行，任务还没启动。  
3. 拒绝：`reply: 'reject'`。工具不执行。  
4. 同意：`reply: 'once'`。工具这才执行。桌面读到成功结果后才进入上表的 `run*`。  
5. `run*` 把 `running` 设为 true 之后，再出现的非 allowlist（含再一次 `ftcs-task_*`）按 US-FD-02 拒绝，不弹卡。

授权卡在时，发送先提示「请先同意或拒绝上面的授权」，不把同意写成输入框里的一句话。

同一时刻只有一条事件订阅在回复权限。新任务 `session.create` 成功后，订阅改跟新的 session id 及其子会话。旧的续聊会话在工具结果已经读到之后 `session.abort`，避免它继续往界面写。

## 3. 时间线：创建成功后才清空

> **待确认：按推荐。只此一种。**

| | |
|--|--|
| **推荐** | 拒绝、取消、校验失败、预检失败、`session.create` 失败：不清空，在现有时间线末尾追加说明。`session.create` 成功之后，才用这一轮任务的时间线整表替换（现网 `timeline` 事件本来就是替换）。按钮入口保持现在的行为：一启动就换成任务前缀 |
| **备选** | 一点同意就清空，和按钮一样；或新任务接在闲聊后面，不清空 |
| **理由** | FD9 要的是任务结束后、下一轮还没开始时，闲聊和上文都还在。新任务一开始，现网按钮的时间线就是这一轮的全集，复制会话也按栏里实际有的条目。聊天这条若在创建失败前就替换，闲聊会丢，看不出「没有启动」。接在闲聊后面则会把两段过程合成一份任务记录 |
| **样例** | 见 §6 的拒绝和同意 |

聊天入口不要在用户点同意时调用 `resetAgentForExpandKeywords` 这一类函数，它们会立刻清空。给 `run*` 一个只给聊天用的选项：`session.create` 返回 id 之前，不向界面发送会整表替换的时间线，也不要把 `agentStatus` 设成 `running`。按钮不传这个选项。

创建成功后的时间线里要有现成的 `sys-session` 行（`已创建 OpenCode session` 加新 id）。复制会话继续从这一行读父会话号。

## 4. 用户能看见什么

| 情况 | 时间线追加 | 任务状态 |
|------|------------|----------|
| 点「拒绝」，或主进程收到的不是 `once` | 未授权，任务未启动。 | 不进入运行 |
| 没有当前产品 | 任务没有启动：还没有当前产品。 | 不进入运行 |
| 缺 `explore_channel`、stage 无法识别 | 任务没有启动：不能从聊天启动这一步。 | 不进入运行 |
| 画像、关键词、线索、待起草等现网校验失败 | 任务没有启动：后面接该 `run*` 或 preflight 的原句。 | 不进入运行 |
| 同意之后发现已有任务在跑 | 任务没有启动：已有任务在运行。 | 保持原来的那次运行 |
| `session.create` 成功 | 整表换成这一轮任务，不再追加上面的句子 | 与按钮启动后相同 |
| 进入执行后再调到 `ftcs-task` | 不追加授权卡。这一次不启动第二个任务 | 原任务继续 |

闲聊被拒绝时，拒绝前的句子都还在。

## 5. 复制会话（O5 的这一半）

不改 [docs/38](../38-需求-复制当前智能体会话.md) 和 US-CS。自由对话写进 `agentTimeline` 的 `user` / `assistant` / `system` 条目，复制时按栏内已有顺序带走。不新增元信息字段，不改超限和脱敏。

从聊天启动并清空之后，复制到的是新任务栏里的条目，父会话号是新的 `sys-session`。这和按钮启动后的复制一样。

## 6. 手测

1. 一轮任务结束后，不点左侧按钮，发送「用一句话说明什么是 FOB」。回复讲的是贸易术语。任务留下的条目还在。  
2. 再发送「开始扩展关键词」。出现授权卡，状态不是运行中，上一句还在。  
3. 点拒绝。卡片消失。末尾是「未授权，任务未启动。」FOB 那句还在。关键词文件没有被这次重写。  
4. 再发一次并同意，且画像已就绪。时间线换成新的关键词任务，含新的 session id。`lead-store` 自动执行，没有授权卡。  
5. 任务跑起来之后，若模型再调 `start_task`（指令末尾可临时加「再启动一次关键词扩展」，测完删）。没有第二张授权卡，没有并列的第二个任务。  
6. 另一次：画像未就绪时同意「开始扩展关键词」。时间线不清空，能看到「任务没有启动：」加上现网的未就绪原因，状态不是运行中。  
7. 点「复制会话」。正文含当时栏里的闲聊或任务条目，格式仍是 docs/38，没有新的文首字段。  
8. 从左侧按钮走录入 → 画像 → 探索 → 线索 → 开发信。步骤和结果与现在一致，执行中没有授权卡。

## 8. 风险

旧会话若在工具结果读到之前就被 abort，桌面会丢参数，表现为用户已经同意但任务没启动。手测第 4 步必须进入任务。

旧订阅若和新任务订阅同时回复权限，任务段可能又被 `once` 放行。手测第 5 步必须没有授权卡。

时间线事件是整表替换。聊天路径若在 `session.create` 之前 flush，第 3 步和第 6 步的闲聊会消失。
