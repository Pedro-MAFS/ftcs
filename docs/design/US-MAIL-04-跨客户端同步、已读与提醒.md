# US-MAIL-04 · 跨客户端同步、已读与提醒

0.6.4 · 详细设计 · 已评审

Alice 发来三封邮件。用户在手机上读了一封，下次同步后，FTCS 的邮箱标签和 Alice 旁边都应少一个未读。用户回到 FTCS，只看到屏幕上的第二封，FTCS 就只把第二封写回已读。第三封继续保持未读，即使三封都已加载进时间线。

## 用户能看到的变化

| 动作或场景 | 页面和邮箱的行为 |
| --- | --- |
| 手机或网页邮箱把旧邮件标为已读或未读 | FTCS 核对服务器标记后更新该封邮件、联系人计数和邮箱标签总数。远端改回未读同样生效。 |
| 用户在 FTCS 看到未读来信 | 本地立即扣减未读数，后台写回收件箱。断网时可以继续阅读，重连后补交。 |
| 当前会话收到新邮件 | 浏览最新消息时沿用现有跟随滚动，读到后标记已读。正在翻历史时保留位置，沿用「查看新消息」。 |
| 正在看其他联系人或其他页面 | 更新列表和标签计数，保留当前页面、滚动位置与草稿。 |
| FTCS 退出期间用手机回复 | 重开后从已保存的 UID 继续补收。手机发件进入对方联系人的时间线，沿用现有回复头匹配和已发送副本合并。 |
| FTCS 在后台收到来信 | 开启邮件通知时显示系统通知，点击打开对应会话。关闭邮箱标签仍可收信和通知。 |

本故事沿用 US-MAIL-03 的发信、引用及草稿语义。邮件上的已读表示托管邮箱一侧的阅读状态。

## 什么时候算「看到」

渲染进程观察时间线里的消息气泡，以时间线滚动容器作为 `IntersectionObserver` 的根。窗口在前台且有焦点、邮箱标签激活、当前联系人匹配、时间线可见时才开始计时。邮箱设置、放大写信框或其他覆盖时间线的面板打开时暂停。失焦、离开页面、切换账号或联系人时取消未完成的计时。

建议阈值为**气泡垂直方向至少露出 32 像素，连续 500 毫秒**；高度不足 32 像素的小气泡完整露出即可。这样很长的 HTML 邮件也能被读到。组件在挂载、重新激活、滚动、布局或焦点变化后重新检查，计时结束再校验目标和可见区域。自动选中联系人、读取一页历史、仅显示左栏摘要都不会单独触发已读。

一次连续可见期间只上报一次有效阅读。若手机把正在显示的邮件重新标为未读，页面更新计数，等用户离开并再次看到这封邮件才产生新的阅读操作。明确的通知跳转、从历史返回、窗口重新获得焦点都重新计算可见范围。

## 增量同步与已读写回

现有 `MailboxService` 启动时立即同步，完成一轮后约 60 秒再跑下一轮。「重新同步」复用同一个调度器。本次继续使用该机制。现有 `importFolder` 按 `last_scanned_uid` 导入新增邮件并读取首次 FLAGS；它会跳过已入库副本，因此旧邮件的标记核对需要独立执行，即使本轮没有新增 UID。

| 同一账号内的步骤 | 主进程动作 |
| --- | --- |
| 1. 获取新邮件 | 按现有收件箱、已发送文件夹游标读取新 UID。写完消息和副本后推进游标。已发送沿用 `Message-ID` / `X-FTCS-Send-ID` 的匹配规则。 |
| 2. 核对旧来信 | 仅请求收件箱已知副本的 UID 和 FLAGS。有可用的 CONDSTORE 和文件夹版本时，按上次 `flags_modseq` 请求变更。首次建立基线时核对所有已知副本。基线或增量全部成功后，提交本轮开始时捕获的 `highestModseq`，以便下轮仍可捕获本轮期间的变化。 |
| 3. 无增量标记能力或副本被移除 | 分批对已知 UID 做普通 FLAGS 查询。建议每批 200 个，每轮优先核对待写回副本，再轮转覆盖所有已知 UID。有 CONDSTORE 的账号也保留轮转核对，因为只读取标记变化不足以发现移除。普通查询完整成功且缺少某 UID 时，追加 `present=false` 并移出未读统计。超时、部分结果、增量查询未返回某 UID 均不据此判定移除。 |
| 4. 写回本地阅读 | 有待办时以可写方式打开同一收件箱，再核验 UIDVALIDITY。对仍存在且未读的目标，用 UID 模式的 `messageFlagsAdd` 只增加 `\Seen`，保留星标等其他标记。若已为目标值，直接确认。发送成功后读取目标 FLAGS 再确认，无需重新下载 MIME 或附件。 |

本地阅读触发一次尽快执行的写回。若已有同步运行，则合并唤醒请求，在本轮处理或结束后立即处理一次。所有 IMAP 操作由同一账号的服务串行调度。分批查询结束后再发下一条命令，避免在 ImapFlow 的异步 fetch 迭代器内嵌套命令。文件夹只读或服务端明确禁止修改时，取消受影响的待办、恢复服务器值，并在邮箱同步状态说明原因；网络中断保留待办，按既有轮询重试。

## 状态归属与恢复

路径以 `data/mail/accounts/<account_id>/` 为根。沿用现有副本日志，旧工作区打开时即可重建索引。[工作区邮箱数据模型设计](工作区邮箱数据模型设计.md)

| 位置 | 写入与读取 |
| --- | --- |
| `copies/<folder_id>.jsonl` | 按 `folder_id + uid_validity + uid` 找副本。读到邮件时先追加完整新版本，`pending_seen=true`、`rev+1`。远端核对更新 `seen`；确认写回后清除 `pending_seen`。每次提交从最新版本合并，旧网络结果不能清掉后来产生的待办。无变化不追加。 |
| `sync/inbox.json` | 延用新增邮件游标；另存可选 `flags_modseq`（十进制字符串）和按 UID 轮转核对的位置。旧文件缺少字段即建立基线。UIDVALIDITY 改变后重建映射、重置两类进度；旧有效期的待办不得用于相同数字的新 UID。 |
| `account.json` | 建议增加可选 `new_mail_notifications`，缺省按开启处理。在邮箱设置提供「桌面新邮件通知」开关；按工作区和托管账号分别保存，改动立即生效。 |

显示值取 `pending_seen ?? seen`。同一逻辑来信只计一次，只要当前收件箱仍有一个有效、存在的未读副本，就计为未读。阅读该来信将对应有效副本一并设为待写回。使用同一份未读集合生成消息的 `unread`、联系人未读数和标签总数。副本变化时更新受影响联系人的 `revision`，通过现有 `mailbox:changed` 合并刷新。纯标记变化保留当前页锚点。

有本地待办时，本地阅读意图优先，确认后继续跟随服务器。写回成功但回执丢失时，下轮先读取标记，已读即可完成待办。主进程在每次异步操作后验证工作区、账号及连接代次；断开托管或切换账号后，旧请求、计时器和通知点击均失效。

## 桌面通知和点击定位

通知由主进程在新来信及副本成功落盘后产生。候选必须是**首次入库、尚未读的收件箱来信**。判断依据为导入结果和 UID 边界，未读数的增减仅用于渲染。首次回填、UIDVALIDITY 重建、重复同步、已发送副本、旧邮件被重新标为未读均静默。每次启动或重连，建议将首次打开收件箱时已有的积压邮件静默补齐，超过该次上界的新来信正常提醒。

窗口最小化、隐藏或失焦时允许桌面通知；窗口在前台时只更新界面。同一轮、同一联系人多封新信合成一条，显示发件人及封数，点击定位该批最新一封。发通知前复核开关和未读状态。通知在持久化后尽力投递；进程中断后不为历史记录补弹，系统禁用通知也不影响同步。

点击时复用桌面现有的主窗口恢复与聚焦逻辑，并激活或重新打开「邮箱」标签。导航目标携带工作区、账号、连接代次、联系人 ID 和消息 ID；根视图接收目标，等邮箱页就绪后沿用按消息定位的时间线查询。切换联系人前先保存当前草稿。若目标消息已不可定位，打开仍存在的对应会话；切换到其他账号后点击旧通知，不跳转也不标已读。点击本身不直接写回，仍走可见性判定。

## 接口与交付顺序

1. **主进程副本同步。** 扩展 `ImportIndex` 的副本读写、消息到副本的反查、未读投影和日志重放；在 `MailboxService` 接入 FLAGS 核对、待办写回和账号切换取消。新增消息游标、发送日志和附件路径沿用现有实现。
2. **页面已读联动。** `MessageView` 增加 `unread`。新增 `mailbox.markRead(ctx, account, contact, messageIds)`，渲染端合并上报，主进程验证调用来源、会话归属和来信方向，只受理有效副本。返回表示本地待办已持久化；失败保留未读并允许重试。邮箱页、联系人列表和主标签栏订阅现有刷新事件。
3. **通知与导航。** 在邮箱设置新增开关，通过现有 `mailbox.act` 保存；主进程从本轮导入结果生成通知，点击时发送定向打开邮箱会话的事件。设置关闭或账号断开时清理该账号仍可关闭的通知与待导航目标。

## 验收

| 场景 | 可观察结果 |
| --- | --- |
| 手机读一封旧邮件，再改回未读 | 无新增 UID 时，FTCS 也能先减少、再恢复未读数；联系人与邮箱标签一致。覆盖有、无 CONDSTORE 两条路径。 |
| 三封未读，只有一封在视口 | 稳定显示后只扣一封；快速划过、后台标签、最小化、放大撰写时不扣。长邮件无须整封进入视口。 |
| 离线阅读，重启后联网 | 本地未读数保持已扣，联网后网页邮箱显示已读。模拟写回已成功但回执丢失，可正常收敛。 |
| 旧副本移除、UIDVALIDITY 改变或切换 A → B | 历史消息保留，旧副本退出计数。A 的写回不会标记 B 或新有效期下同 UID 的邮件。 |
| FTCS 关闭期间在手机回复 Alice | 重启后已发送副本出现一次，能匹配的回复可跳转到原件；重复同步和重启均不新建第二条。 |
| 首次导入 30 天历史，后台随后收到两封 Alice 来信 | 历史只更新计数；新信产生一条通知。点击恢复窗口并打开 Alice 会话。关闭提醒后仍正常收信。 |
| 正在其他页面工作或在 Bob 会话写草稿 | 前台收到 Alice 来信仅更新计数；主动点击后台通知后才切换，返回 Bob 时草稿仍在。 |

自动化用可控 IMAP 响应覆盖游标、部分失败、重复投递和账号切换；用 Electron 窗口覆盖可见性、滚动和导航。实机联测用同一测试账号的手机或网页邮箱核对 `\Seen` 双向变化，并在系统通知可用的桌面验证最小化、点击恢复和关闭提醒。
