# US-SITE-02：智能体编写和修改独立站

状态：设计已确认，已完成实现，待 Windows 和 macOS 实机联测。基于[需求拆分](../独立站-需求拆分与交付顺序.md)、[站点权限与运行验证](../TV-SITE-01-站点开发权限与本地运行技术验证.md)、[站点创建](./US-SITE-01-创建和恢复全局站点.md)及现有本地预览、构建和发布能力。

## 1. 目标与范围

用户通过自然语言要求智能体创建或修改当前工作区的站点，例如“把首页改成工业设备企业风格”“增加产品详情页”或“调整手机端导航”。智能体理解已有项目，按用户意图编辑，用户在 FTCS 预览、检查并主动发布。

采用一个**说明型 Skill**：它提供建站约定、已有工具的使用方法和交付要求，不为每次修改规定统一的步骤或固定产物。具体如何拆解工作、读取哪些文件和使用哪些组件由模型结合项目与用户要求决定。默认模板是 Vue Router + vite-ssg，但该 Skill 不把用户项目限制在 Vue 或单页架构。

本次覆盖 US-SITE-02：自由聊天中的站点开发、说明型 Skill、必要的文件和命令权限、执行与结果展示。本次不实现 US-SITE-03 的画像/资料库选择器和素材复制工作流，也不实现自有域名、站内询盘接收或自动发布。已经有的预览、构建、发布入口继续复用。

## 2. 用户体验

### 2.1 在当前聊天中描述需求

1. 用户在右侧智能体自由聊天中说出建站需求，例如“把独立站首页改成蓝白色，介绍我们的工业泵”。对话继续使用当前会话，不因识别出站点需求而新建会话。
2. 模型根据用户意图路由并加载建站 Skill；不能以关键词、聊天标题或固定提问模板来判断用户要改什么。用户信息不足以完成关键内容时，模型可在当前会话提问；页面文案不应凭空捏造产品参数、认证或联系方式。
3. 智能体先读取项目现状，再决定修改哪些站点文件。页面保持交互；用户可继续查看已有本地预览。已有用户内容、配置和 GitHub/Cloudflare 关联需要保留，除非用户明确要求修改。
4. 模型在会话中说明做了什么、涉及哪些文件及尚需用户补充的内容。模型无法执行的检查要如实说明；不能因为代码写入完成就声称构建通过、网站已发布或线上已经更新。
5. 用户通过独立站页面现有入口安装依赖、启动/打开预览、执行构建检查和发起发布；发布仍走现有源码快照与用户确认流程。

站点不存在、目录不可用或当前工作区变化时，不自动重建或接管已有目录；页面提示用户先使用已有的创建/恢复入口，再继续对话。用户已处于其他页面时，可以在聊天中收到提示并前往独立站页面。

### 2.2 站点页面辅助入口

建议独立站页面增加“让智能体修改”入口：打开或聚焦右侧现有聊天，并给出可编辑的示例提示，让用户输入具体要求。点击本身不发送修改指令、不创建会话、不启动预览或发布。用户也可以直接在自由聊天中提出同样的需求。

该入口是易发现的快捷方式，不是产品与站点的绑定；切换产品不切换站点。若技术验证发现当前版本无法可靠识别建站 Skill 的调用上下文，使用下文“建站编辑上下文”作为权限兜底，不改变由模型路由 Skill 的原则。

## 3. 说明型 Skill

### 3.1 位置和触发

新增 `workspace/skills/build-website/SKILL.md`（名称可在实现前调整），frontmatter 的 `description` 清楚描述创建、修改、排查当前独立站的意图，供模型自行选择。支持用户提出具体页面、交互、SEO、响应式或代码修改需求；普通产品画像、获客和邮件任务不应因为提到“网站”就被转入建站。

它是项目开发的指导文档，不是固定业务流水线。Skill 内容分为“项目契约、工具和边界、站点实现建议、交付汇报”，用约定指导模型，而不要求固定执行“读取→修改→构建”等步骤。模型根据已有内容和用户要求行动。

### 3.2 建议写入的约定

- **站点范围**：唯一站点根目录是当前工作区 `website/`；先了解现有项目和 `package.json`，不因框架、路由结构或用户内容与模板不同就整体重建。
- **项目契约**：保留可运行的 `npm run dev`、`npm run build`，遵循页面中配置的静态构建产物目录。可有多个页面或产品详情页；已有依赖与框架按项目实际情况使用。
- **代码与体验**：优先延续现有设计和项目惯例；按需求处理响应式、可访问性、页面标题/描述及静态渲染。模板已有 `robots.txt`、sitemap、`llms.txt` 等时按站点内容维护；不要保证搜索引擎一定收录。
- **资料与资源**：未经确认不杜撰业务事实。需要公开的图片、文本和其他资源应是用户允许使用的内容，最终放到 `website/` 内；代码和构建不能直接引用工作区其他目录。资料选择、受控复制及来源记录由 US-SITE-03 实现；US-SITE-02 不假设已经存在跨目录复制工具。
- **工具**：根据本次会话真实提供的读文件、搜索、编辑和授权命令工具工作；不能因为 Skill 提及某个工具就假设它已配置或已获授权。现有预览、依赖安装和构建以桌面独立站页面入口为准；如果没有可调用的智能体工具，就指引用户使用页面，不虚构工具调用。后续如增加专门工具，需列出真实名称、参数和权限。
- **交付**：说明主要变更、用户需要补充的真实信息、实际检查结果和下一步；不要暴露或打印凭据。不要自动推送到 GitHub、创建 Cloudflare 部署或声称已经上线。

### 3.3 与现有业务 Skill 的关系

`workspace/AGENTS.md` 当前要求每个业务 Skill 在查询外部服务、复制或写入业务数据前调用 `lead-store.task_begin/task_done`。本 Skill 是指导开放式自由聊天的说明型 Skill，不创建既有的画像/获客业务任务，也不为每次文件修改伪造固定任务类型或新会话。实现时同步调整 AGENTS 中这条约定：既有业务 Skill 的生命周期保持不变，明确说明型建站 Skill 的适用边界；如果对话里确实触发其他业务 Skill，该业务 Skill 仍按自己的协议执行。

右侧会话的正在回复、询问、取消和错误使用现有会话状态；不能把“加载了 Skill”当成文件修改开始，也不能把回答结束当成构建或发布成功。将来如果需要可恢复的独立建站任务和跨区域任务卡，再另行设计正式 `task_begin/task_done` 类型，不把说明型 Skill 隐式当作固定流程。

## 4. 权限与执行边界

### 4.1 当前状况

设计前，仓库的 `workspace/config/opencode/opencode.json` 将 `edit`、`bash` 和 `external_directory` 设为 `deny`；桌面端 `permission-gate.ts` 的硬边界也会拒绝 `edit`、`bash`、`shell` 和 `external_directory`，运行中的自动任务会拒绝权限询问。Skill 单独加载不能编辑站点或发起 Bash 确认，因此需要下述权限接入。

本设计沿用 TV-SITE-01 已确认方向：文件操作以站点目录为边界；自由聊天的 Bash 逐次询问；自动任务中的 Bash 自动拒绝。规则由 OpenCode 配置与桌面端共同执行，Skill 和 `AGENTS.md` 只说明规则，不能取代代码检查。

### 4.2 建站编辑上下文

直接在全局配置中无条件放开 `website/**` 会让其他任务也获得写入能力，不符合原有任务边界。目标是只在当前工作区、当前会话的**建站编辑上下文**中允许站点编辑：

- 模型仍负责决定是否加载 `build-website` Skill，程序不做关键词路由。主进程需要基于可信、可关联会话的实际 Skill 工具调用或明确的页面入口建立建站上下文，记录工作区根、站点根、session ID 和有效期；不接受模型输出文字、聊天标题或前端传来的任意路径作为授权依据。
- **实现验证**：依据当前 OpenCode 的工具事件和权限字段接入 Skill、会话和工具调用的关联，并覆盖缺失字段时拒绝的自动测试；不同平台的真实运行仍需联测。新版[OpenCode 权限文档](https://opencode.ai/docs/permissions/)和[服务端文档](https://opencode.ai/docs/build/plugins/server)描述了资源及会话规则，但本项目使用的版本、事件结构和语义必须以实际运行验证，不能直接假设相同。
- 若当前版本不能可靠地将自由聊天中的 Skill 加载与会话授权关联，则以独立站页面的“让智能体修改”入口建立明确的建站上下文；自由聊天直接发起时提示用户先从该入口启用，再在**原会话**继续。不能为了实现无感入口而放宽其他会话的写入权限。最终优先采用哪条路径，以实际验证结果为准。
- 上下文仅供当前会话和工作区使用；新建/切换会话、切换工作区、结束建站上下文、应用重启或站点失效时撤销。运行中的自动业务任务不会继承该上下文；并行会话、子代理是否继承必须显式设计并默认不继承。上下文变更时清理等待中的权限请求。

### 4.3 文件工具

| 操作 | 建站编辑上下文中的策略 |
| --- | --- |
| 读取站点文件 | 使用现有读、搜索工具；不读取或展示无关凭据。 |
| `website/` 内新增或编辑普通文件 | 针对实际文件工具和每个目标路径核验后允许；不需要模型每次申请。 |
| `website/` 外的直接写入 | 继续拒绝，业务数据仍只能经原有受控 MCP 路径写入。 |
| 同一次操作包含多个目标 | 所有目标均须通过；存在站点外、未知或无法验证的目标时整个操作拒绝。 |
| 符号链接、junction、路径遍历、尚不存在的目标 | 规范化路径，检查根目录、现存祖先和真实路径；对不能证明留在站点内的目标拒绝。尤其在 Windows 检查盘符、大小写、UNC 和 junction。 |

需要同时覆盖实际提供的 `edit`、`write`、`patch` 等写入方式；批量补丁、删除/重命名如果工具支持，也要检查每个源和目标。文件系统链接与并发替换存在竞争，路径检查只能约束应用能验证的工具调用，不能宣称它是操作系统级沙箱。若当前事件缺少完整路径或出现未覆盖的写入工具，保持拒绝并给模型可理解的结果；不得用一次宽泛授权作为回退。

实现前需验证权限在哪一层执行：如果 `allow` 使请求根本不经过桌面端权限门，仅靠该门无法核验路径；需要使用当前 OpenCode 可验证的按资源规则或受控文件工具，确保**每次实际写入之前**执行边界判断。不得只在 Skill 加载后修改提示词或只在执行完成后检查。

### 4.4 Bash / shell 与桌面命令

- **自由聊天**：建站上下文中，只有能可靠取得并验证工作目录位于 `website/` 的 Bash/shell 请求才进入逐次询问；界面展示具体命令和工作目录，用户选择本次允许或拒绝。目标目录未知、会话不匹配、站点外或无法完整呈现命令时拒绝。用户拒绝后模型不能绕过决定重试同一操作。
- **自动业务任务**：Bash/shell 请求一律自动拒绝，不显示需要用户回答的权限卡，不因激活建站上下文而改变现有自动任务行为。
- 主进程现有权限事件只保留权限名和工具标识；实现时要核对并保留当前 OpenCode 实际返回的工作目录、命令、session ID 和权限请求 ID。事件字段缺失、组合命令无法展示或请求过期时失败关闭；不从模型自然语言猜参数。
- 用户允许的是一次具体命令。即使工作目录在 `website/`，命令、脚本、依赖和子进程仍可能访问工作区其他目录、网络及用户账户资源；工作目录检查不能证明命令的全部操作范围。界面应在确认中说明这一点，不承诺隔离。
- 页面现有的安装、预览和构建通过桌面端使用 FTCS 配置的 Node/npm 执行，不是模型 Bash 的自动放行。是否新增可让智能体调用的受控桌面工具，需要明确接口、用户触发和进程状态后单独实现；首期不假设已存在。

## 5. 页面状态和刷新

| 区域 | 建站期间与结束后 |
| --- | --- |
| 右侧智能体 | 使用当前自由聊天的状态、消息和权限询问卡；可显示实际编辑工具调用。用户询问、允许/拒绝和取消都留在原会话。 |
| 主区域独立站 | 沿用站点存在、预览、构建、发布和云端部署的各自状态。建站上下文及会话忙碌可显示“智能体正在处理站点请求”，但不能据此判定写入或构建成功。 |
| 左侧产品信息 | 站点不绑定产品；单纯修改站点不切换产品、不刷新或更改产品画像及线索数据。 |

### 5.1 源码变化与 FTCS 页面刷新

本次在桌面主进程监听当前工作区 `website/` 的文件变化。可使用 Node 的 `fs.watch` 或经过验证的文件监听库；监听对智能体和外部编辑器的写入一视同仁。流程如下：

1. 工作区站点就绪后建立监听，监听到变化时做短暂防抖，合并同一次操作产生的连续事件。
2. 通知只是“可能发生了变化”的线索。主进程按与发布源码快照相同的文件范围和摘要规则，重新检查站点文件，与最近一次已确认推送的源码摘要比较；排除 `node_modules/`、当前构建产物目录及发布规则排除的文件。检查时不依赖事件一定提供文件名。
3. 检查结果按工作区和序号发给页面：一致显示“本地与上次推送一致”，不一致显示“本地有未发布修改”，失败或没有可用基线显示准确原因，不猜测结果。首次没有发布基线时显示“尚未发布”。这里比较的是本地与上次推送的源码；线上是否已更新仍由 Cloudflare 部署状态单独决定。
4. 构建检查记录应关联检查时的源码摘要。源码改变后，旧构建结果保留为历史结果，但显示“源码已变化，需重新检查”，不得将其描述为当前源码构建通过。若构建期间源码发生变化、摘要不可获得或构建前后不能确认一致，显示“当前源码构建状态待确认”。不自动重跑构建。
5. 站点页面打开、用户手动刷新及窗口恢复时主动重新核对，弥补监听可能漏事件；站点目录重建、工作区切换或应用退出时关闭旧监听并按需重新建立。监听失败时显示状态未知并允许手动重试。异步检查完成前再次核对工作区与序号，防止旧结果覆盖新状态。

监听可能因系统、目录移动、网络文件系统或文件被替换而丢失事件；实现时处理错误和资源释放，不能用监听作为安全边界。变更检查不读取或上传文件内容到云端，也不把文件事件当作智能体任务完成信号。

### 5.2 本地预览内容

预览中的网站内容由站点的开发服务负责更新。默认 Vite 模板在开发服务正常运行时通常支持热更新；其他 Node 项目可能需要用户手动刷新预览页或重启服务。FTCS 的源码状态更新不等于预览内容一定已经刷新，也不自动重启用户的服务。生产网站只有在用户再次发布且 Cloudflare 部署成功后才更新。

设计中不能把后台任意 `message.part.updated` 或监听到的文件变化当作正式业务任务的 `task_done`；也不因技能结束自动执行 `npm install`、`npm run build` 或云端发布。用户编辑源文件、智能体写入、外部编辑器修改和构建中间产物均不能被简单等同；变更范围应与现有发布快照排除规则一致，并标明检查失败或未知状态。

## 6. 异常与恢复

- **站点不存在或损坏**：停止文件写入，给出页面恢复入口；不覆盖非空目录。
- **工具权限无法验证**：拒绝该次工具调用并在会话说明，不把宽泛的询问批准转换成无限期授权。
- **用户拒绝命令**：不执行，不改用其他命令或工具绕过；可继续完成不依赖该命令的修改，并如实说明。
- **自动任务发起 Bash**：立即返回拒绝结果；任务按自身生命周期继续或以实际结果结束，不等待用户。
- **会话/工作区发生变化**：撤销旧授权，清理旧会话待处理询问；新的会话不继承旧工作区权限。
- **模型中断或页面关闭**：保留已经写入的用户文件，不自动回滚；恢复后以磁盘真实状态为准，告知用户检查预览与构建。无需为了证明任务已结束而猜测写盘。
- **项目修改破坏契约、依赖缺失或构建失败**：展示实际错误；用户可让智能体继续修改，或使用桌面入口安装、预览和构建。用户未要求时不自动删除依赖、锁文件、站点或云端资源。

5. 修改 `workspace/skills/`、`workspace/config/` 或 `workspace/AGENTS.md` 时，同次更新 `WORKSPACE_TEMPLATE_VERSION`；若实现中修改工作区 MCP，还须重新构建对应 `dist/mcp.js`。同步生效需要重启桌面端。

真实事件格式与 OpenCode 版本兼容性是**实现验收项**。如果无法在写入前证明所有目标属于站点，需保持拒绝并调整技术方案，而不是宣称已支持受限直写。

## 8. 验收场景

1. 同一自由聊天中，自然语言修改首页、增加一个路由及调整响应式；模型按意图加载说明型 Skill，保留原项目框架，用户能在本地预览看到变化。无需新建会话或填固定业务参数。
2. 站点不存在、工作区切换、会话新建、应用重启和用户取消：不会误写旧目录，权限不串会话；已有项目和云端关联不被重置。
3. 站点内新建/修改文件可用；站点外绝对路径、`..`、混合多文件 patch、符号链接/junction、缺失祖先及未知路径都不能越界。普通获客等自动任务和其他会话保持原规则。
4. 自由聊天 Bash 只在能够确认站点工作目录时逐次询问；确认卡准确显示命令和目录，拒绝、取消和失效请求不执行。自动业务任务中 Bash 被直接拒绝，没有等待授权；未获授权的替代命令同样不能绕过。
5. 分别验证当前支持的 OpenCode 工具/事件格式、Windows 中文和空格路径、macOS 路径、子会话及配置合并。无法取得必要参数时拒绝，并展示原因。
6. 已有模板和另一种符合 `dev`/`build` 契约的纯前端 Node 项目均可继续修改；不能强制改成 Vue 或重建项目。真实资料不应凭空补全，工作区外资源不被直接引用。
7. 模型只修改文件时，不能把站点显示为已构建或已发布；用户修改后预览、构建和再次发布，状态与实际快照和 Cloudflare 版本一致。构建失败、网络断开、权限拒绝都能得到准确提示。
8. 验证旧的画像、探索、邮件业务 Skill 仍使用各自 `task_begin/task_done` 和既有自动任务权限，不因新增说明型 Skill 改变行为。
9. 智能体和外部编辑器分别修改站点源码时，独立站页面自动更新本地状态并使旧构建结果过期；依赖目录和构建产物变化不误报。模拟监听漏事件、目录重建和工作区切换，验证主动刷新可恢复且旧检查结果不会覆盖新工作区。默认 Vite 预览验证热更新，其他项目不假定均支持热更新。
