# US-MAIL-02 · 联系人列表与会话时间线

0.6.4 详细设计稿，待评审。用户已反馈 US-MAIL-01 联测通过。本故事使用已导入的本机邮件，让用户打开邮箱就能找到一个人，看清双方最近一次谈了什么，并向上翻阅更早的往来。[需求与界面稿](../43-需求-工作区邮箱与即时通讯式会话.md) · [数据模型](工作区邮箱数据模型设计.md)

## 1. 打开邮箱

保留未连接时的连接表单。已连接时，主区域使用设计稿中的左右两栏。当前账号和「邮箱设置」入口常驻；重新验证、取消托管、补选已发送文件夹及同步重试仍然可达。同步失败只在页内提示，已落盘邮件继续可读。[现有邮箱页](../../desktop/src/views/MailboxView.vue)

| 用户动作 | 左栏 · 最近会话 | 右栏 · 当前联系人 |
| --- | --- | --- |
| 首次打开已连接邮箱 | 按最近一封邮件的时间倒序展示。每行显示姓名、地址、最近消息摘要、时间及未读数。无姓名时以地址为标题；有公司资料时在联系人详情展示。 | 默认选中最近会话并定位到最新消息。空邮箱显示「还没有邮件往来」和「新会话」入口。 |
| 从 Alice 切到 Bob | 选中态随之切换；同名时按邮箱区分。 | 清空 Alice 的详情和分页状态，显示 Bob 的最近一页。标题展示姓名和邮箱，已有公司信息一并显示。 |
| 切换产品、切回邮箱 | 保持账号及原选中联系人。 | 保持阅读位置；账号或工作区变化时清空旧会话、缓存和未完成的页面请求。 |
| 新邮件导入 | 更新时间、摘要、未读数及顺序；当前选中联系人保持不动。 | 正在底部阅读该联系人时追加消息并跟随到底部；向上翻历史时保持阅读位置，提供「查看新消息」。其他联系人的来信只更新左栏。 |

摘要采用正文首段可读文字，折叠换行；无文字时依次回退到附件名、主题或「无正文」。自己发出的消息在摘要前显示「我」。有多条邮件时按实际邮件时间排序，补导上个月的邮件不会误把会话顶到今天。

## 2. 一封邮件属于哪个联系人

会话键为当前工作区内的 `(account_id, contact_id)`。使用消息已保存的 `conversation_contact_ids` 建立时间线。关系来自实际往来，无需用户已有线索、公司或产品记录。

| 邮件 | 左右栏的结果 |
| --- | --- |
| Alice 发给我，抄送 Bob | 只在 Alice 的会话出现一次；展开详情能看到发件人 Alice、收件人和抄送人 Bob。Bob 不因仅被这封来信抄送而新增一条会话。 |
| 我从手机发给 Alice 和 Bob，已发送副本同步回来 | 沿用导入时保存的联系人关系。两个会话都可以显示同一个本地消息 ID，正文保存一份。 |
| 同公司两人、同一地址涉及不同产品、陌生地址首次来信 | 前者分别展示。相同地址的往来合在一条时间线；陌生发件人首次直接来信后即可看到。 |
| 同一逻辑邮件有多个服务器副本 | 每段时间线只展示一次。只计入方向为来信、当前收件箱有效副本中仍有未读的消息；同一消息最多计一次。取每个副本最新版本，有待写回标记时优先使用。 |

US-MAIL-02 展示本机已知的未读状态。默认选中联系人、预加载历史、展开收件详情都不会直接调用 IMAP 修改标记。US-MAIL-04 接入“用户实际看到来信”及跨设备的已读更新；呈现和统计继续共用同一套副本状态。

## 3. 阅读时间线和发起新会话

- 时间线左侧显示对方来信，右侧显示本方发信。每条展示本地时间、主题、正文和附件名称，跨天加日期分隔。展开「收件详情」显示实际地址，只呈现本账号可见的信息。长正文可展开；优先显示纯文本，只有 HTML 的邮件提取可读文本，保留段落。列表及阅读区均不执行邮件脚本，也不自动加载远程图片。
- 默认加载最近 30 条，从早到晚排列。向上加载时将上一页插到顶部，以原先第一条可见消息为滚动锚点。翻到最早后结束加载。这里的 30 是每页条数，与首次导入的天数独立。
- 点「新会话」后在页内输入收件邮箱，确认前校验地址。用连接账号相同的地址归一化规则匹配，已有联系人直接定位；新地址打开临时会话，标题显示完整地址。取消或仅打开临时会话都不会产生空联系人。地址输入和定位在本故事交付，US-MAIL-03 接上写信、草稿及发送；首封成功后转为正式列表项，明确失败或结果未知时保留撰写上下文。
- 邮件已记录的附件先显示名称与大小；用户保存附件、引用原文进行回复、发送和草稿标识分别接入 US-MAIL-03。设计稿中的「回复全部」随撰写能力一起交付。

## 4. 从已有 JSONL 读取

当前 `ImportIndex` 保存地址与联系人 ID 的映射、导入去重键和消息数。页面收到的 `Snapshot.contacts` 只有地址，无法据此分页展示邮件。扩展主进程现有的账号级内存索引，复用启动扫描和每次导入成功的写入路径。现有月份分片、联系人文件、服务器副本文件均可原样读取。[导入实现](../../desktop/electron/mailbox/import.ts) · [当前 IPC 类型](../../desktop/electron/mailbox/types.ts)

| 来源 | 查询所需的内存数据 |
| --- | --- |
| contacts.jsonl | 以 contact_id 取最新版本的地址、姓名和可选公司，以 address_key 查找联系人。先写联系人后崩溃产生的孤立记录，在有可展示的消息前不加入最近会话。 |
| messages/*.jsonl | 每条消息解析一次，保留 ID、方向、时间、短摘要、关联联系人及正文所在的分片、UTF-8 字节偏移、字节长度。每个联系人保存按时间排序的消息引用。正文和附件字节不常驻内存。 |
| copies/*.jsonl 与 sync/inbox.json | 根据当前收件文件夹及 UID 有效期，取仍存在的副本最新标记，并按逻辑消息归并未读数。已发送副本的已读状态不参与统计。 |

打开账号时按已有 JSONL 行扫描建立索引，异步分批让出主进程事件循环；索引准备期间显示「正在读取本地往来」。启动扫描与新批次提交按账号协调，已持久化的增量进入同一索引，重放同一 message_id 不会重复计数。页内切联系人复用索引。读正文时按位置读取当页记录并核对 ID；文件缺失或位置失效时重建对应索引并重试一次，再失败则保留列表并提示重新读取。

排序键使用 `(occurred_at, message_id)`，日期相同仍有稳定顺序。查询上一页只取严格早于最旧键的记录，不按月份文件名或数组下标翻页。导入期间，变更事件到达后刷新当前已加载的时间区间并按 ID 合并，使迟到的历史邮件能插入正确位置。底部新邮件和顶部翻页均以可见消息 ID 维持位置。

## 5. 页面与主进程契约（拟定）

所有查询由主进程验证 `Context.root`、`generation` 与活动 account_id，并校验 contact_id 属于该账号。渲染层只传业务 ID 和分页游标。文件路径、偏移和附件物理位置保留在主进程。

| 调用 | 参数 | 返回及用途 |
| --- | --- | --- |
| listConversations | context、accountId | 返回联系人摘要数组：contactId、email、displayName、company、lastMessageId、lastAt、preview、unreadCount。供左栏及地址定位使用。 |
| getTimeline | context、accountId、contactId、可选 before 游标 | 返回 MessageView 数组、nextBefore、hasMore。MessageView 包含消息 ID、方向、时间、主题、可读正文、地址详情及附件摘要。默认 30 条。 |
| mailbox.changed | 复用已有订阅 | 页面合并同批刷新。左栏更新排序；右栏仅在当前会话变化或重新激活时更新已加载范围，可分多页读至原锚点。US-MAIL-01 的连接快照继续服务于设置和同步提示。 |

切换联系人后，按「账号上下文 + 联系人 + 页面请求序号」接收响应，丢弃迟到结果。账号断开时立即清空两个栏位。离线、同步暂停时允许查询本地数据。当前账号的索引仍在准备、会话确实为空、查询失败分别展示加载态、空态及可重试的错误态。

## 6. 验收与实现顺序

| 场景 | 验收结果 |
| --- | --- |
| 用 US-MAIL-01 已联测的工作区离线打开邮箱 | 无需重新导入。联系人有可辨认的地址和最近摘要，选择后能阅读本机双向往来。 |
| Alice 来信抄送 Bob；随后同公司的 Bob 单独来信 | 左栏出现两个独立地址，Alice 的第一封只显示在 Alice 会话。展开能看到 Bob 的抄送地址。 |
| 同一联系人有跨月份的 65 封邮件，部分时间戳相同 | 首次显示最近 30 条，向上再加载 30 条、5 条；全程顺序稳定，无重复或漏项。中文正文、仅 HTML 和仅附件的邮件均有可读呈现。 |
| 阅读历史时导入新信、快速在 Alice 与 Bob 间切换 | 列表更新且保留当前会话；滚动位置稳定，迟到的 Bob 响应不会出现在 Alice 的时间线上。 |
| 同一来信存在多份映射，另有本方已发送邮件 | 消息与未读数按逻辑邮件去重；本方发件不会增加未读数。 |
| 选择「新会话」分别输入已有地址、新地址和无效地址 | 分别定位已有会话、进入临时会话、就地提示修正。与 US-MAIL-03 联测首发成功、失败及草稿恢复。 |
| A、B 两个账号有同名联系人，切换工作区或重连另一账号 | 即使旧查询迟到，也看不到前一账号的列表、消息和附件摘要。 |

开发顺序建议先用旧格式样本验证读取、去重及分页，再接主进程查询和左右栏，最后用已完成联测的邮箱验证增量插入和阅读位置保持。写信、保存附件和双向已读各自在对应故事完成后做联测。
