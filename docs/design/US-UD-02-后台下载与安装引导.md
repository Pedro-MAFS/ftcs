# US-UD-02 详细设计：后台下载与安装引导

> **用户故事**：作为 Windows 上的外贸业务员，我想发现新版本后安装包在后台下好，再决定马上重启安装还是稍后，以便不打断当前的活，也不在没点头时被换掉。
> **范围**：发现新版本后立即下载 Windows NSIS 安装包；横幅显示进度；下完后「立即安装/重启」或「稍后」；失败可重试，并给出「去官网下载」。
> **依赖**：US-UD-01；[27-需求-后台检测与下载更新.md](../27-需求-后台检测与下载更新.md) UD2～UD6、UD8。现网横幅在 `UpdateBanner.vue`，清单在 `{官网根}/updates/latest.json`。
> **不在本期**：electron-updater、差分包、便携版、静默参数安装、macOS、改官网下载页和发版制度。
> **文档位置**：`docs/design/`
> **状态**：**已确认待开发**

## 0. 相对现网

| 现网 | **本期（UD-02）** |
|------|-------------------|
| 有更新只打开官网下载页，应用自己不下安装包 | 发现更高版本后立即下载 NSIS 安装包 |
| 横幅主按钮是「前往下载页」 | 下完后主按钮是「立即安装/重启」和「稍后」 |
| 无下载进度 | 同一条顶部横幅显示进度，不弹窗、不挡主界面 |
| 无本地安装包 | 下到 `userData/updates/{version}/`，稍后仍可安装 |

官网下载页和安装包链接保持现状，本故事不改 `website/`。

## 1. 目标与非目标

### 1.1 目标

1. US-UD-01 判定有更新后，立刻开始下载，没有「是否下载」确认框。
2. 只下 NSIS 安装包，不下便携版。
3. 下载不阻塞探索、线索、开发信。进度在现有顶部横幅里。
4. 成功后横幅主操作只有「立即安装/重启」和「稍后」。
5. 「立即安装/重启」打开正常安装向导（不加静默参数），然后退出应用。
6. 「稍后」收起强提示，不删除已下好的包。横幅留一行，设置里也能再点安装。
7. 下载失败、中断或校验失败：短错误、可重试，并有「去官网下载」。
8. 同一版本不并行下两次。已下好且校验通过则直接进入完成提示。

### 1.2 非目标

| 不做 | 说明 |
|------|------|
| `/S` 或等价静默覆盖 | 用户必须先点「立即安装/重启」，然后看到现有 NSIS 向导 |
| 便携版 exe | 官网便携版入口保持隐藏现状，应用内不下载它 |
| 改 `site.ts`、下载页、发版 tag | 地址按下面的默认规则拼；清单若写了地址则用清单 |
| 强制最低版本 | `minVersion` 不改变按钮，也不触发安装 |

## 3. 实现要点

### 3.1 下载地址

默认（版本号来自清单 `version`，已 trim）：

- 主地址：`https://gitee.com/mfs1998_admin/ftcs/releases/download/V{version}/` + `encodeURIComponent(外贸获客-Setup-{version}.exe)`
- 备用：`https://github.com/Pedro-MAFS/ftcs/releases/download/{version}/foreign-trade-Setup-{version}.exe`

清单可选字段（没有就用默认，当前 `latest.json` 没有这些字段也必须能下）：

| 字段 | 含义 |
|------|------|
| `setupUrl` | 主地址，有则替换 Gitee 默认 |
| `setupUrlFallback` | 备用地址，有则替换 GitHub 默认 |
| `setupSha256` | 有则下载完成后做 SHA-256；没有则不校验哈希，只要 HTTP 成功且文件非空 |

先下主地址。一次地址的失败不限于网络错误和 HTTP 非 2xx。响应头含非 Latin-1 字符（例如 Gitee 跳转后 `Content-Disposition` 的 filename 是「外贸获客-Setup-….exe」）导致这次下载中断，也算这次地址失败。删掉不完整的 `.part`，再试备用地址，只换一次，不并行。两个都失败才算下载失败。

这种失败必须落在下载逻辑能接住的路径上，不能变成主进程未捕获异常，也不能弹出 Electron 错误对话框。两个地址都失败时，界面只走 §3.6 的失败横幅（「重试」和「去官网下载」）。备用地址能下则仍然 `ready`。

不要为躲开这个崩溃改成只下英文文件名，也不要改 Gitee 发布物的文件名。本地落盘文件名仍可以是中文。请求 URL 继续百分号编码。详设不指定用 `net.fetch` 还是别的 API，只约束结果。

### 3.2 落盘与单次下载

目录：`path.join(app.getPath('userData'), 'updates', version)`。

文件名：`外贸获客-Setup-{version}.exe`。先写入同名 `.part`，完成后改名。

规则：

- 该版本已有完整文件，且（没有 `setupSha256` 或哈希相符）：不再下载，直接完成提示。
- 该版本正在下载：新的检查只把进度交给界面，不另起一条。
- 清单版本比正在下或已下好的更高：停掉旧下载，删掉 `updates/` 下其他版本目录，再下新的。
- 用户手动连点检查：不增加并行下载。

### 3.3 进度

主进程下载时向渲染进程推状态，至少包括：`phase`（`downloading` / `ready` / `failed`）、`version`、`received`、`total`（未知则为 null）、`message`。

横幅在 `downloading` 时显示「正在下载 {version}」和百分比；没有总长就显示「正在下载」，不要假装百分比。

横幅仍放在 `WorkspaceLayout` 现有位置，不使用全屏遮罩。

### 3.4 完成与稍后

`ready` 时横幅标题用「已下载 {version}」。按钮：

- 「立即安装/重启」
- 「稍后」

不要在成功态把「前往下载页」放成主按钮。「查看发布日志」可以留，沿用现网 `openChangelogPage`。

「稍后」把界面收成一行，包留在磁盘。不要写 `snoozeUntil`，也不要 7 天后才允许再看到。下次启动如果这个文件还在且清单仍是这个版本，直接 `ready`，不要为了同一文件再下一次。

### 3.5 安装

点「立即安装/重启」：

1. 确认目标 exe 存在。
2. `spawn` 该 exe，不加 `/S`，`detached: true`，并 `unref`，让安装向导在应用退出后还在。
3. 然后 `app.quit()`。

这是现有 NSIS 向导（可选目录），不是静默覆盖。失败则横幅说明「无法启动安装程序」，不要先退出应用。

### 3.6 失败与官网

失败横幅用短句，例如「下载失败：HTTP 404」或「校验失败」。按钮：「重试」「去官网下载」。响应头含非 Latin-1 字符而两个地址都失败时，同样走这条失败横幅，不弹 Electron 错误对话框。

重试对该版本重新走 §3.1，先删掉不完整的 `.part`。

「去官网下载」= 现网 `openExternal(downloadPage)`。成功态不必突出这个按钮，失败态必须有。

校验：仅当清单有 `setupSha256`（64 位十六进制，大小写不敏感）。不符则删掉文件，`phase: failed`，文案「校验失败」。

### 3.7 通道

在 `ipc/types.ts` 增加，并在 `preload.ts`、`electron.d.ts` 露出：

| 通道 | 用途 |
|------|------|
| `update:state` | 渲染进程拉取当前下载状态 |
| `update:progress` | 主进程推送进度（`webContents.send`） |
| `update:retry` | 重试当前失败的版本 |
| `update:install` | §3.5 |
| `update:defer` | §3.4 稍后 |

不新增「忽略此版本」的界面调用。`update:dismiss` 保持不被新界面使用。

## 7. 风险

| 风险 | 缓解 |
|------|------|
| 现网清单没有安装包直链 | 用 §3.1 的默认地址，和现网 `site.ts` 的 Setup 链接同一规则 |
| 安装向导需要应用先退出才能覆盖文件 | 先 `spawn` 再 `quit`；向导本身不是静默的 |
| 用户没点安装就去官网重装 | 允许。官网路径保持可用 |
| 响应头里的中文文件名打崩主进程，备用不再试 | 算该地址失败，删掉不完整的 `.part` 再试备用；接在下载逻辑里，不弹 Electron 错误对话框 |
