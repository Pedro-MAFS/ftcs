# 18 - 需求：任务编排 · 一键跑通

> **文档类型**：本期需求 + 用户故事（**US-W**）  
> **状态**：**v0.5.3 已交付**（US-W-01～W-05 编码已落地）  
> **基线**：桌面端 **v0.5.2+**（R1/R2/R3 探索、评分去重、批量起草已各有独立按钮与 IPC）  
> **关联**：[17-需求-业务效率工具.md](17-需求-业务效率工具.md)（录入 US-I、探索 US-E）、[04-实施计划.md](04-实施计划.md)

---

## 1. 一句话目标

把探索页 / 线索页上分散的 **「开始 R1/R2/R3」「评分去重」「批量起草」** 收敛为 **「选方案 → 执行」**：  
单步方案等价于现在的「只跑一个动作」；多步方案等价于 **帮用户按顺序自动连点**，不另做特殊执行 UI。

---

## 2. 背景与动机

### 2.1 使用节奏

| 阶段 | 典型动作 | 频率 |
|------|----------|------|
| **初始化** | 录入 → 生成画像 → 扩展关键词 | 新产品各做一次 |
| **循环获客** | 探索 → 评分去重 → 起草开发信 | 按周 / 按需重复 |

用户在 **线索页** 看完结果后，常希望 **立刻再跑一轮探索→评分→邮件**，而不想逐步切页。  
**初期（v1）** 任务编排入口 **只在线索页**；探索页仍用现网 R1/R2/R3「开始探索」，待 US-W-07 再统一。

### 2.2 与现网控件的关系

| 现网 | v1 编排后 |
|------|-----------|
| 探索页 `ExploreStartControl`（R1/R2/R3） | **暂不改动**（US-W-07） |
| 线索页 `ExploreStartControl` + 评分 / 起草 | 改为 **方案下拉 +「执行」**；评分 / 起草单步按钮 **保留** |
| 每步 Preflight / Agent 时间线 | **保留**；执行器顺序触发，UI 不特殊化 |

## 3. 已确认产品规则

| # | 规则 |
|---|------|
| **R1** | 预置内置方案「**标准获客**」（`builtin-standard`，默认选中）与「**高级获客**」（`builtin-advanced`）；**不**另建「仅 R1/R2/R3」内置方案。 |
| **R2** | 用户可 **新建 / 编辑 / 删除** 自定义方案；持久化在工作区（见 US-W-01）。 |
| **R3** | 方案步骤 v1 仅从 **固定节点目录** 选取（见 §4），**不**开放任意 Skill 字符串。 |
| **R4** | **执行 UI 不特殊化**：顺序调用与现网各页主按钮 **相同的 IPC**；右侧 Agent 时间线、左侧流水线规则 **不变**（完成态仍看磁盘产物）。 |
| **R5** | 某步 Agent **失败或 Preflight 不通过** → **停止后续步骤**，文案说明停在哪一步；**不**新增流水线 `failed` 态（与现网一致）。 |
| **R6** | **v1 入口仅线索页**：`WorkflowPlanControl`（compact）+ 下拉内新建 / 编辑 / 删除；**探索页不改**（仍用现网 R1/R2/R3，见 US-W-07）。 |
| **R7** | **执行记忆**：记住上次选中方案；线索页进入时自动恢复（键 §5.1；探索页接入后与之共用）。 |
| **R8** | **定时触发**（支持计划 `scheduled-tasks`）、**后台静默跑完再通知** → **本需求不做**。完成通知见 [22-需求-任务完成Windows通知.md](22-需求-任务完成Windows通知.md)（US-N）；定时见 US-W-06。 |

## 4. 节点目录（v1）

每步对应现网已有能力；执行器内部映射到与单步按钮相同的 IPC / Skill。

| 节点 ID | 展示名 | 等价现网动作 | Skill / IPC |
|---------|--------|--------------|-------------|
| `expand-keywords` | 扩展关键词 | 画像页 · 新建探索任务（扩展） | `expand-keywords` · `keywords:expand` |
| `discover-r1` | R1 广撒网 | 探索页 · 开始 R1 | `discover-leads` · `exploration:start-r1` |
| `discover-r2` | R2 社媒发现 | 探索页 · 开始 R2 | `discover-leads-r2` · `exploration:start-r2` |
| `discover-r3` | R3 地图发现 | 探索页 · 开始 R3 | `discover-leads-r3` · `exploration:start-r3` |
| `score-and-dedupe` | 评分去重 | 线索页 · 评分去重 | `score-and-dedupe` · `leads:score-and-dedupe` |
| `enrich-lead-contacts` | 批量补全联系人 | 线索页 · 批量补全 | `enrich-lead-contacts` · `leads:enrich-contacts` |
| `draft-outreach-email` | 批量起草开发信 | 线索页 · 批量起草 | `draft-outreach-email` · `email:draft-generate` |

**本需求不做**：`extract-product-profile` 纳入方案（仍走录入 / 画像页「生成画像」）。  
**说明**：`expand-keywords` **已纳入**节点目录，供用户自建方案；内置「标准获客 / 高级获客」**均不含**扩展关键词（默认假设关键词已就绪）。「高级获客」含 R3、批量补全与批量起草。

## 5. 预置方案

| ID | 名称 | 步骤 | 说明 |
|----|------|------|------|
| `builtin-standard` | 标准获客 | R1 → R2 → 评分去重 → 批量起草 | **默认选中**；`builtin: true`，不可删 |
| `builtin-advanced` | 高级获客 | R1 → R2 → R3 → 评分去重 → 批量补全 → 批量起草 | 含地图发现与 Hunter 补全；需 Places / Hunter Key；`builtin: true`，不可删 |

**不提供**「仅 R1 / 仅 R2 / 仅 R3」内置方案。若只需跑单步，用户可在 US-W-04 中 **自建单步方案**（如只含「R1 广撒网」）；探索页 / 线索页保留的单步按钮仍可直接点。

### 5.1 上次选中方案（执行记忆）

| 项 | 规则 |
|----|------|
| **记什么** | 用户在下拉中 **最后一次选中** 的方案 `id`（含仅切换未点「执行」）。 |
| **存哪** | 渲染进程 `localStorage`，键 `ftcs.workflow.lastSelectedPlanId`（v1 仅线索页写入；US-W-07 后探索页共用）。 |
| **何时写** | 用户更改下拉选中项时 **立即写入**；新建 / 编辑方案保存后若当前正在编辑该方案，同步更新选中项。 |
| **何时读** | `WorkflowPlanControl` 挂载时；`listWorkflowPlans` 返回后。 |
| **默认值** | 无记录或记录无效 → **`builtin-standard`（标准获客）**。 |
| **失效** | 记忆的 id 已被删除或不存在于方案列表 → 回退 **`builtin-standard`**，并 **覆盖** 写入 storage。 |

示例：用户在线索页选中「标准获客」后关闭应用，下次进入线索页下拉仍显示「标准获客」，可直接点「执行」。

## 7. 用户故事详述

### US-W-01　方案模型、节点目录与预置持久化

**作为** 产品 / 开发，**我需要** 在工作区内统一存储「任务方案」与内置预置，**以便** UI 与执行器读写同一数据源。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | 无（映射现网 Skill 名称） |
| 状态 | **编码已落地** → [design/US-W-01-方案模型与预置.md](design/US-W-01-方案模型与预置.md) |

**验收要点**

- 方案 JSON Schema：`id`、`name`、`steps[]`（有序节点 ID）、`builtin`、`createdAt` / `updatedAt`（用户方案）。  
- 持久化路径：**`data/prefs/workflow-plans.json`**（工作区根；与 `explore-r2.json` 同层，见 W-01 详设 §1 Q1）。  
- 启动时合并 **§5 唯一预置** + 用户方案；`builtin` 不可被用户文件覆盖。  
- 提供主进程 IPC：`listWorkflowPlans`、`saveWorkflowPlan`、`deleteWorkflowPlan`（用户方案）。  
- 节点目录 **§4** 在代码中单源维护，供弹框与 Preflight 使用。

**本故事不做**：顺序执行；UI 控件。

---

### US-W-02　方案下拉与「执行」控件

**作为** 外贸业务员，**我想** 在线索页选一个任务方案并点「执行」，**以便** 不必逐步理解 R1/R2/R3 细节也能跑日常流程。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-W-01 |
| 状态 | **编码已落地** → [design/US-W-02-方案选择与执行控件.md](design/US-W-02-方案选择与执行控件.md) |

**验收要点**

- 用 `WorkflowPlanControl` 替换线索页现网 **轮次下拉 +「开始探索」**（探索页 **不在此故事**）。  
- 下拉展示方案 **名称**；默认选中按 **§5.1 执行记忆** 恢复，无效时 `builtin-standard`。  
- 主按钮文案：**执行**；忙碌时 **执行中…**；禁用时 `title` 给出原因（与现网 Preflight 文案一致）。  
- 用户 **仅切换下拉**（未点执行）也应写入记忆；重启应用后再进 **线索页** 选中不变。  
- 记住用户上次选中方案（§5.1）；`ftcs.workflow.lastSelectedPlanId`。  

**本故事不做**：弹框 CRUD（W-04）；顺序执行（W-03）。

---

### US-W-03　顺序执行器（等价自动连点）

**作为** 外贸业务员，**我想** 点一次「执行」后自动按方案顺序跑完 R1→R2→评分→邮件，**以便** 不必逐步盯屏点四个按钮。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-W-01、US-W-02；现网 `agent-runner` done 事件 |
| 状态 | **编码已落地** → [design/US-W-03-顺序执行器.md](design/US-W-03-顺序执行器.md) |

**验收要点**

- 执行器逐步调用与 **§4** 等价的 IPC；**等待** 当前步 `agent` `done`（`ok: true`）再进入下一步。  
- **Preflight**：在点「执行」前对 **整链** 所需能力一次性检查（R2 词、Places Key 等）。  
- 任一步 `done` 且 `ok: false` 或 Preflight 失败 → **停止**，横幅 / 时间线说明「方案「xxx」在步骤「R2 社媒发现」失败：…」。  
- **UI 不特殊化**：右侧仍为逐步累积的 Agent 时间线；不新增独立「编排进度条」组件。  
- 执行中「执行」禁用；支持 **中止**（沿用现网 `abortProfile`）。  
- 每步结束后 `refreshPipelineArtifacts`（与现网流水线磁盘判定一致）。  
- 预置 `builtin-standard` 手工验收：有词、有 raw 线索、有 scored、有 high 待起草时，四步串跑成功。

**本故事不做**：后台静默执行。完成推送通知见 [22-需求-任务完成Windows通知.md](22-需求-任务完成Windows通知.md)（US-N-03 承接编排整段一次通知）。

### US-W-04　编排弹框：新建 / 编辑 / 删除

**作为** 外贸业务员，**我想** 在下拉里新建或修改自己的任务方案，**以便** 按自己的获客习惯组合 R1/R2/评分/邮件。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-W-01 |
| 状态 | **编码已落地** → [design/US-W-04-方案编排弹框.md](design/US-W-04-方案编排弹框.md) |

**验收要点**

- 方案下拉底部（或旁）入口：**新建方案**、**编辑当前**、**删除当前**。  
- 内置方案：**编辑 / 删除 disabled**（或编辑打开只读）。  
- 弹框字段：方案名称；**有序步骤列表**（从 §4 节点目录添加、删除、上移 / 下移；v1 可不做拖拽）。  
- 校验：至少 1 步；名称非空；不重名（用户方案内）。  
- 保存后下拉立即刷新；删除后若删的是当前选中，回退到 `builtin-standard`。

**本故事不做**：跨产品复制方案；导入导出。

### US-W-05　线索页接入任务执行

**作为** 外贸业务员，**我想** 在线索页选方案并点「执行」，**以便** 在查看线索时一键跑完探索→评分→邮件，而不逐步切页点按钮。

| 项 | 内容 |
|----|------|
| 优先级 | Must |
| 依赖 | US-W-02、US-W-03 |
| 状态 | **编码已落地** → [design/US-W-05-页面接入与迁移.md](design/US-W-05-页面接入与迁移.md) |

**验收要点**

- **线索页**：`WorkflowPlanControl`（compact），替换现网 `ExploreStartControl`。  
- **探索页**：**不改**；仍用 R1/R2/R3 +「开始探索」（US-W-07）。  
- 空态文案：「暂无线索 · 选择方案并执行」；不再写「在本页或探索页开始探索」。  
- **保留**「评分去重」「批量起草」单步按钮；与「执行中」互斥 disabled。  
- 左侧流水线跳转规则 **不变**。

**本故事不做**：探索页接入（W-07）；录入页、邮件页挂控件。

## 9. 风险与开放问题

| # | 项 | 倾向 |
|---|-----|------|
| O1 | 四步串跑总时长很长，用户切走页面 | 与现网单步相同：Agent 占用中禁止并发；切页不影响磁盘完成态。回来提醒见 [22-需求-任务完成Windows通知.md](22-需求-任务完成Windows通知.md) |
