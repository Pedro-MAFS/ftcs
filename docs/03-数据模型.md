# 03 - 数据模型

本文档定义系统核心数据结构。Phase 1 使用 JSON 文件存储，Phase 2 可迁移至 PostgreSQL，Schema 保持一致。

## 1. 产品画像（Product Profile）

**路径**：`data/products/{product_id}/profile.json`

```json
{
  "id": "prod_20260709_001",
  "version": 1,
  "created_at": "2026-07-09T14:00:00Z",
  "updated_at": "2026-07-09T14:00:00Z",
  "status": "ready",
  "readiness": {
    "score": 85,
    "missing_fields": ["hs_code"],
    "warnings": ["未指定目标市场，将默认全球搜索"]
  },
  "company": {
    "name": "示例科技有限公司",
    "website": "https://example.com",
    "country": "CN",
    "description": "专业从事工业阀门制造",
    "certifications": ["ISO9001", "CE"]
  },
  "products": [
    {
      "name": "不锈钢球阀",
      "name_en": "Stainless Steel Ball Valve",
      "category": "工业阀门",
      "hs_code": "84818040",
      "materials": ["不锈钢304", "不锈钢316"],
      "specs": ["DN15-DN200", "PN16-PN40"],

      "price_range": "$5-$50",
      "use_cases": ["水处理", "石油化工", "暖通空调"],
      "differentiators": ["自有工厂", "15天快速交付", "OEM/ODM"]
    }
  ],
  "buyer_personas": [
    {
      "role": "procurement_manager",
      "company_types": ["distributor", "OEM", "engineering_company"],
      "regions": ["EU", "NA", "SEA"],
      "pain_points": ["供应商交期不稳定", "质量一致性差"]
    }
  ],
  "target_markets": {
    "regions": ["EU", "NA"],
    "excluded_regions": [],
    "languages": ["en", "de", "es"]
  },
  "competitors": [
    {
      "name": "Competitor A",
      "website": "https://competitor-a.com"
    }
  ],
  "source_inputs": [
    {
      "type": "website",
      "url": "https://example.com",
      "crawled_at": "2026-07-09T13:55:00Z"
    },
    {
      "type": "file",
      "path": "data/products/prod_20260709_001/inputs/catalog.pdf",
      "uploaded_at": "2026-07-09T13:50:00Z"
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 格式 `prod_{date}_{seq}` |
| `status` | 是 | `draft` / `ready` / `archived` |
| `readiness` | 是 | 画像就绪度，影响是否开始探索 |
| `company` | 是 | 卖方公司信息 |
| `products` | 是 | 至少一个产品 |
| `buyer_personas` | 推荐 | 目标买家画像 |
| `target_markets` | 推荐 | 目标市场，缺省则全球 |
| `competitors` | 可选 | 用于竞品客户反查 |

### 就绪度规则

`readiness.score` 计算：
- 有 `company.name` + `company.website`：+20
- 有 ≥1 个 `products[].name`：+20
- 有 `products[].use_cases`：+15
- 有 `buyer_personas`：+20
- 有 `target_markets.regions`：+15
- 有 `competitors`：+10

`score < 60` 时状态为 `draft`，系统应提示用户补全后再探索。

### 线索状态流转

```
new → reviewed → email_drafted → email_approved → contacted → replied → converted
                              ↘ rejected
```

| 状态 | 说明 |
|------|------|
| `new` | 新发现，待用户查看 |
| `reviewed` | 用户已确认有价值 |
| `email_drafted` | 已生成邮件草稿 |
| `email_approved` | 用户审核通过 |
| `contacted` | 已发送 |
| `replied` | 收到回复 |
| `rejected` | 用户标记无效 |

## 6. 配置模型

### 6.1 评分规则

**路径**：`config/scoring-rules.yaml`

```yaml
weights:
  product_match: 0.30
  purchase_intent: 0.25
  size_fit: 0.15
  geo_match: 0.15
  reachability: 0.10
  competition: 0.05

tiers:
  high: 80
  medium: 60
  low: 40
```

### 6.2 探索调度

**路径**：`config/exploration-schedule.yaml`

```yaml
product_id: prod_20260709_001
enabled: false  # Phase 2 启用
cron: "0 9 * * 1"  # 每周一 9:00
rounds: ["R1", "R4"]
daily_limits:
  search_calls: 50
  crawl_pages: 100
```

## 7. ID 生成规范

| 实体 | 格式 | 示例 |
|------|------|------|
| 产品 | `prod_{YYYYMMDD}_{seq}` | `prod_20260709_001` |
| 线索 | `lead_{YYYYMMDD}_{seq}` | `lead_20260709_0001` |
| 邮件 | `email_{YYYYMMDD}_{seq}` | `email_20260709_0001` |
| 探索运行 | `run_{YYYYMMDD}_{seq}` | `run_20260709_001` |
| 搜索词 | `q_{seq}` | `q_001` |

`seq` 为三位数字，当日递增。

---

## 8. 去重键规则

1. 主键：公司官网域名（规范化：去 www、小写）
2. 辅键：公司名模糊匹配（Levenshtein 距离 < 3 且同国家）
3. 无官网时：公司名 + 国家
