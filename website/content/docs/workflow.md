# 推荐使用流程

FTCS 外贸获客标准路径与桌面端侧栏一致，建议按顺序推进：**录入 → 画像 → 探索 → 评分 → 开发信**。补全联系人（Hunter）为可选扩展，穿插在线索与开发信之间。

## 1. 产品录入

在 **录入** 页按自己的习惯建目录（例如「客户公司 / 地板」），把官网和说明书放在同一夹里：

- **网站**：在当前文件夹保存官网书签，不再是全局单独一列  
- **文件**：上传或拖入 txt / md 等文本，Word / Excel / PPT（`.docx` / `.xlsx` / `.pptx`），**图片**（jpg / png 等），以及 **文字型 PDF**（自动抽文本后进画像；扫描件暂不支持）  
- **生成画像**：勾选文件、书签，或直接勾选整个产品文件夹（默认只含该层内容）后生成一份画像  

官网与文件可同时选，信息会合并进同一份画像。勾选含图片时，请使用 **支持读图的模型**（官方通道部分模型已支持）。老格式 `.doc` 与扫描型 PDF 暂不支持；Office 文件需可选安装 [OfficeCLI](/docs/install#officecli)（未安装时仍可用官网、文本与图片生成）。

也可在右侧智能体面板说明要生成画像，选择资料库里的文件和网站书签。

## 2. 产品画像

触发画像生成后，在 **画像** 页核对公司、产品、买家画像与目标市场。画像是后续关键词与获客探索的基础，缺字段时可人工补全，也可在智能体面板说明要修改的已有画像内容。

## 3. 关键词与获客探索

在画像就绪后扩展关键词（产品、场景、买家、地理等）。在 **设置 → 探索** 选择探索强度（低 / 中 / 高，默认中）：更高会多出关键词，每次搜索和地图发现也会多看结果，耗时和费用更高。改强度后请重新扩展，已有关键词不会自动重算。若要用社媒发现，请先确认已启用对应站点（默认 LinkedIn 公司页、Facebook 公共主页），再扩展关键词；改开关后同样需重新扩展。

然后在 **探索** 页（或 **线索** 页）选择方式并开始：

- **全网搜索**：按关键词在公开网页检索，打开候选公司官网后，判断是否写入线索。  
- **社媒发现**：只检索已启用站点的**公开搜索摘要**，从中抽出公司并核对官网后再写入线索。**不会打开领英 / 脸书登录页**，也不代替领英开发。  
- **地图发现**（可选）：用 Google Places 按城市与品类找本地商户，补全官网并核对后写入线索。官方通道在 **设置 → 探索** 申请官方 Places Key，受理后预计下一自然日内开通（需要能访问 Google 的网络，由本机直接访问 Google，使用费用计入官方额度）；自定义通道须自备 [Places API Key](/docs/places-api-key)，费用由 Google 按其价格收取。

保存线索时，若该公司域名已在本产品线索库中，会自动跳过并保留旧线索，不再重复写入。

开始后会跑完该方式已经生成的合格词。右侧时间线可展开查看智能体过程。任务需要你回复时，界面会显示题目和选项，按题目选择或填写后任务继续。启动任务前的必要选择长时间未回答时会结束等待，任务执行中的提问按题型处理。窗口不在前台时会弹出「任务在等你回复」通知。若页面出现人机验证或登录墙，任务会停下，请不要尝试绕过。

## 4. 线索库

探索产物进入 **线索** 页：

- 未评分线索可人工编辑；匹配理由会标出全网搜索、社媒发现或地图发现  
- 打开线索可查看目标公司画像（探索写入新线索时一并生成）和破冰话术，破冰可以改完保存。以前没有画像的旧线索不会自动补写  
- 导出 CSV 时会带上每条线索的全部联系方式与关键联系人  
- 执行 **评分去重** 后按 tier（A/B/C）筛选  
- 对已评分线索可点 **补全联系人**（可选）：按官网域名查找相关联系人。验邮开关为 **允许对关键人验证邮箱**，由智能体决定验谁、验几封。官方通道无需自备 Key，由官方代调；自定义通道未配置 [Hunter Key](/docs/hunter-api-key) 时按钮不可用。**不影响**探索与开发信主路径  
- 对 high 线索 **写邮件**；已有草稿可点 **邮件** 跳转  
- 本页可选 **任务方案**，把探索、评分、起草等步骤 **按顺序一键跑通**（也可保留单步按钮）  
- 预埋的 **标准获客**、**高级获客** 可点「查看方案…」看清步骤顺序，不能修改或删除；自己新建的方案仍可编辑  
- 可为方案设置 **每日或每周定时**（最多 5 条）。请在设置中开启开机自启，并把关闭窗口改为进入托盘；到点若已有任务在跑会跳过；应用未运行时错过的时刻不会在下次启动后补跑
- 本页也可直接开始下一轮探索  

## 5. 开发信草稿审核

在 **邮件** 页：

- 每条线索默认有一封 **公司向**草稿，并为有个人邮箱的联系人各起草一封（1+N）；顶部可切换收件人审阅，缺稿时可单人补起草  
- **行文风格**在 **设置 → 开发信行文风格** 用自然语言描述（默认「专业，真诚」），影响之后的起草与重写，不自动改已有稿  
- 可展开 **中文对照** 辅助审阅（外发仍用原文）；外文改稿后对照可能过期，可按需重新生成  
- **查看线索**：一键回到线索页并选中当前公司，便于对照联系人后再改稿  
- **通过并保存** / **驳回**：按当前收件人或整条线索操作；发出节奏由你掌握  

画像、探索、线索、邮件页面及左侧产品列表都可以手工刷新。刷新画像和邮件时，未保存的编辑会保留。

先把信写对、存好，再按你自己的方式发出。

<h2 id="website">独立站</h2>

在主区域的 **独立站** 页面创建工作区网站。一个工作区维护一个站点，不随当前产品切换。新站点使用 Vue、Vite 和静态预渲染模板；也可使用提供 `npm run dev`、`npm run build` 的已有纯前端 Node 项目，并设置静态产物目录。

可以通过右侧智能体修改网站。聊天输入区可选择电脑中的文件作为临时参考，也可以输入 `@` 选择资料库文件或产品画像；参考文件不会自动加入资料库。自由聊天中执行 Bash 命令时由你逐次授权，自动业务任务中的 Bash 请求会被拒绝。

在独立站页面安装依赖、启动并打开本地预览，检查构建。连接自己的 GitHub 和 Cloudflare 后，首次发布选择或创建 GitHub 仓库及分支，检查通过后推送；再创建或选择 Cloudflare Pages 项目并关联，查看构建和部署状态。后续发布沿用已选目标。也可以在聊天中要求预览、停止预览或发布。GitHub 推送成功不代表 Cloudflare 已部署成功，请查看页面状态。

在 **工作区独立站 → 发布与域名配置** 添加自有域名。子域名按提示在 DNS 服务商设置 CNAME，再检查 Cloudflare 状态；根域名需要先按页面提示将 DNS 接入当前 Cloudflare 账号。移除域名只处理 Pages 关联，FTCS 不主动修改 DNS。默认模板如需按正式地址生成 sitemap，请在 Cloudflare 构建环境设置 `SITE_URL` 并重新部署。

## 建议节奏

先用少量搜索词跑通一次「全网搜索 → 评分 → 1～2 封开发信草稿」，确认画像与话术质量，再扩大规模或补做社媒发现。需要具名收件人时，再为高匹配线索补全联系人。官方通道无需自备 Key；自定义通道再配置 Hunter。

## 通道与搜索提示

- 使用 **官方通道** 时，开通后即可做全网搜索和社媒发现，无需再配置搜索 Key。地图发现在设置里申请官方 Places Key，受理后预计下一自然日内开通，由本机直接访问 Google。  
- 使用 **自定义通道** 时，请先在设置中填好模型与 Tavily Key，再启动探索。地图发现须自备 [Google Places API Key](/docs/places-api-key)。  
- 地图发现需要能访问 Google 的网络。  
- **补全联系人** 为可选扩展。官方通道无需自备 Key，由官方代调，费用计入官方通道；自定义通道仍自备 [Hunter API Key](/docs/hunter-api-key)、直连，费用在你自己的 Hunter 账号。主路径不依赖补全。
