# 独立站开发约定

这是建站的说明型技能。结合用户需求、现有代码和工具结果灵活工作；不需要固定步骤或为每次修改创建业务任务。每轮继续进行独立站修改时先加载本技能。只有用户所说的内容足以动手时才开始，缺少必须由用户决定的内容就提问。

## 项目

- 当前工作区的 `website/` 是唯一站点源码根目录，不与当前选中的产品绑定。先检查现有项目，不要因其不是默认模板而重建。
- 保留项目的 `npm run dev` 和 `npm run build` 契约，遵守 FTCS 中配置的静态产物目录。允许单页、多页和产品详情页；不要强制使用特定框架。
- 按用户要求和现有代码惯例修改，尽量保留已有内容、配置、路由和关联。注意响应式、可访问性及标题、描述等 SEO；不保证搜索引擎收录。
- 不能直接从工作区其他目录引用资源或作为构建依赖；需要公开的资源须经用户允许并放到 `website/` 内。没有可用的受控复制工具时说明限制，不自行越权复制或通过命令绕过。不要编造产品参数、证书、联系方式或客户评价。

## 工具与权限

- 使用会话中实际提供的读、搜索及文件编辑工具；仅在当前会话经过桌面端许可时编辑 `website/` 内文件。其他路径继续遵守工作区规则。权限被拒绝时不要绕过。
- 自由聊天中的 Bash/shell 请求需经用户逐次确认；用绝对路径明确指定 `website/` 或其子目录作为工作目录，具体命令和目录必须能由桌面端核验并展示。无法确认时不要换其他方式绕过。自动任务中的 Bash/shell 会被拒绝，不要等待授权。
- 用户要求预览时调用 `lead-store_site_preview` 启动 FTCS 管理的服务；用 `lead-store_site_status` 查询实际状态，已确认运行后可调用 `lead-store_site_open_preview` 打开内置浏览器。地址待确认、缺少依赖等情况请说明并引导用户到页面处理。
- 用户要求构建时调用 `lead-store_site_build`，用 `lead-store_site_status` 查询结果；启动不代表成功。已在运行时不要重复启动。依赖安装仍由页面处理。
- 用户要求发布时调用 `lead-store_site_publish_prepare`，使用已确认的仓库和分支准备快照与构建检查；告知用户到独立站页面核对源码、目标和构建结果，并由用户点击确认。首次发布、未连接账号或目标不可用时，引导用户在页面完成配置。工具不会推送或触发 Cloudflare；不要把准备完成当成发布成功。
- 不主动推送代码或发布网站；不要输出凭据。不把独立站操作当成画像等业务任务，不调用其 task_begin/task_done。

## 交付

按实际结果概述修改内容与需要用户补充的信息。没有执行构建、预览或发布时明确说明；不要把代码修改当作构建或线上部署成功。
