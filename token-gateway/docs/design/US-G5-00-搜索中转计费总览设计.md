## 1. 已拍板选型

| 项 | 决定 |
|----|------|
| **路径（草图）** | `POST /v1/search`（详设可微调，保持 `/v1` + sk） |
| **鉴权** | `Authorization: Bearer sk-…`；身份与 Chat 相同 |
| **上游** | `https://api.tavily.com/search`；Key = 服务端 `TAVILY_API_KEY` |
| **计价** | 按次；价目行 `model=tavily.search` |
| **计量行** | `token_request_logs.model = tavily.search` |
| **隐私** | 只落摘要；禁止 query / 结果正文 / 上游 Key |
| **结算** | 复用 G0-10 异步扣费 |
| **实现顺序** | 先网关可计费代理，再宿主改桌面 |

---

## 2. 逻辑架构

```text
Client (官方通道 sk)
    → POST /v1/search + Bearer sk-
    → SkAuth + BalanceGuard
    → TavilyUpstreamClient (服务端 Key)
    → 写 token_request_logs（摘要 + pending）
    → 异步结算 → charge + 扣 balance_li
```

自定义通道桌面：**不**走本路径（BYOK 直连 Tavily），见宿主 docs/15。

## 3. API 草图（冻结前可调）

### 3.1 请求

```http
POST /v1/search
Authorization: Bearer sk-…
Content-Type: application/json

{
  "query": "…",
  "search_depth": "basic",
  "max_results": 5
}
```

| 字段 | 规则（草） |
|------|------------|
| `query` | 必填；长度上限详定；**不落库全文** |
| `search_depth` | 白名单，默认 `basic` |
| `max_results` | 1～10（对齐现 MCP） |

### 3.2 响应

返回对客户端有用的搜索结果（title/url/snippet 等，对齐现 `search_web` 映射）；**不**回传上游 Key、原始计费内部字段。

### 3.3 错误（与 Chat 对齐风格）

| HTTP | 场景 |
|------|------|
| 401 | 无效 sk |
| 403 | 账户/Key 禁用 |
| 402 | 余额不足 |
| 400 | 参数非法 |
| 502 / 上游映射 | Tavily 失败；不扣费（无有效计量） |

## 4. 计量与价目（草）

| 项 | 约定 |
|----|------|
| model | 固定 `tavily.search` |
| 按次编码 | **已冻结方案 A**（见 [US-G5-03](./US-G5-03-搜索按次计量与结算设计.md)）：`prompt_tokens=1` + 价目 input = 厘/次×1e6；**不做**扩列 B |
| 摘要字段 | `error_summary` 复用为审计摘要（如 `depth=basic;results=5`）；另有 status、latency |
| COGS | 可记上游成本厘/次（运维价，同样 ×1e6 写入 upstream_input）；**不对用户面板暴露** |

种子价：开发占位 INSERT；上线前按 Tavily 成本 + 毛利复核（对齐 FR-PRICE 精神）。

---

## 4.1 费率如何维护（与 Chat 同轨）

| 项 | 决定（默认，待评审确认） |
|----|--------------------------|
| 载体 | 复用 `token_price_rules`；`model = tavily.search` |
| 调价方式 | **仅 INSERT** 新行 + `effective_from`（同 G0-09 / US-G0-15）；**禁止** UPDATE 覆盖历史价 |
| 运维入口 | **不做**管理端调价 UI；`ops/insert_price_rule_*.sql` 示例 + 运维手册 |
| 生效语义 | 与模型价相同：已 `charged` 的请求**不回算**；新请求按 `findEffective(asOf)` |
| 与白名单关系 | `tavily.search` **不进** Chat `ModelWhitelist` / `GET /v1/models`；搜索是否可调由 `/v1/search` 开关 + 有效价目决定 |

## 4.2 用户面板展示（必须纳入 G5）

> 仅靠消费列表出现 `tavily.search` **不够**：用户充值前需要知道「搜一次多少钱」。现 G4-05 价格区只扫 Chat 白名单 ∩ Token 两档价，**不会**自动带出按次行。

| 项 | 决定（默认，待评审确认） |
|----|--------------------------|
| 入口 | 仍在面板 **「价格」** Tab（**不**新开搜索专区 Tab） |
| API | 扩展 `GET /v1/billing/portal/prices`：在模型列表之外追加搜索价目项（有有效价才展示） |
| 对外字段 | 建议增加 `billing_unit`：`per_mtok` \| `per_call`；按次项只展示**一次单价**（元/次），**不**伪造输入/输出两列 |
| 页内文案 | 模型区：「元 / 百万 Token」；搜索行：「元 / 次」；脚注不变「价格变更不影响已完成请求」 |
| 消费区 | `tavily.search` 自然出现在用量列表即可（O3）；无需专区 |
| 敏感 | 仍不回传上游 COGS / 毛利 |

故事：**US-G5-04**（面板价格扩展）→ [US-G5-04-面板搜索价格展示设计.md](./US-G5-04-面板搜索价格展示设计.md)（编码已落地）。
