# US-G5-04 面板搜索价格展示设计

> **用户故事**：[../02-用户故事.md](../02-用户故事.md) · US-G5-04  
> **状态**：编码已落地（单测覆盖 per_call 解码 / 零价追加 / 缺价跳过；联调需有效 ticket + `tavily.search` 种子价）  
> **范围**：扩展用户面板「价格」Tab / `GET /v1/billing/portal/prices`：在模型价目之外展示伪 model `tavily.search` 的**按次**用户单价（**元/次**）；**不**暴露上游 COGS  
> **需求映射**：[../01-需求.md](../01-需求.md) FR-PRICE-08；FR-SEARCH-08；[US-G5-00](./US-G5-00-搜索中转计费总览设计.md) §4.2；[US-G5-03](./US-G5-03-搜索按次计量与结算设计.md) §3.4；[US-G4-05](./US-G4-05-模型价格说明设计.md)  
> **依赖**：US-G4-05（prices API + 价格 Tab）；US-G5-03（方案 A 价目编码 + 种子行）  
> **不做**：搜索用量专区；改 `GET /v1/models`；管理端调价；回传厘/COGS；历史价 `asOf`  
> **文档位置**：`token-gateway/docs/design/`

## 1. 已确认选型

| 项 | 决定 |
|----|------|
| **Q1 路径** | **仍用** `GET /v1/billing/portal/prices`（不新开 URL） |
| **Q2 鉴权** | 不变：`RechargeTicketAuthFilter` |
| **Q3 列表构成** | ① 原模型列表（白名单 ∩ 有效价）→ ② 若 `findEffective("tavily.search") != null` 则**追加**一项 |
| **Q4 判别字段** | 每项增加 **`billing_unit`**：`per_mtok` \| `per_call` |
| **Q5 按次对外金额** | **`price_yuan_per_call`** = `liToYuan(input_price_li_per_mTok / 1_000_000)`；整数除法用 `BigDecimal`，先 `/1e6` 得厘/次再 `/1000` 得元 |
| **Q6 按次项字段** | 含：`model`、`billing_unit=per_call`、`price_yuan_per_call`、`effective_from`；**省略** `input_price_yuan_per_mtok` / `output_price_yuan_per_mtok`（`NON_NULL`） |
| **Q7 模型项字段** | 在 G4-05 基础上增加 `billing_unit=per_mtok`；原两档字段保留 |
| **Q8 零价** | `price_yuan_per_call=0` **仍展示**（与「缺价跳过」区分：有价目行即展示） |
| **Q9 缺价** | 无 `tavily.search` 有效行 → **不追加**；接口仍 200 |
| **Q10 排序** | 先全部模型项（白名单序），**最后**搜索项（若有） |
| **Q11 敏感** | 永不回传 `upstream_*`、厘字段、rule `id` |
| **Q12 UI** | 同「价格」Tab；按 `billing_unit` 分支渲染；旁注同时说明两种单位 |
| **Q13 models API** | **不**把 `tavily.search` 写入 `GET /v1/models` |
| **Q14 展示名** | 本期 API/`model` 字段仍为 `tavily.search`；页内可加轻量说明「网页搜索（按次）」，**不**另开 `display_name` 字段（可后置） |

## 2. 目标与非目标

### 2.1 目标

1. 用户打开面板「价格」能看到搜索一次多少钱（含 0 元）。  
2. 不与模型「元/百万 Token」混淆。  
3. 不泄露上游成本。  
4. 与 G5-03 方案 A 编码一致，避免运维/面板双重语义。

### 2.2 非目标

| 不做 | 说明 |
|------|------|
| 搜索消费专区 Tab | 用量列表自然出现即可 |
| 拆独立「搜索价格」HTTP | 扩展现 prices |
| 试算器 / 预估次数 | 非本故事 |
| 改价写接口 | ops INSERT |
| 向用户解释方案 A 的 ×1e6 存储技巧 | 面板只说「元/次」 |

## 3. 解码公式（方案 A → 元/次）

```text
li_per_call           = input_price_li_per_mTok / 1_000_000
price_yuan_per_call   = li_per_call / 1000
                      = input_price_li_per_mTok / 1_000_000_000
```

实现建议（与现网厘→元一致）：

```java
BigDecimal liPerCall = BigDecimal.valueOf(inputLiPerMTok)
    .divide(BigDecimal.valueOf(1_000_000L), 0, RoundingMode.HALF_UP); // 或保留小数再除，种子为整厘
BigDecimal yuan = liToYuan(liPerCall.longValueExact()); // /1000 → 最多 3 位小数
```

种子例：`input=0` → `0.000` 元/次；若日后 `input=100_000_000` → `0.100` 元/次。

**禁止**：对 `tavily.search` 调用现有 `toPriceItem` 把 `input/1e3` 当成「元/百万 Token」（会把 0 显示成 0，但一旦调价会错得离谱，例如 `100_000_000/1000=100000`「元/MTok」）。

### 4.3 字段表

|------|------------|------------|
| `model` | 必有 | 必有（`tavily.search`） |
| `billing_unit` | `per_mtok` | `per_call` |

兼容：旧前端若忽略 `billing_unit`、仍读 input/output，搜索项两字段缺失时需防御；**本故事同步改 `portal.html`**，不依赖旧渲染。

## 5. 应用层改动

### 5.1 `BillingPortalApplication.listPrices`

```text
items = []
for model in ModelWhitelist.listSorted():
  rule = findEffective(model, now)
  if rule != null:
    items.add(toMtokPriceItem(rule))   // billing_unit=per_mtok

searchRule = findEffective(SearchBilling.MODEL, now)
if searchRule != null:
  items.add(toPerCallPriceItem(searchRule))

return { as_of, items }
```

| 方法 | 职责 |
|------|------|
| `toMtokPriceItem` | 现 `toPriceItem` + `billing_unit=per_mtok` |
| `toPerCallPriceItem` | 解码 §3；`billing_unit=per_call`；不设 mtok 字段 |

常量：`SearchBilling.MODEL`（或本模块常量，避免 portal → metering 环依赖时在 portal 侧复制字符串 `"tavily.search"` —— **允许** portal 依赖 `SearchBilling`，或抽 `SearchModels.TAVILY_SEARCH` 到无环包；编码时选最简）。

### 5.2 DTO

`BillingPortalPriceItem` 增加：

- `billingUnit` → JSON `billing_unit`
- `priceYuanPerCall` → JSON `price_yuan_per_call`

保持类级 `@JsonInclude(NON_NULL)`（或字段级），使按次项不输出空 mtok 键。

### 5.3 单测

| ID | 用例 | 期望 |
|----|------|------|
| T1 | 白名单两模型有价 + tavily 有价 | items 末项 `tavily.search`，`per_call`，`price_yuan_per_call=0`（种子） |
| T2 | tavily 无有效价 | 仅模型项，无 search |
| T3 | 解码：`input=100_000_000` | `price_yuan_per_call=0.100` |
| T4 | 模型项带 `billing_unit=per_mtok` | 回归 G4-05 数值不变 |
| T5 | 响应无 `upstream_*` | 断言 |

复用/扩展 `BillingPortalApplicationTest.listPrices*`。

## 6. 面板 UI（`portal.html`）

### 6.1 文案

| 位置 | 文案 |
|------|------|
| 旁注 `#prices-unit-hint` | `模型单价：元 / 百万 Token；搜索单价：元 / 次` |
| 脚注 | 不变：`价格变更不影响已完成请求。` |
| 空态 | `暂无已定价项目`（可含「模型或搜索」语义，避免只说模型） |

### 6.2 `renderPricesList` 分支

```text
if item.billing_unit === "per_call":
  展示价 = "每次 " + formatChargeYuan(item.price_yuan_per_call)
  可选副标题/meta：网页搜索（按次）
else:
  展示价 = "输入 … · 输出 …"（现逻辑）
```

可选：在列表中于首个 `per_call` 前插入轻量分隔文案「搜索」（非独立 Tab）。**默认做分隔**（落实 G5-00 O5）。

### 6.3 无障碍

- `price_yuan_per_call` 缺失且 `per_call` → 显示 `—`，不抛 JS 错。  
- 旧缓存页：用户刷新即可。
