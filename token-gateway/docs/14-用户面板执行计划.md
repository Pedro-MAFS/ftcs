# Token 网关 · 用户面板执行计划（Phase G4）

> **目标**：网关托管「用户面板」Web 页；用户凭短时 `rt_` ticket 进入，查看账户、Token 消费、充值入账、模型价格，并管理本账户 API Key（`sk-`）；退费仅引导联系客服（**不做**自助退款 API）。  
> **原则**：复用 G3 充值 ticket / Cookie；**账本相关只读**，API Key 管理为例外写操作；不暴露上游 COGS/毛利；非运维管理端。  
> **现状锚点**：G0 账本/计量/价目/rotate 已落地；G3 微信充值与 `/billing/recharge` 已落地。  
> **用户故事**：[`02-用户故事.md`](./02-用户故事.md) Phase G4。  
> **总览设计**：[design/US-G4-00-用户面板总览设计.md](./design/US-G4-00-用户面板总览设计.md)

按阶段顺序做；**未完成上一阶段「出门条件」不要跳到编码联调。**

---

## 已拍板产品决策（2026-08-06）

| 项 | 决定 |
|----|------|
| 阶段 | **Phase G4**（G3 支付闭环之后） |
| 入口凭证 | **复用** `POST /v1/billing/recharge/ticket` → `rt_` + Cookie `tg_recharge_ticket`（与充值页同一套） |
| 页路径 | `GET /billing/portal`（不在 `/v1` 下） |
| 退费 | **不自助**；面板按钮弹出联系方式（电话 / 邮箱 / 公众号）；人工约 **3 个工作日**（对齐 G3-05） |
| 价目 | 面板展示**用户侧**输入/输出单价；**不**展示上游成本 |
| 桌面 | 仅换票 + `openExternal` 跳转（US-G4-07）；不内嵌面板 UI |
| API Key | 面板内「API Token 管理」：列表元信息 + 按 name 签发/重置（对齐 US-G0-06）；明文 **仅展示一次**；鉴权用 `rt_`，不要求页内 UC JWT |

## 阶段 C — 网关实现（建议顺序）

1. US-G4-01：`/billing/portal` + 扩 `RechargeTicketAuthFilter` → `/v1/billing/portal/**`
2. US-G4-02～05：只读 API + 页内区块
3. US-G4-08：API Token 管理区（列表 + rotate；复用 G0-06 领域逻辑）
4. US-G4-06：退费 Modal（无写库）
5. 页内「去充值」→ `/billing/recharge`（同 Cookie）
6. 备案/联系页脚与充值页一致

**出门条件**：有效 ticket 可浏览四类数据与 Key 列表；可重置并见一次明文；无效 ticket 见 NeedClient；退费不改余额。
