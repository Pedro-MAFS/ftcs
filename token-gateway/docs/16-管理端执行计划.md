# Token 网关 · 运维管理端执行计划（Phase G6）

> **目标**：内网部署运维管理端（独立进程 + Vue3 前端），替代日常改库；提供**大屏看板**（用户增长 / 充值 / 消费 / 活跃）与**运营面板**（用户、API Key、消费、充值、**价目**）。  
> **原则**：与 `token-gateway-server` **共库**（`token_*`，经 `token-gateway-db`）；**进程分离**（不挂消费方 `/v1/chat`、`/v1/search`）；**非** G4 用户面板；余额变更**必须**同事务写 ledger；调价**只 INSERT** 新 `effective_from`，禁止改历史价行。  
> **现状锚点**：G0 账本/Key/结算、G3 微信充值、G4 用户面板、G5 搜索计费已落地；运维仍依赖 `ops/*.sql` 与 US-G0-15。  
> **用户故事**：[`02-用户故事.md`](./02-用户故事.md) Phase G6（阶段 A 补全）。  
> **骨架约定**：[design/US-G0-01-工程骨架设计.md](./design/US-G0-01-工程骨架设计.md) §2.3。

按阶段顺序做；**未完成上一阶段「出门条件」不要跳到编码联调。**  
**建议实现顺序**：**运营面板写路径优先**（降改库风险），大屏看板可紧随或短并行。

## 指标与领域口径（看板 / 列表共用）

金额一律库内 **厘（li）**；API/UI 可同时给 `*_li` 与展示用元（÷1000）。时间默认 **UTC** 存储、展示可转本地。

| 维度 | MVP 指标 | 口径 |
|------|----------|------|
| 用户增长 | 今日 / 近 7 / 近 30 新增；累计用户数；趋势（按日） | `token_users.created_at`；可选副指标「曾 topup 用户数」 |
| 充值统计 | 今日 / 近 7 / 近 30 充值额与笔数；趋势 | `token_ledger_entries.type = 'topup'`；**主图不含** `adjust`（adjust 可另卡或下钻） |
| 消费统计 | 今日 / 近 7 / 近 30 消费额与笔数；趋势；可选按 `model` 占比 | `type = 'charge'`；model 拆分可 join / 经 `request_id` 关联 `token_request_logs` |
| 活跃统计 | DAU / WAU；近 7 日 DAU 趋势 | 当日（或窗内）在 `token_request_logs` 出现过的去重 `user_id`；**不用**「余额>0」当活跃 |

**禁止口径混淆**：充值额 ≠ 微信商户到账（对账仍走 G3 运维）；消费额以 ledger `charge` 为准，不以「pending 未结算」当已消费。

## 信息架构（前端）

```
tokengateway-admin-ui
├── /dashboard          # 大屏看板（四类统计 + 趋势）
└── /ops
    ├── /users          # 用户管理
    ├── /users/:id      # 用户详情（余额、状态、最近活跃）
    ├── /users/:id/keys # 该用户 API Key
    ├── /usage          # 消费查询（可从用户详情下钻）
    ├── /topups         # 充值记录 + 人工调账入口
    └── /prices         # 价目：当前生效 + 历史版本 + 新增版本
```

本期无登录页、无路由守卫（内网信任）；写操作表单必填 **operator**（文本）+ **note**（价目新增建议同样记录操作者备注，可落 `note` 扩展或仅写应用日志——详设拍板）。

### API 草图（路径前缀建议 `/admin/v1`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/v1/health` | 探活（内网可匿名） |
| GET | `/admin/v1/dashboard/summary` | 四类 KPI 卡片（今日/7/30/累计按约定） |
| GET | `/admin/v1/dashboard/series` | `metric=user_growth\|topup\|charge\|dau` + 日序列 |
| GET | `/admin/v1/users` | 分页；筛选 status / user_code |
| GET | `/admin/v1/users/{id}` | 详情含 `balance_li` |
| PATCH | `/admin/v1/users/{id}/status` | `active` / `disabled` |
| GET | `/admin/v1/users/{id}/keys` | name / prefix / status / 时间；无 hash、无全文 sk |
| PATCH | `/admin/v1/users/{id}/keys/{name}/status` | Key 启停 |
| POST | `/admin/v1/users/{id}/keys/{name}/rotate` | 可选；响应明文仅一次 |
| GET | `/admin/v1/users/{id}/ledger` | 筛选 type；分页 |
| GET | `/admin/v1/users/{id}/requests` | request_logs 分页 |
| GET | `/admin/v1/ledger` | 全局流水（运营「消费/充值」总览入口） |
| POST | `/admin/v1/users/{id}/adjustments` | body：`type=topup\|adjust`，`amount_li`，`operator`，`note` |
| GET | `/admin/v1/prices` | 按 model 列当前生效价 + 可选历史；含用户价与上游 COGS 列（内网可看） |
| GET | `/admin/v1/prices/{model}` | 某 model 价目版本时间线 |
| POST | `/admin/v1/prices` | **INSERT** 新行：`model`、五档单价、`effective_from`、operator/note |

写操作统一：校验金额符号约定（充正扣负与 G0 一致）、拒绝直接 `UPDATE balance` 不写流水的旁路；价目 **拒绝** `UPDATE`/`DELETE` `token_price_rules` 历史行。

**价目防呆（Must）**：

| model 类型 | UI/API 输入建议 | 落库 |
|------------|-----------------|------|
| Chat（如 deepseek-*） | 厘 / 百万 Token（或元/MTok 由服务换算） | `*_li_per_mTok` 五列 |
| `tavily.search` | **元/次或厘/次** 显式标签 | 按 G5 方案 A：`li/次 × 1e6` 写入 input 列；勿把 Chat 量级直接填入 |

**出门条件**：内网可调通用户启停、人工充值（余额与 ledger 一致）、Key 禁用、消费/充值可查、**新价目 INSERT 后结算按新 `effective_from` 取价**；看板 summary/series 数字与手写 SQL 抽样一致。

## 故事草案（写入 02 前可先按此拆）

### US-G6-01　Admin 工程可启动

**作为** 运维开发，**我想** 独立启动 `token-gateway-admin` 并连同一套 `token_*`，**以便** 管理 API 与消费方 RS 进程分离。

### US-G6-02 / US-G6-03　大屏统计

**作为** 运营，**我想** 在大屏看到用户增长、充值、消费、活跃的汇总与趋势，**以便** 不用写 SQL 也能盯盘。

### US-G6-04　用户管理

**作为** 运营，**我想** 查询用户并启用/禁用账户，**以便** 处理滥用或停用。

### US-G6-05　用户 API Key 管理

**作为** 运营，**我想** 查看并启用/禁用（可选轮换）某用户的 Key，**以便** 替代 `ops/disable_key_by_name.sql`。

### US-G6-06　用户消费管理

**作为** 运营，**我想** 按用户/时间查看消费流水与请求日志，**以便** 客服排障与对账。

### US-G6-07　用户充值管理

**作为** 运营，**我想** 查看充值记录并做人工 topup/adjust，**以便** 替代 `ops/topup_example.sql` 并留下 operator/note。

### US-G6-10　价目管理

**作为** 运营，**我想** 查看并新增 Chat / 搜索价目版本，**以便** 替代 `ops/insert_price_rule_*.sql`，且不破坏历史取价。

### US-G6-08 / US-G6-09　前端大屏与运营面板

**作为** 运营，**我想** 用 Web 完成上述只读与写操作（含价目），**以便** 日常不必登库。
